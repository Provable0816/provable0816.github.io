# 贡献指南

感谢你愿意补充这份清单。为了让它长期可用，PR 需要满足下面几条硬性要求。

## 收录标准

一个仓库要被收录，必须同时满足：

1. **确实从零实现**：核心算法/系统由作者手写，而不是对 `torch.nn`、`diffusers`、`langchain` 的一层薄封装。判断是否合格的经验法则：**把框架依赖去掉，这个仓库还剩多少自己的代码？**
2. **可理解**：有 README、注释，或配套博客/视频/Notebook。只有一份能跑但没人看得懂的代码，不算教学项目。
3. **真实存在**：`owner/repo` 能正常打开，README 能确认它在实现什么。**不接受任何无法核验的条目。**

优先收录这些形态：

- 一个概念对应一个几百行的小仓库（micro-* 式）
- 配套书籍/课程、有分章结构
- 能给出正确性验证的（单元测试、CPU 参考实现、benchmark）
- 2025 年之后新建或仍活跃维护的

原则上不收：

- 纯调库教程、只有 PPT/资料索引没有代码的
- 只有提示词模板 + API 调用的「Agent 项目」（可收录到 Agent 分区，但会注明是最小演示）
- 5 年以上无更新且无历史价值的（有历史价值的会标 ⚠️）

## 不写 star 数

**这是硬性规则。** star 会随时间变化，且大量中长尾仓库的 star 无法稳定核验。请改用标签：

| 标签 | 含义 |
| :--- | :--- |
| 🔥 | 社区公认高人气（万星级量级） |
| 🧩 | 极简实现，核心代码几百行内 |
| 🧪 | 可训练，单张消费级 GPU 能跑完 |
| 📖 | 书籍配套 |
| 🎓 | 系统课程，有分章/分课结构 |
| 📓 | 以 Notebook 讲解 |
| ⚙️ | 偏系统：推理引擎、算子、编译器、CUDA |
| 🆕 | 2025 年之后新建或活跃更新 |
| ⚠️ | 经典但偏旧，依赖需自行迁移 |

## PR 格式

在对应分区按现有风格加一行：

```markdown
- [owner/repo](https://github.com/owner/repo) — 一句话说清「它从零实现了什么」以及「为什么值得看」。 🔥🧩
```

要求：

- **一句话价值**，不要复制项目简介原文，不要写「这是一个很棒的项目」这类空话。
- **放到正确的层级**：清单分 4 个 Part、26 个章节，放错层级比漏收更糟 ——
  - **NLP** 讲表示 / 序列 / 经典任务；**LLM** 讲架构 / 训练 / 推理 / 微调 / 对齐。
  - **Agent** 分区要把「最小 ReAct 玩具」（§6.1）和「可评测的多智能体系统」（§6.5）分开。
  - 「模型怎么算」进 Part I；「怎么跑得快、放得下、训得动」进 Part II（并行 / 量化 / 编译器 / 算子 / 硬件）。
  - 一个仓库若横跨多个方向，放在它**主要贡献**那一章，另一章写「（见 §x）」引用，不要重复列条目。
- **一次 PR 建议不超过 5 个条目**，便于逐条核验。

### 关于「延伸：工业级对照实现」

各章末尾的这一小节**不是从零实现**，而是用来对照「自己写的和工业级差在哪」的参考。收录标准放宽为：代码可读性高、能反推算法设计。请在提 PR 时明确说明它应进主清单还是延伸小节——把生产级框架混进主清单是最常见的退稿原因。

各方向的最低质量线：

- **量化**：必须同时回答校准、敏感层识别、算子 kernel 与端到端精度，只宣称「4 比特快 N 倍」的不收。
- **算子/GPU**：必须有 CPU 参考实现、误差阈值与 benchmark（正确性 + 基准 + 对比三件套）。
- **编译器**：要能看清 IR 分层与 lowering 路径，只有 API 的不收。
- **数值/科学计算**：必须有误差界、与 NumPy/SciPy 对照和边界测试。
- **Agent**：仅有提示词模板 + API 调用的，只能进 §6.1 并注明「最小演示」。

## PR 描述里请附上

```text
- 仓库链接：
- 是否已确认 owner/repo 可正常打开：是 / 否
- 它从零实现了什么（一句话）：
- 建议标签：
- 放在哪个分区：
- （可选）Python/框架版本、是否能跑通、运行结果截图或训练曲线
```

## 其他可以帮上忙的方式

- 报告失效链接、已归档项目（直接开 Issue）
- 补充明显缺货的方向：目前**Agent 的记忆机制 / 评测 / 可观测性**、**独立的 RLHF 与 DPO 从零实现**、**VAE 与 Normalizing Flow 的教学实现**最缺
- 完善 [LEARNING_PATH.md](LEARNING_PATH.md) 里的阶段安排
- 修正描述不准确或层级放错的条目

## 许可

提交 PR 即表示你同意本仓库的 MIT 许可。各收录仓库的代码许可以其自身仓库为准，本清单不对其做任何授权。
