## 贡献

把「上下文学习」用到协作式多智能体 RL：先在集中式训练中学习一个集中式嵌入模型（CEM）捕捉团队级轨迹表示，再让去中心化嵌入模型（DEMs）逼近它，使每个 agent 在执行期只凭本地子轨迹就能检索到**团队级**历史轨迹，从而缓解去中心化部署导致的「任务对齐与奖励分配错配」。

## 机制要点

整体流程见 Figure 1：虚线为训练期数据流（CEM 从离线数据集采样轨迹并蒸馏团队信息给 DEMs），实线为执行期数据流（当前子轨迹按相似度从混合记忆检索轨迹）。CEM 的结构（Figure 2）利用**队内可见性**：同一时间步内同队的观测与动作 token 互相注意，因果 Transformer 在此之上做自回归预测，从而把「团队协同模式」编码进嵌入。关键设计是把「信息不对称」显式建模：执行期每个 agent 看不到全局，于是训练期的蒸馏承担了信息补全的职责。

在 StarCraft Multi-Agent Challenge（SMAC）等协作任务上，对各场景做 50 次随机任务测试并报告均值回报与 95% 置信区间（Figure 3）；Table 1 是消融，逐个去掉组件（含检索项 Ret.）观察最终适应回合的平均回报，用于验证「集中式嵌入 + 去中心化检索」各自的贡献。

## 局限与定位

第一，方法依赖**集中式训练 + 离线轨迹数据集**，这在许多现实多 agent 场景（跨组织、隐私受限）中不可得，与 CTDE（集中训练分散执行）范式共享同一局限。第二，检索到的是「历史轨迹」这一粗粒度记忆单位，缺少对其做压缩/归纳的机制——记忆库随任务数线性增长，因此它属于「用检索替代学习」的范式，与本方向的记忆压缩主线只在「如何组织可复用经验」这一层相关。第三，评测集中在 SMAC 类离散协作任务，向 LLM 多 agent 自然语言协作的外推需谨慎。定位上，它为「多 agent 的共享记忆应当如何在去中心化条件下近似」提供了一个可参考的形式化。
