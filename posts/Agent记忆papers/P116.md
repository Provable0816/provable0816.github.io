# P116 Self-Taught Agentic Long Context Understanding

## 一句话贡献

提出 AgenticLU：把长上下文问答重述为「**自我澄清 + 上下文接地**」的 agentic 工作流。核心是 Chain-of-Clarifications（CoC）——模型通过自生成的澄清问题与相应的上下文证据逐步细化对问题的理解；把推理时的搜索扩展为**树搜索**（每个节点是一次 CoC 步骤），在深度 3、分支因子 8 的设定下于 NarrativeQA 上达到 **97.8% 的答案召回率**；为摊薄搜索成本，用 CoC 过程中得到的偏好对做两阶段微调（先监督微调学习分解策略，再用 DPO 提升推理质量）。

## 1. 问题与第一性原理动机

长上下文问答的困难不只是「上下文太长」，还包含一个被忽视的环节：**问题本身可能不明确**。当问题存在歧义或缺少必要的锚点（例如「他们最后去了哪里」中的「他们」指代不明），直接检索会指向错误的证据，模型再强也无从恢复。因此论文提出的第一步不是检索而是**澄清**——先让模型把问题分解为可验证的子问题，再为每个子问题去找对应证据（contextual grounding），形成「澄清—接地」的交替链条。这一顺序颠倒（先弄清问什么，再找证据）是方法的核心判断。

## 2. 核心洞察

洞察在于把**推理时搜索与训练解耦又结合**：树搜索在推理时能显著提升召回（97.8%），但代价高昂；而搜索过程本身会产生大量「哪个澄清路径更好」的比较信号，正好可以当作偏好对用于训练，从而把这部分算力**转化为模型能力**（amortize cost to training）。这与 P023（MemAgent 把 RL 训练用于记忆读写策略）的动机一致：把昂贵的推理期搜索/试错，固化为模型内的策略。第二个洞察是澄清与接地必须交替进行——只澄清不接地会退化为空泛的自我提问，只接地不澄清会在错误的问题上做精确检索。

## 3. 方法机制

(1) 生成澄清问题（自提问）；(2) 为每个澄清获取上下文证据（grounding）；(3) 把上述步骤组织为树，节点为一次 CoC 步骤，通过搜索（深度 ≤3、分支因子 8）寻找最优路径；(4) 从搜索中得到偏好对，做两阶段微调：SFT 学分解策略、DPO 提升推理质量。代价是：树搜索的推理成本随深度与分支指数增长；微调需要高质量偏好对；澄清过程可能引入与用户意图偏离的假设（自提问漂移）。

## 4. 实验证据

NarrativeQA 上，在深度 3、分支因子 8 的搜索设定下取得 97.8% 的答案召回率——这是一项很强的召回证据（说明搜索能找到含答案的上下文）。论文另报告两阶段微调后的模型能更有效且高效地生成澄清并取回相关上下文。需要注意的是「答案召回率」与「最终回答正确率」是两个不同指标，前者衡量是否**找到**了含答案的证据，后者才反映端到端能力。

## 5. 第一性原理再审视

第一，97.8% 是召回率，指标口径需要明确：如果是「搜索结果中包含答案所在段落」的比例，它衡量的主要是搜索覆盖能力，而 RAG 类系统的瓶颈常在下游的读取与推理；因此该数字不能直接读作端到端准确率。第二，树搜索的成本结构是关键：深度 3 × 分支 8 意味着数十次模型调用，摘要未给出延迟与 token 成本；即使通过微调摊薄，推理时是否仍需搜索决定了它在生产中的可用性。第三，「自我澄清」存在**自提问漂移**风险：模型自生成的澄清问题可能固化一个错误假设（例如把「他们」理解为错误的对象），之后所有检索都在错误方向上高效进行；需要机制来检测并回退，而摘要未涉及。第四，两阶段微调（SFT + DPO）依赖搜索产生的偏好对，这使训练数据分布与推理策略绑定；若部署时改变搜索配置（深度/分支），微调后的策略可能不再匹配。第五，评测集中在 NarrativeQA 这类叙事性长文，对需要精确数值、表格或多源交叉验证的任务，澄清式分解的收益可能不同。

## 6. 与相邻工作的关系

与 P099（HippoRAG 用图传播完成多跳）、P024（REMem 用工具化图探索）相比，AgenticLU 的多跳发生在**问题空间**（澄清）而非知识空间（实体关联），是互补的一种多跳形式；与 P023（MemAgent）共享「用昂贵的推理期过程训练出廉价策略」的范式；与 P114（RMM 用引用作为反馈）在「从推理过程提取训练信号」这一点上同源，但信号类型不同（偏好对 vs 引用证据）；与 P109（CoA 多 agent 分段）相比，本文不切分上下文而切分**问题**。定位上属于 agentic 长上下文推理的一种新分解方式。

## 7. 可迁移点与开放问题

可迁移：(a) 「先澄清问题再检索证据」的顺序在真实用户查询（常含歧义指代）场景中价值很大，值得作为 RAG 系统的默认前置步骤；(b) 「把推理期搜索过程转成偏好对用于训练」是压缩昂贵搜索成本的通用手法。开放问题：答案召回与端到端正确率的差距；搜索成本与部署可行性；自提问漂移的检测与回退；微调策略对搜索配置的依赖；以及在结构化与数值型长文档上的适用性。
