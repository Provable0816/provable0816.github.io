# P186 SubGCache: Accelerating Graph-based RAG with Subgraph-level KV Cache

- 会议/来源：AAAI 2026（主会）
- 方向簇：AGENT
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40827
- 本地全文：cache/txt/P186.txt

## 贡献

利用图式 RAG 的一个统计特性——不同查询检索到的**子图往往高度相似**——把 KV 缓存的复用单位从「前缀/整段文本」上移到「子图结构」：按子图嵌入对查询聚类，为每簇构造代表性子图并**预计算其 KV 缓存**，簇内查询直接复用代表子图的 KV，从而省去重复的 KV 张量计算。

## 机制要点

设定为图式 RAG 的 in-batch 场景：一批查询同时到达，共享系统。流程（Figure 2）：对文本图 $G$ 与查询批 $\{q_1,\dots,q_m\}$，先检索各查询的子图 $s_i$，再按子图嵌入聚类，为每簇选出代表子图并预计算 KV；簇内查询复用该 KV，随后按簇释放，再进行下一簇的处理（论文强调这种「按簇复用-释放」保证显存效率）。与传统前缀缓存（P199 之外的另一条复用路线）相比，复用的对象是**结构化提示**而非线性前缀，因此需要新的等价性判据：哪些查询可以共享同一份 KV。

## 关键结果

数据集为 Scene Graph、OAG、DBLP；基线为两个代表性图式 RAG 框架 G-Retriever 与 GRAG，SubGCache 作为即插即用模块得到 G-Retriever+SubGCache 与 GRAG+SubGCache；骨干 LLM 含 Llama-3.2-3B 等。主指标为 ACC（质量）、RT（运行时间）、TTFT（首 token 时间）与 PFTT；Table 1 给出整体对照，摘要报告 **TTFT 最高降低 6.68×**，同时生成质量可比甚至更好。

## 局限与定位

第一，聚类把「相似子图」当作可互换，但相似不等于等价：代表子图与成员子图之间的结构差异会被静默丢弃，论文用「质量可比」作为兜底证据，缺少**最坏情形**分析（差异最大的成员子图损失多少）。第二，收益依赖「不同查询检索到相似子图」这一数据特性，在图谱稀疏或查询分布分散时聚类簇会变小、命中率下降——这决定了方法的适用边界，论文未给出命中率与加速比的联合分布。第三，复用对象与查询绑定程度、缓存淘汰策略都会显著影响真实 serving 表现。定位上，它属于「记忆复用」而非「记忆压缩」：不改变表示大小，而减少重复计算，与 P184（多上下文 KV 稀疏）、P204（ICaRus 同构缓存复用）同属缓存复用家族，在 agent 化 RAG 的工程优化中很实用。
