# P152 StreamKV: Streaming Video Question-Answering with Segment-based KV Cache Retrieval and Compression

- 会议/来源：AAAI 26（主会）
- 方向簇：VLM
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/37305
- 本地全文：cache/txt/P152.txt

## 一句话贡献

提出 StreamKV：一个**免训练**框架，为 Video-LLM 配备先进的 KV cache 检索与压缩能力，用于流式视频问答。与既有方法采用**均匀切分（uniform partitioning）**不同，StreamKV 把视频流**动态划分为语义片段**，从而更好地保留语义信息；在检索侧，它为每个片段计算摘要向量以保留片段级信息。

## 1. 问题与第一性原理动机

论文指出的改进点与前一批的多个工作构成同一条脉络：均匀切分（按固定帧数或固定时长）会把语义完整的事件切断，从而使检索命中的片段只包含事件的一部分——这正是 P039（ChunkKV 的固定 chunk 边界）、P118（句间相似度动态切块）、P111（「边界丢失」）在文本侧的对应问题。视频的语义边界未必与固定时间窗口对齐（一个动作可能跨越窗口），因此把「切分单位」从时间改为语义是结构性改进。第二点是摘要向量：片段级摘要可以承载片段内被压缩掉的细节，使「压缩后仍可被检索到」——这与 P055（UniGist 用 gist 替换原 token 但保留位置）与 P106（xRAG 用 embedding 承载文档）的设计意图一致。

## 2. 核心洞察

洞察是**检索与压缩应当在同一粒度层次上协同设计**。既有流程常把「先压缩再检索」或「先检索再压缩」当成两步独立操作，导致检索粒度与压缩粒度不匹配（例如按帧压缩却按片段检索）。StreamKV 把片段作为共同单位：片段既是压缩单位（生成摘要向量），也是检索单位（按查询匹配摘要），从而避免粒度错配——这是一个常被忽视但在工程上决定成败的细节。

## 3. 方法机制

(1) 把视频流动态划分为语义片段；(2) 为每段计算摘要向量，保留片段级信息；(3) 按查询检索相关片段并取用其 KV。方法免训练，可直接用于现有 Video-LLM。代价是：语义切分需要额外判定（依赖相似度或事件检测信号），其质量决定上游的一切；摘要向量是有损的，对需要逐帧细节的问题不利；流式场景下片段需在线更新（新帧到来可能改变片段边界），这在摘要向量已计算的情况下难以回退；免训练意味着压缩策略无法针对具体模型优化。

## 4. 实验证据

论文报告在流式视频问答上相对既有检索与压缩方法取得改进；具体基准与数值需回看正文。评价这类方法应关注：在需要跨片段推理的问题上（而非单片段命中）表现如何，因为片段化天然削弱跨片段关联。

## 5. 第一性原理再审视

第一，「动态语义切分」在**离线**视频上可行（可看到全局再划分），但**流式**场景要求在线决定边界——一旦划分后新帧到来可能需要修正，论文需要说明边界的在线更新策略，否则「语义片段」的宣称在流式设定下会被削弱。第二，摘要向量的召回能力是关键未知量：它能否让查询命中「细节藏在被压缩部分」的片段？这更像检索命中率问题而非压缩率问题，需要专门的召回评测。第三，与 P059（InfiniPot-V 的硬性显存上限）相比，StreamKV 未强调显存上界，而流式设备（手机、AR 眼镜）恰恰需要硬约束；两种设计目标（检索精度 vs 资源可预测性）不同。第四，视频的语义边界检测可借鉴音频/语音线索（场景切换、说话人变化），论文未提及是否利用多模态信号。第五，免训练是优点，但也意味着无法像 P041（DMS）那样通过少量训练获得更高的压缩比与更好的精度保持；其收益上限受免训练设定约束。

## 6. 与相邻工作的关系

与 P059（InfiniPot-V 的流式视频、查询无关、硬显存上限）构成同类场景的两种取舍：一个强调资源约束、一个强调语义切分与检索；与 P028（MARC 的检索 + RL 蒸馏）、P029（VideoChat-Flash 的层级压缩）相比，StreamKV 更轻量且免训练；与 P039（ChunkKV 以 chunk 为单位）、P118（语义动态切块）在「切分单位应与语义对齐」上同源，应用于视频域；与 P081（MMInference 的模态感知稀疏注意力）在优化视频输入的成本上互补——一个改注意力模式、一个改 cache 组织。定位上属于视频流式场景的检索与压缩协同设计。

## 7. 可迁移点与开放问题

可迁移：(a) 「检索粒度与压缩粒度必须一致」是工程上极易被忽略却影响显著的设计约束，适用于任何「先压后取」或「先取后压」的流水线；(b) 用语义边界替代固定窗口切分，可推广到音频、多模态流与日志流。开放问题：流式场景下片段边界的在线更新；摘要向量的召回能力；跨片段推理的表现；硬性显存约束的支持；以及利用多模态线索改进边界检测。
