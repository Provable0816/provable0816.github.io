# P169 VFlowOpt: A Token Pruning Framework for LMMs with Visual Information Flow-Guided Optimization

- 会议/来源：ICCV 2025
- 方向簇：VLM
- 链接：/content/ICCV2025/html/Yang_VFlowOpt_A_Token_Pruning_Framework_for_LMMs_with_Visual_Information_ICCV_2025_paper.html

## 贡献

指出视觉 token 冗余带来的计算成本问题虽有大量研究，但**剪枝框架与策略仍然过于简单、探索不足**，常导致显著的性能退化。VFlowOpt 提出一个 token 剪枝框架，包含**重要性图（importance map）的推导过程**与**带回收机制（recycling mechanism）的渐进式剪枝模块**，并称其超参由视觉信息流的引导来优化。

## 机制要点

论文的两个设计要素各有针对。「**渐进式剪枝**」针对的是「一步到位剪枝风险大」的问题：分多阶段逐次削减，使模型可在中间阶段重新评估哪些 token 仍需保留——这与 P085（Activation Beacon 渐进压缩）、P144（半引导迭代压缩）在原理上一致，即在缺乏可靠一次性判据时用迭代换取精度。第二个要素「**回收机制**」更有意思：它承认剪枝可能出错，因此允许被剪掉的 token 在后续阶段被**重新纳入**，从而把不可逆的操作变成可撤销的——这与 P088（OmniKV「不丢弃、动态选择」）、P025（记忆回调）属于同一思想谱系：**用可撤销性替代判据的绝对正确性**。

## 关键结果

论文报告 VFlowOpt 在 LMM 上以更少视觉 token 保持性能，并强调重要性图推导与渐进回收机制带来的改进；具体加速与精度数值需回看正文。

## 局限与定位

第一，「视觉信息流引导的超参优化」这一表述需要具体化：若超参由另一模型或启发式在线决定，则引入额外开销与新失效点；其稳定性与成本需要数据支撑。第二，渐进剪枝意味着多次前向或多次评估，延迟可能高于单步剪枝——在实时视觉应用中这是决定性的取舍；论文应给出端到端延迟而非仅 token 数。第三，回收机制的有效性依赖「被剪 token 的信息在后续仍可恢复」，若在早阶段其 KV 已被丢弃，则需要重新计算——这又回到计算成本问题；需要说明回收的成本模型。第四，与 P168（FrameFusion 的相似度合并 + 重要性剪枝）相比，一个靠引入第二个维度、一个靠引入可撤销性与渐进流程，两者可以组合；与 P030（MixKV）、P095（VL-Cache）、P161（AirCache）等同类方法相比，需要统一预算下的横向对比才能定位。定位上属于视觉 token 剪枝的框架化工作，其可撤销性设计是相较于同类方法的差异化点。
