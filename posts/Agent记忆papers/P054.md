# P054 Efficient Prompt Compression with Evaluator Heads for Long-Context Transformer Inference

## 一句话贡献

发现 transformer LLM 中存在一类可被识别为「评估者头」（evaluator heads）的注意力头，它们专门负责在长输入中挑出对推理最重要的 token；据此提出免训练的 EHPC：prefill 阶段只用含评估者头的前几层让模型「速读」整段 prompt，随后把筛出的重要 token 交给完整模型推理，在 prompt 压缩与长上下文加速两个基准上取得 SOTA。

## 1. 问题与第一性原理动机

主流 prompt 压缩（SelectContext、LLMLingua、LongLLMLingua）依赖预训练模型输出的 logits 或困惑度来逐 token 打分，为处理长文必须**分块**，于是同一段文本要被多次前向——计算复杂度随长度变得不可接受。LLMLingua-2 这类更高效的方法则通常需要额外训练一个压缩器。这里存在一个结构性矛盾：为了省「完整模型的前向成本」，反而要先付出昂贵的前向或训练成本。EHPC 的出发点是把这一步彻底绕开——**能否直接复用模型自身的某一小部分，来充当「读者」**？

## 2. 核心洞察

论文的观察是：模型内部并非所有层都在同等程度地参与「决定看哪里」。存在特定的注意力头（evaluator heads），其注意力分布能有效标识长输入中对后续推理重要的 token；换句话说，**「挑重点」这项能力已经被预训练模型自身习得并局部化了**，无需外部小模型或额外训练。由此得出两个推论：(1) 压缩决策可以直接从评估者头的注意力读出，天然免训练；(2) 因为只需前几层就足以做判断，压缩过程可以在 prefill 的最浅阶段完成，之后把精简后的 token 序列交给完整模型——这使复杂度从「完整模型 × 分块次数」降到「浅层 × 一次」。

## 3. 方法机制

(1) 识别评估者头：在 transformer 各层中定位对「选择重要 token」敏感的头；(2) 速读式压缩：prefill 阶段只在含评估者头的前几层上跑整段 prompt，据其注意力选出重要 token；(3) 精简推理：把保留的 token 交给完整模型做后续深度前向。方法是 training-free 的，不需要额外参数或压缩器模型。代价是：(a) 评估者头的识别需要一次性的分析（是否跨模型通用需验证）；(b) 压缩后 token 序列的位置信息与原文不一致（被删 token 造成不连续），可能影响位置编码语义；(c) 仅用浅层信息做全局判断，在需要深层语义才能判断重要性的文本上可能漏选。

## 4. 实验证据

论文称在两类基准上达到 SOTA：prompt 压缩，以及长上下文推理加速；并说明相较商业 API 调用可降低成本同时提升性能。论文另报告其效果与基于 KV cache 的加速方法具有竞争力——这一点值得注意，因为它意味着 prompt 级压缩（可跨 API 使用）与 KV 级压缩（需本地模型）在性能上可以打平，从而在只能调用 API 的场景中具备独特价值。

## 5. 第一性原理再审视

三点追问。第一，评估者头这一概念的可迁移性是方法成立的前提：若这些头依赖具体模型/训练数据，那么每换一个模型都需要重新做一次识别与验证，方法的「免训练」优势会被部分抵消；论文摘要未给出跨模型族的一致性证据。第二，只在前几层做判断，隐含假设「token 重要性可以在浅层被判定」。但已有研究普遍显示深层的语义与指代关系对判断关键性很重要；在需要理解长距离指代或跨段因果的任务上，浅层速读可能系统性漏掉关键 token，论文需要给出这类任务的专门评测。第三，删 token 会破坏位置连续性，而位置编码（尤其 RoPE 的相对位置）直接影响注意力；论文未在摘要中说明如何处理这一点，若靠「保持原位置索引」则与 KV 压缩中的位置处理存在同类困难。第四，效率叙事需要口径统一：论文的对比对象既有需分块多次前向的 logits 类方法（EHPC 大幅占优），也有本身就很高效的方法；与后者的比较才决定它在真实流水线中的位置。

## 6. 与相邻工作的关系

与 P019（COMI，软 token 压缩）最不同：COMI 需要训练 encoder 并改写表示为连续向量，EHPC 保留原始 token、完全免训练，因此可跨 API 使用；与 LLMLingua/SelectContext 属同一硬 token 压缩家族，区别是打分信号来源（内部头 vs logits/困惑度）与复杂度（一次浅层 vs 多次分块前向）；与 KV 级方法（SnapKV、Ada-KV 等）相比，prompt 压缩在 API 场景不可替代，而若在本地部署，二者可能互补——先压缩 prompt 再压 KV。

## 7. 可迁移点与开放问题

可迁移：(a) 「预训练模型内部已存在完成任务所需的子能力，先找它、再复用它」是降低方法成本的通用范式（评估者头之于 token 选择，类似检索头、归纳头等专能头）；(b) 只在浅层完成一次廉价扫描、再让完整模型处理精简输入，这一「粗筛—精算」结构可推广到多模态输入、工具调用参数筛选与 RAG 的初筛阶段。开放问题：评估者头的跨模型/跨语言可迁移性与自动识别方法；浅层判断在深层语义任务上的漏选率；删除 token 后的位置编码处理；以及 EHPC 与 KV 级压缩叠加时的增益是否可叠加。
