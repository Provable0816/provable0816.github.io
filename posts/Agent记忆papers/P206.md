# P206 QuoKA: Query-Oriented KV Selection for Efficient LLM Prefill

## 一句话贡献

提出一个**免训练、硬件无关**的稀疏注意力算法，专门加速 chunked prefill：核心观察是「与平均 query 余弦相似度低（$S_q$ 高）的 query 会与更多 key 强交互、并对最终注意力 logits 贡献最大」，因此先保留一小批代表性 query，再据此 subselect 最对齐的 key，在接近基线精度的前提下把每次注意力的 KV 对数减少 88%。

## 1. 问题与第一性原理动机

prefill 延迟可占端到端运行时的 70% 以上，而 chunked prefill（把输入切块调度）是主流部署方式。此时瓶颈是每个 chunk 对全量 KV 的稠密注意力。已有的稀疏注意力多在解码阶段优化（每步一个 query），而 prefill 阶段的**查询是成批出现的**，因此「选哪些 key」可以被设计成「先选 query、再选 key」的两级问题。论文的第一个观察（Figure 2，Llama 3.2-3B-Instruct 第 0 层第 11 头）给出判据：把 query 相对均值 query 的偏离程度记为 $S_q$，PCA 投影显示 $S_q$ 高的 query 更靠近 key 簇，且 $S_q$ 与 $\max_k A$（除 sink token 外）正相关——也就是说，**偏离均值的 query 才是真正在做"检索"的 query**，而接近均值的 query 注意力平摊、贡献小。

## 2. 核心洞察

这带来一个漂亮的归约：既然注意力的信息量集中在少数「偏离均值」的 query 上，就不必为所有 query 都选 key。于是稀疏化可以分解为 (i) query 子选择（去除冗余查询）与 (ii) 基于余弦相似度的 key 子选择。两级的组合把「$N_q\times N_k$ 的稠密矩阵」变成「少量 query × 少量 key」的稠密计算，且不依赖任何硬件特性或训练过程——这使它可同时部署在 GPU 与 CPU 上（论文在 Intel Xeon 上也报告了加速）。

## 3. 方法机制

算法（Figure 1、Algorithm 1）三步：(1) **query 子选择**：依据 $S_q$ 保留信息量最大的一小批 query；(2) **余弦相似度打分**：计算保留 query 与 key 的余弦相似度以估计匹配强度；(3) **key subselection**：为每个 chunk 选出与这些 query 最对齐的 KV，交由稠密注意力 kernel 计算。代价与边界：两级选择都是启发式近似，理论上无法保证与全注意力等价（论文以「接近基线精度」作为经验保证）；$S_q$ 的统计依赖具体层/头（论文举例为第 0 层第 11 头），跨层是否需要不同策略值得追问；子选择本身的开销在高压缩率下也必须计入。

## 4. 实验证据

基准为 Needle-In-A-Haystack、LongBench、RULER 与 Math500（覆盖检索、长文任务、超长上下文与数学推理四类）。效率结果（摘要）：**首 token 时间（TTFT）降低 3×**、Nvidia GPU 上注意力加速 **5×**、Intel Xeon CPU 上最高近 **7×**，同时每次注意力评估使用的 KV 对数减少 **88%**。附带的密度对照试验（Table 给出 Sample Attention 等基线的逐任务数值，如 0.854–0.885 区间的相对水平）用于说明其相对既有稀疏方法的质量优势。

**证据缺口**：(a) 「接近基线精度」在 NIAH 这类**单针检索**任务上的表现最关键，因为该任务对 key 子选择错误最敏感，需要逐任务而非平均值核对；(b) $S_q$ 阈值是核心超参，论文缺少阈值—精度—加速的完整曲面；(c) query 子选择假设「偏离均值的 query 才重要」，但在**长文档问答**中真正需要聚合分散证据的 query 可能恰是「均值附近」的泛化型查询，这是一个可构造的反例风险，需要针对性实验；(d) 与 kernel 级方案（FlashAttention 稀疏变体）的比较在同等位宽/预算下是否公平需要核对。

## 5. 第一性原理再审视

QuoKA 的贡献可以概括为一次**角色区分**：把 query 分成「在做检索的」与「在背景统计的」，只对前者做精确计算。这与 P183（SPARK 的通道显著性随查询变化）、P182（符号索引）在精神上一致——都是「识别稀疏结构再压缩」。其最需要警惕的假设是 $S_q$ 与「attentional 信息量」的等价性：$S_q$ 是**几何量**（偏离均值），而信息量是**任务量**（对最终输出的因果影响）。两者的相关性在一个 head 上被展示，但缺少跨层跨头的统计分布，也缺少因果检验（例如人为剔除高 $S_q$ 的 query 后精度掉多少、剔除低 $S_q$ 的 query 又掉多少——后者才是该方法安全性的直接证据）。第二，从信息论看，「少数 query 决定注意力」意味着注意力矩阵是**低秩可近似的**，这一性质在长上下文与重复内容多的场景（检索增强的拼接文档）中更强，而在需要广泛聚合的任务中更弱——因此该方法的收益应当与输入类型强相关，论文的四个基准可据此重新分组解读。第三，它同时报告 CPU 加速是有意义的：在 CPU/边缘部署中，稀疏性带来的访存减少往往比 FLOPs 减少更重要，这与 GPU 上的瓶颈结构不同。

## 6. 与相邻工作的关系

与解码期稀疏注意力（token 淘汰类）的区别是它处理的是**成批 query**，因此多了一层「选 query」的自由度，这在 prefill 语境下是新的。与 P177（Judge Q）相比，两者都在改进「用哪些 query 打分」：Judge Q 学习一组软 token 探针，QuoKA 直接在现有 query 中挑代表——一个是学习式、一个是选择式。与 P199（MatryoshkaKV 降特征维）、P171/P174（位宽压缩）正交，可叠加。与 P182（self-indexing 让压缩 key 当索引用）在设计目标上互补：P182 让 key 自带索引，QuoKA 让 query 自带筛选。

## 7. 可迁移点与开放问题

可迁移：(a)「**先选信息量大的查询，再据其选数据**」这一两级归约，可迁移到向量库检索（先挑代表性查询向量再做 ANN）、多模态 token 选择、以及 agent 记忆的批量读取；(b) 以「偏离均值程度」作为信息量的廉价代理，是无需训练即可部署的实用启发式。开放问题：$S_q$ 的因果验证与跨层/头分布；面向「需要广泛聚合」的查询类型的补偿机制；阈值自适应；与 KV 量化/淘汰的联合压缩；以及在 CPU 与 GPU 上最优策略不同的原因与统一建模。
