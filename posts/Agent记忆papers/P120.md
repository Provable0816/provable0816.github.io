# P120 Hierarchical Document Refinement for Long-context Retrieval-augmented Generation

- 会议/来源：ACL 2025
- 方向簇：AGENT
- 链接：/2025.acl-long.176/

## 贡献

提出 LongRefiner：一个**即插即用**的文档精炼器，利用长文档自身的结构特征降低 RAG 的推理成本与噪声。它由三部分组成：双层查询分析（dual-level query analysis）、层级化文档结构化（hierarchical document structuring），以及在**单一基础模型**上通过多任务学习实现的自适应精炼。在七个问答数据集上达到有竞争力的性能，同时相对最佳基线的计算成本与延迟**低 10 倍**。

## 机制要点

设计的重点是把「结构」变成效率来源：长文档天然有章节与层级，若先把查询分解到与文档层级匹配的粒度，再按层级逐层筛选，就能避免把整篇文档塞进上下文。这与 P118（按句间相似度动态切块）、P039（把 chunk 作为压缩单位）在动机上一致，但 LongRefiner 依赖**文档已有的结构**而非统计切分——在结构化文档（报告、法律、手册）上更可靠，在无结构的长对话上则退化。把三项能力压进单一基础模型并做多任务学习，是为了减少多模型串行带来的延迟，这也是 10× 成本优势的来源之一。

## 关键结果

七个问答数据集上性能有竞争力，而计算成本与延迟相比最佳基线低 10×；论文进一步论证了可扩展性、效率与有效性。

## 局限与定位

第一，10× 的成本优势需要明确对照对象：若基线是需要多轮检索或多模型协作的方案，则优势主要来自「单模型多任务」这一架构选择，而非精炼算法本身；与轻量基线（如单纯的关键词检索）对比才能定位真实效率。第二，依赖文档层级意味着适用范围受限于结构化文档；对无标题、无段落结构的长文（如转录稿、聊天记录）其效果需要单独验证。第三，多个任务共用一个基础模型可能带来任务间干扰，需要给出各任务的分解指标，而非仅报告平均值。第四，与 P109（Chain-of-Agents 用多 agent 分段）、P116（AgenticLU 澄清式分解）相比，LongRefiner 属于「结构化预处理」路线，成本最低但对文档质量的依赖最强；三者在不同文档类型上各有优势，选择应依据输入结构而非性能排名。
