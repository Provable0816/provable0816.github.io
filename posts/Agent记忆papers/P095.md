# P095 VL-Cache: Sparsity and Modality-Aware KV Cache Compression for Vision-Language Model Inference Acceleration

- 会议/来源：ICLR 2025
- 方向簇：VLM
- 链接：/paper_files/paper/2025/hash/00db17c36b5435195760520efa96d99c-Abstract-Conference.html

## 贡献

指出把面向 LLM 的 KV 压缩方法**直接迁移到 VLM** 会导致精度与加速都不理想，并提出 VL-Cache：一种面向 VLM 的 KV 压缩配方。论文首先区分视觉 token 与文本 token，分别考察它们在 prefill 与 decoding 阶段的稀疏模式，据此设计 (1) 层自适应、稀疏度感知的缓存预算分配，以及 (2) 模态感知的 token 打分策略。

## 机制要点

两项设计对应两个被忽视的差异：其一，视觉 token 数量远大于文本 token，但其注意力稀疏性在不同层之间差别很大，因此统一分配预算会浪费或不足；其二，视觉与文本 token 的重要性判据不同——文本 token 的重要性可由语言统计支撑，而视觉 token 的价值取决于其是否被当前问题引用，需要单独的评分口径。把这两点分开处理，是「模态感知」的实际含义，而不只是给两类 token 加权。

## 关键结果

在多个基准数据集上，仅保留 10% 的 KV cache 即可达到与全量 cache 相当的精度；速度方面，生成 100 token 的端到端延迟最多加速 2.33×，解码阶段最多加速 7.08×，同时 GPU 上 KV cache 的显存占用降低 90%。

## 局限与定位

第一，「10% 即相当精度」需要按任务细分：视觉密集任务（高分辨率文档理解、视频细粒度问答、图表数值读取）依赖被压缩掉的视觉细节，而通用 VQA 对细节的容忍度更高；摘要未给出这类压力测试，因此不能推断该方法在所有 VLM 场景下都成立。第二，解码加速 7.08× 与端到端 2.33× 的差距说明瓶颈不只在解码（视觉编码与 prefill 也占大头），读者应据此校准预期。第三，模态感知打分依赖对「视觉 token 是否被引用」的判断，其可靠性在多轮追问下会变化（同一图像与不同问题组合时重要区域不同），这一动态性未被讨论。第四，与 P028（MARC）、P029（VideoChat-Flash）、P030（MixKV）、P058（PrefixKV）、P081（MMInference）等多项 VLM 压缩工作并列时，其差异点主要在「模态感知打分 + 层自适应预算」，缺乏与这些方法的直接横向对比会削弱定位的说服力。
