# P079 Efficient Length-Generalizable Attention via Causal Retrieval for Long-Context Language Modeling

- 会议/来源：ICML 2025
- 方向簇：CTX
- 链接：https://proceedings.mlr.press/v267/hu25v.html

## 贡献

提出 Grouped Cross Attention（GCA）：把输入切成 chunk，用当前 chunk 检索 top-k 个相关的历史 chunk，再用**固定大小**的注意力窗口处理被检索内容，从而在常数注意力窗口下保持对远距离信息的访问能力。核心创新在于检索器**不是现成组件**——它被端到端训练，目标是让检索到的历史 chunk 能最小化后续 token 的自回归损失。

## 机制要点

与「外挂向量检索器 + 长上下文模型」的两段式做法相比，GCA 把检索目标直接绑定到语言建模损失，因此检索器学到的是「对生成有用」而非「语义相似」。这个差别很关键：语义相似的历史片段未必能降低下一 token 的困惑度（例如它只是话题相近）。由于注意力窗口固定，计算与显存不随序列长度增长；检索只是选择块，因此复杂度可控。

## 关键结果

论文报告基于 GCA 的模型在 **16M** 上下文长度的 passkey 检索上达到近乎完美的准确率，而该长度是训练长度的 **1000×**——即 1000 倍的长度外推；同时训练与推理的计算/显存开销显著降低。

## 局限与定位

第一，最强证据是 passkey 检索——单针、低信息密度、且答案形式固定，这类任务恰好最大化「检索对」的收益；1000× 外推的说服力需要用多针、多跳、需要聚合多块证据的任务来补强，否则无法区分「学会了检索」与「学会了找那一个异常块」。第二，端到端训练检索器意味着**检索质量与语言建模目标耦合**：在预训练语料上「降低下一 token 损失」的历史块，未必是下游问答任务所需的证据（对比 P045 指出的查询无关 vs 查询相关问题），因此下游微调后检索行为可能偏移。第三，chunk 大小是核心超参，决定检索粒度与窗口利用率，但摘要未给出其敏感性。第四，与 P056/P057 等混合架构相比，GCA 用检索替代了对全量注意力的部分保留，其上限受 top-k 与窗口大小共同限制，缺少与「同等算力的全注意力」的公平对照。定位上属于「可学习检索 + 固定窗口」这一强外推路线。
