# P064 HiFC: High-efficiency Flash-based KV Cache Swapping for Scaling LLM Inference

- 会议/来源：NeurIPS 2025
- 方向簇：KV
- 链接：/paper_files/paper/2025/hash/4431224d3762aa655f0aee4eaf04ff16-Abstract-Conference.html

## 贡献

提出 HiFC：跳过 DRAM 的 KV cache 换出方案。既有框架（vLLM 等）把 KV 页换到主机 DRAM，但大容量 DRAM 成本高昂；换到 SSD 又因数据路径必经 CPU 导致吞吐骤降（FlexGen 即如此）。HiFC 把 KV 页存放在商用 NVMe SSD 的伪 SLC（pSLC）区域，利用 GPU Direct Storage 实现 SSD 与 GPU 之间的**直连传输**，绕开主机 DRAM 与 PCIe 瓶颈。

## 机制要点

三项设计支撑收益：pSLC 区域在顺序 I/O 下可维持高吞吐，且写入寿命比常规 TLC 模式提升最多 8×；细粒度块映射把写入限制在高性能 pSLC 区，从而使延迟与吞吐在负载下保持稳定；GPU Direct Storage 消除了 SSD→CPU→GPU 的中间拷贝。代价是依赖特定 SSD 特性（pSLC 模式、GDS 支持）与细粒度映射的元数据管理，硬件耦合较强。

## 关键结果

在 NarrativeQA 等长上下文负载上，推理吞吐与基于 DRAM 的换出方案相当；GPU 服务器的内存扩容成本三年期内降低 4.5×。

## 局限与定位

第一，这类系统工作的评估应关注**尾部延迟与负载相关行为**，而非平均吞吐：SSD 在写放大、垃圾回收与并发竞争下容易出现长尾延迟，而论文的对照是 "comparable throughput"，需要核实 P99 延迟是否同样可比。第二，写入寿命提升 8× 是相对 TLC 模式而言，但 KV 换出是**高频写场景**，实际寿命仍受每日写入量约束；论文未给出目标负载下的寿命估算。第三，硬件耦合度高（pSLC + GDS + 细粒度映射），在云环境中能否可用取决于实例类型。第四，与 P061、P062 这类算法侧方法完全正交——HiFC 不减少需要多少 KV，只改变它存放在哪里；因此它与其他压缩方法的叠加是自然的，但也意味着其结果不能与压缩方法的收益直接相加比较。定位上属于面向成本而非显存的推理基础设施工作。
