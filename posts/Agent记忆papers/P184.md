# P184 Sparse Attention Across Multiple-Context KV Cache (SamKV)

- 会议/来源：AAAI 2026（主会）
- 方向簇：KV
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40266
- 本地全文：cache/txt/P184.txt

## 贡献

首次研究 **RAG 场景下的多上下文（multiple-context）KV cache 稀疏化**：在 RAG 中每篇检索文档的 KV 是**独立计算并缓存**的（彼此之间没有交叉注意力），这使得为「单上下文档」设计的稀疏方法失效。SamKV 在稀疏化某一段上下文时显式利用其它上下文提供的**互补信息**，并对被稀疏掉的信息做局部重算（personalized query embedding + 局部 recompute）。

## 机制要点

问题设定用 Figure 1 的「TTFT（相对全量重算的百分比）× F1」散点刻画三条路线：全量重算（高 TTFT）、直接复用（低 TTFT 但 F1 崩溃，表中 Reuse 一列 F1 低至 1.92–18.73，而 Recompute 为 19.94–37.70）、以及本文的折中。SamKV 的流程（Figure 2）：先为每段上下文生成**专属的个性化查询向量**（Personalized Query Embedding，Figure 3：上半部分增量 prefill 得到通用查询向量，下半部分为各上下文定制），据此得到压缩后的 KV，再对少量关键 token 做局部重算，从而在保留少量重算成本的前提下逼近全量重算的精度。Table 2 给出术语对照，Table 1 给出序列加载比例与重算比例的定义——这两个指标正是该问题的本质权衡轴。

## 关键结果

评测沿用以 CacheBlend、EPIC 等现有多上下文方法的框架以保证可比，模型为 Mistral 7B Instruct，数据集取多跳 QA 的 2WikiMQA、MuSiQue、HotpotQA。论文的核心主张是在显著降低 TTFT 与显存的同时，F1 接近全量重算而远离 naive reuse。

## 局限与定位

第一，「独立计算 + 事后融合」这一多上下文范式本身的精度损失是不可完全消除的（缺少真实交叉注意力），SamKV 用局部重算做近似，其收益上界由重算比例决定，而论文需要给出「重算比例—F1」的完整曲线才能支撑其实用价值判断。第二，个性化查询向量使每段上下文的缓存**与查询绑定**，这削弱了「前缀缓存可跨请求复用」的系统优势——在真实 serving 中，缓存可复用性往往比单请求质量更重要，论文未讨论这一取舍。第三，评测限于 Mistral 7B 与多跳 QA 数据集。定位上，它把「记忆压缩」的对象从单一上下文扩展到**组合式上下文**，与 P186（SubGCache 按子图聚类复用 KV）同属「RAG 场景下的缓存复用/压缩」这一分支，区别是 P186 复用同簇代表子图的 KV，SamKV 在跨上下文稀疏时互相利用信息。
