# P028 MARC: Memory-Augmented RL Token Compression for Efficient Video Understanding

- 会议/来源：ICLR 2026
- 方向簇：VLM
- 链接：/paper_files/paper/2026/hash/16049e0c3f47899091ac46f8b3afb178-Abstract-Conference.html

## 贡献

提出 MARC：面向视频理解的「先检索再压缩」（retrieve then compress）方案。用 Visual Memory Retriever（VMR）把视频切成事件级片段并挑出与查询相关的 clip，再用 Compression Group Relative Policy Optimization（C-GRPO）把教师网络的推理能力蒸馏到学生网络；在六个视频基准上，用约「一帧的 token 量」达到与 64 帧 Qwen2.5-VL-3B 基线几乎相同的准确率。

## 机制要点

现有视频 token 压缩多数是 training-free 的空间或时间维度合并，压缩过程不受任务监督，因此信息损失不可控。MARC 的取舍是把「选什么」交给检索、把「学到什么」交给 RL：VMR 负责在事件粒度上做查询相关的 clip 选择，避免无差别均匀采样；C-GRPO 则以教师输出为对齐目标训练学生，使压缩后的表示仍能支撑原有推理。这一组合把压缩从「前处理启发式」变成「后训练目标」。

## 关键结果

六个视频基准上，视觉 token 减少 95%（输入仅相当于一帧的 token 预算），准确率与 64 帧 Qwen2.5-VL-3B 基线近乎持平；GPU 显存降低 72%，生成延迟降低 23.9%（摘要）。论文把这套结果定位为面向实时视频问答、监控与自动驾驶等延迟敏感、算力受限场景的部署方案。

## 局限与定位

最关键的缺口是**教师依赖**：C-GRPO 的监督信号来自教师网络，学生上限受教师约束，而论文未报告教师自身的准确率与「学生—教师差距」随压缩率变化的曲线，因此无法判断 95% 压缩下的持平是蒸馏有效还是教师本身在该基准上就不高。其次，VMR 的事件切分与 clip 相关性判断依赖上游模块，切分粒度是新的超参，论文未给出其对准确率的敏感性。第三，23.9% 的延迟下降与 72% 的显存下降是相对同规模基线，但整个管线多了检索与 RL 后训练两个环节，其一次成本与在线检索开销未在摘要中说明。第四，「一帧的 token 量」这一表述模糊了具体 token 预算（未给绝对数值），跨论文比较时需谨慎。定位上，MARC 与 P029（VideoChat-Flash 的层级压缩）是两条对立路线：后者靠架构化的层级压榨视觉冗余，本文靠查询相关的检索 + RL 后训练选择性保留。
