# P150 A Compressive Memory-based Retrieval Approach for Event Argument Extraction

- 会议/来源：COLING 2025
- 方向簇：AGENT
- 链接：/2025.coling-main.85/

## 贡献

针对检索增强的事件论元抽取（EAE）的两点局限——(1) **输入长度约束**、(2) **检索器与推理模型之间的差距**——提出基于压缩记忆的检索机制（CMR）。其压缩记忆被设计为一个**动态矩阵**，可有效缓存被检索的信息并支持持续更新，从而克服输入长度限制；此外，论文先把所有候选示范**预加载**进压缩记忆，以此缓解检索器与推理模型之间的错配。

## 机制要点

两点设计值得注意。第一，用**动态矩阵**作为记忆载体，是把「检索结果」的存储从文本形式转为连续表示，从而不受单次输入长度限制，且支持在线更新——这与 P106（xRAG 把检索文档压成 embedding 直接用于生成）在思路上同源，都是让检索产物以压缩形式直接进入推理路径。第二，「预加载全部候选示范」这一做法很有意思：它把检索从「先选后看」变成「全部装进记忆、由模型在使用时选择」，从而**消除了对检索器精度的依赖**——这正是回应「检索器与推理模型存在差距」这一问题的直接手段：既然两者难以对齐，就让检索不再做硬性筛选。

## 关键结果

论文报告 CMR 在两处局限上都有改进，并在 EAE 任务上取得效果；具体基准与指标需回看正文。EAE 是结构化抽取任务（需要定位事件触发词并抽取论元角色），对精确定位要求较高，因此该任务上的成功比通用问答更能说明压缩记忆保留了定位能力。

## 局限与定位

第一，「预加载全部候选」在候选数量很大时会带来记忆容量压力：动态矩阵的尺寸是有限的，当候选示范远超容量时仍需某种选择机制，而这又把检索器的问题带回来了；论文应给出容量与候选规模的关系。第二，把检索结果转为连续表示会损失**字面信息**，而 EAE 中论元往往是具体的实体字符串，需要精确匹配；这与 P111 指出的 gist 压缩在精确召回上的弱点属于同类风险，需要专门的证据。第三，该工作面向特定任务（EAE），其设计的通用性（能否用于开放域问答、长文摘要）需要验证；任务越结构化，压缩记忆中需要保留的信息形态越明确，收益越容易实现。第四，与 P106 相比，一个面向 EAE 的候选示范、一个面向 RAG 的文档 embedding，两者都在回答「压缩表示能否直接服务下游」，本工作提供了结构化任务上的证据。定位上属于压缩记忆在特定 NLP 任务上的应用型工作。
