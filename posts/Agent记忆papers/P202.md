## 贡献

用极低的适配成本把预训练自回归 LLM 改造成**块扩散（block diffusion）语言模型**：只需约 1B token 的微调（相比 Dream 全注意力扩散 LLM 的 580B token 减少约 500×）即可保留原模型能力，并借助**层级缓存**（块级 cache + 块内 sub-block cache，即 DualCache）实现并行解码。

## 机制要点

训练侧（Figure 2）：序列按块解码，每块内做「部分掩码的 next-token prediction」；关键在于引入**互补掩码**（complementary attention mask）使每个 token 都能被训练到，从而在不牺牲 AR 训练目标的前提下获得块内双向上下文建模能力。推理侧（Figure 3）：逐块生成，已解码块被缓存为干净的 prefix 上下文（块级缓存），当前块内做并行掩码 token 细化，并复用 Fast-dLLM 的 DualCache 加速块内推理。这一「块级 + 块内」两级缓存结构正是它与本方向相关之处：缓存的对象从「线性前缀」变为「已完成的块」，与前缀缓存同源但粒度不同。

## 关键结果

Figure 1 给出吞吐—精度对比：Fast-dLLM v2（7B）吞吐为 Qwen2.5-7B-Instruct 的 **2.54×**，精度相当。Table 1 在代码生成（HumanEval、MBPP）、数学推理（GSM8K、MATH）、指令跟随（IFEval）、知识（MMLU、GPQA）等基准上按 1B 与 7B+ 两组规模对比各模型，用于支撑「适配后能力保持」的主张。项目主页（nvlabs.github.io/Fast-dLLM/v2）提供实现。

## 局限与定位

第一，「保留能力」的判据是若干基准的平均表现，而块扩散的并行解码在**需要严格逐步推理**的任务（长链数学、代码调试）上风险最高，Table 1 中这类任务的表现需要逐项核对而非只看均值。第二，互补掩码训练与块大小是关键超参，块越大并行度越高但块内细化难度越大，论文的权衡曲线（块大小—吞吐—精度）是判断实用性的核心，摘要层面未给出。第三，adapter 式改造的**通用性**待验证：不同基座模型是否都能在 ~1B token 内完成适配，取决于其预训练数据与块扩散目标的匹配度。定位上，它与 P203（FlashDLM 的 FreeCache）、P217（dKV-Cache）、P185（Sparse-dLLM）共同构成本方向「扩散 LLM 推理加速」这一新分支；其中本文侧重训练侧改造 + 层级缓存，P203 侧重免训练缓存近似，两者形成路线对照。
