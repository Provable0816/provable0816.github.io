# P069 Dialogue Without Limits: Constant-Sized KV Caches for Extended Response in LLMs

- 会议/来源：ICML 2025（主会）
- 方向簇：KV
- 链接：https://proceedings.mlr.press/v267/ghadia25a.html
- 本地全文：cache/txt/P069.txt

## 一句话贡献

提出 MorphKV：一种推理时技术，在保持**恒定大小** KV cache 的同时维持精度。它通过相关感知的自适应 token 排序来兼顾长程依赖与局部连贯性，并消除「早期 token 偏置（early-token bias）」；与启发式保留或有损压缩不同，MorphKV 用最近 token 的注意力模式引导对缓存的**轻量迭代精修**。在长回复任务上相对 SOTA 方法平均节省 52.9% 显存、准确率高出 18.2%。

## 1. 问题与第一性原理动机

长回复生成（内容创作、代码生成）与长文读取是两种不同的负载：前者的问题不是「如何阅读长输入」，而是「如何在生成长输出的同时不让缓存无限膨胀」。论文指出现有方法的两种代价——直接丢弃远期 token 会丧失长程依赖，压缩状态则以有损方式引入偏置，其中「早期 token 偏置」尤其值得注意：由于注意力机制对序列开头（sink）有系统性偏好，加速方法常被迫永久保留最初若干 token，这虽然省事，却把固定比例的预算浪费在「位置」而非「内容」上。恒定大小 cache 因此不只是省显存，更要求把预算从位置先验中转出、交给内容。

## 2. 核心洞察

洞察是：**缓存应当是持续演化的状态，而不是一次性筛选的结果**。启发式方法在某一时刻决定留谁，之后便固定；MorphKV 则用最近 token 的注意力模式持续引导缓存的轻量更新，使保留集合随生成内容漂移而调整。论文把这一过程描述为通过相关感知选择（correlation-aware selection）自适应排序 token 并迭代精修，从而在固定容量下追踪「此刻真正相关」的信息，同时靠保留局部上下文维持连贯性。这套设计的隐含前提是：**近期注意力模式足以预测未来的相关 token**——这正是它能否超越「历史注意力累计」类方法的关键。

## 3. 方法机制

(1) 维持固定容量的 KV cache；(2) 用相关感知的自适应排序决定容量如何在 token 之间分配，显式消除早期 token 的位置偏置；(3) 以最近 token 的注意力模式为信号，对缓存做轻量迭代更新（而非重算或硬淘汰）。代价是每步生成都要执行一次缓存精修，其开销需被显存与带宽节省覆盖；固定容量是一个需要按模型/任务设定的超参；迭代更新可能引入漂移，缺少稳定性分析。

## 4. 实验证据

长回复任务上，相对 SOTA 先前方法平均节省 52.9% 显存，平均准确率提升 18.2%。论文图 1/2 给出动机数据：Llama 3.1 70B 与 405B 在 batch=256 时随序列长度增长很快超出 H100 显存；即使使用 SnapKV 压缩，其内存占用仍随**回复长度**增长并最终超出高端 GPU 的 HBM。这组可视化正是「恒定大小」这一主张的动机核心。

## 5. 第一性原理再审视

第一，18.2% 的平均准确率提升幅度很大，需要看清基线构造：若对比对象主要是「为长输入设计的压缩方法」被直接套用到长回复场景，则提升部分来自场景不匹配而非方法本质优越；论文应提供与强基线（如针对生成的滑动窗口 + sink 组合）的对照。第二，恒定容量的一个未讨论风险是**信息不可逆丢失**：若某条早期信息在生成中期被淘汰，而它在生成后期成为关键（例如代码生成中的早期函数签名），固定容量下无法恢复；这与 P025 指出的「覆盖式记忆」问题同源，论文未给出这类长程依赖的专项测试（论文自己把代码生成列为核心场景，因此这一测试应当是必需的）。第三，「用近期注意力预测未来相关性」与 P038（AttentionPredictor）的假设一致，也共享同一风险：注意力漂移时预测失效。第四，每步精修的开销在长回复（数千 token）下会累积，需与显存节省一起报告。

## 6. 与相邻工作的关系

与 SnapKV/H2O（一次性筛选）相比，MorphKV 把缓存视为可迭代状态；与 P041（DMS，训练策略决定驱逐时机）相比，MorphKV 完全免训练，但缺少可学习的决策；与 P045（KVzip，查询无关压缩）相反，MorphKV 明确面向**长输出**而非多查询复用；与 P023/P025 的 agent 记忆覆写相比，本方法在模型内部维护定长状态，属于 KV 层的对应物。定位上填补了「长回复生成」这一被压缩文献相对忽视的负载。

## 7. 可迁移点与开放问题

可迁移：(a) 「把缓存当作持续演化的状态，用最新信号迭代精修」这一模式可推广到 agent 工作记忆与流式 RAG 的缓存管理；(b) 显式消除位置先验（早期 token 偏置）以释放预算给内容，是提升固定预算下有效容量的通用手段。开放问题：被淘汰的早期关键信息如何补救（例如与 P025 的回调机制结合）；迭代精修的漂移与稳定性；固定容量与任务/输出长度的关系；以及每步精修开销在超长生成下的累积效应。
