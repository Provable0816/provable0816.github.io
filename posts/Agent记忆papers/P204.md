# P204 ICaRus: Identical Cache Reuse for Efficient Multi-Model Inference

- 会议/来源：ICLR 2026（主会）
- 方向簇：KV
- 链接：https://openreview.net/forum?id=37f6be32f832caf0f7980469fb06165b
- 本地全文：cache/txt/P204.txt

## 贡献

针对**多模型协同**（agentic AI 中多个任务专精模型轮流处理同一提示）场景，提出跨模型共享同一份 KV cache：把 decoder-only Transformer 概念上拆成「逻辑编码器」（生成 KV cache）与「逻辑解码器」（从 KV 预测 token），只微调解码器、冻结编码器，于是多个专精模型可以共享完全相同的 KV，从而消除缓存爆炸、意外淘汰与重复重算。

## 机制要点

架构见 Figure 3：基座模型充当逻辑编码器，带适配器（如 LoRA）的模型充当逻辑解码器，蓝/橙两线区分「共享的编码计算」与「各自定制的解码计算」。可行性由 Figure 2 的训练损失曲线支撑：在 LLaMA-3.1-8B 上用 MetaMathQA-40k 与 Evol-Instruct-Code-80k 训练时，**ICaRus 的损失曲线与常规任务微调几乎完全重合**——这说明把学习限制在逻辑解码器不会明显损害任务适配能力。这一观察是全文的支点：它把「模型差异」重新表述为「解码器差异」，从而让编码器成为可共享资产。

## 关键结果

Table 1 给出单模型与多模型场景在显存、延迟（prefill / 每 token 解码）、访存与计算复杂度上的解析对照，用于说明共享 KV 的复杂度收益。质量侧报告数学（GSM8K、GSM-Plus）、代码（HumanEval、HumanEval+）、知识（GPQA）上的基线 vs ICaRus 对照（如 GSM8K 73.2→74.0、85.4→87.3 量级的对照，具体模型分组见原文）。系统侧（Fig. 9）在动态、偏斜的 agent 调用模式下，2 模型 0.4 QPS 时 P95 延迟降低约 **15×**、吞吐提升约 1.2×；8 模型设置下吞吐最高提升 **3.5×**，且基线在 QPS 上升后因频繁淘汰/重算而吞吐饱和，ICaRus 则能持续增长。

## 局限与定位

第一，共享 KV 的前提是模型**同源**（同一基座），异构模型（不同架构、不同分词器）无法共享——这限制了它在真实多模型生态中的适用范围，论文未讨论跨基座的近似共享。第二，只微调解码器意味着所有模型被迫接受同一份「上下文编码」，对**强依赖上下文表示差异**的任务（例如需要不同检索视角的专精模型）可能形成表达瓶颈；损失曲线重合是平均证据，任务级差异需逐项核验。第三，评测以数学/代码/知识三类的少量基准为主，缺少长上下文与多轮 agent 的端到端验证。定位上，它与 P186（子图 KV 复用）、P201（KV 二次利用）、P184（多上下文 KV）同属「KV 复用」家族：不压缩单份缓存，而通过共享/复用降低系统总缓存需求——在 agent 化多模型服务中，这类系统级思路的收益往往高于单模型压缩率的边际提升。
