# P104 Reducing Transformer Key-Value Cache Size with Cross-Layer Attention

- 方向簇：KV
- 链接：/paper_files/paper/2024/hash/9e23d020c18e4c40d81c6a0fc7a46f68-Abstract-Conference.html
- 本地全文：cache/txt/P104.txt

## 一句话贡献

提出 Cross-Layer Attention（CLA）：把 MQA 的思路再推进一步——不仅让多个 query 头共享一个 key/value 头，还让**相邻层之间共享** key/value 头，从而在几乎不损精度的前提下把 KV cache 再缩小 2×。论文通过从零训练 1B 与 3B 参数模型，证明 CLA 相对 MQA 在内存/精度权衡上取得 Pareto 改进。

## 1. 问题与第一性原理动机

自 Transformer 问世以来，减少 KV cache 最有效的两类结构手段是 MQA 与 GQA：让多个 query 头共享同一个 K/V 头。论文问的是：既然「共享」在头维度上有效，那么在**层维度**上是否同样有效？这是一个自然但此前未被系统验证的推广——如果相邻层的 K/V 表示本就高度相似（这是后续多篇工作都观察到的现象：P103 的跨层相似、P088 的层间重要 token 一致、P039 的层间索引复用），那么为每层单独维护 K/V 就存在冗余；共享后省下的是**整层的 KV 存储**，收益量与头维度共享同阶，因此有理由期待在精度代价很小的情况下再省一倍。

## 2. 核心洞察

洞察是：KV 的冗余存在于多个维度（头内、头间、层间、序列内、数值内），而 MQA/GQA 只开发了「头间」这一维；层间共享是同一原理在另一维度的应用。这一点也让 CLA 与推理期的跨层合并方法（P103 MiniCache）形成对照：**训练时共享**从结构上消除了冗余，因此不需要事后近似的合并与容错机制，精度与压缩的权衡曲线更优；代价是必须从零训练或大幅改造模型。

## 3. 方法机制

相邻层共享 K/V 头（在 MQA 的基础上再做跨层共享），查询头仍逐层独立。论文从零训练 1B 与 3B 参数模型以评估该设计的真实上限（而非在已训练模型上做近似改造）。代价是：该设计无法直接套用于已发布的开源模型，只能用于新训练的模型；跨层共享改变了层间表示的分工，可能影响需要层间差异的能力；此外共享粒度（每两层、可变间隔）是需要搜索的设计选择。

## 4. 实验证据

从零训练 1B 与 3B 模型的实验显示：CLA 可把 KV cache 再缩小 2×，而精度与未修改的 MQA 几乎相同，从而在内存/精度权衡上形成 Pareto 改进，并可能使未来模型支持更长的序列与更大的 batch。摘要未给出具体的评测基准与绝对数值。

## 5. 第一性原理再审视

第一，实验规模（1B/3B）在当今属于中小模型，跨层共享的精度代价是否随规模变化（变大后被稀释、还是被放大）未知；这类架构结论通常需要至少一个数量级的规模验证才能外推。第二，评测指标以困惑度与常规基准为主时，「几乎相同精度」需要补充长上下文任务（检索、多跳）——共享 K/V 很可能对需要跨层协作的长距离能力影响更大。第三，从零训练意味着与推理期压缩方法（P083、P090、P103 等）不构成直接竞争，而是路线选择：如果目标是让**已发布模型**更省显存，CLA 不可用；如果目标是设计下一代模型，CLA 是零成本的。第四，与 GQA 正交可叠加（论文应在正文中给出 CLA + GQA 的组合结果），读者应注意区分「相对 MQA 再省 2×」这一口径。第五，跨层共享的最优间隔（每 2 层、每 3 层）与模型深度相关，摘要未给出该敏感性。

## 6. 与相邻工作的关系

与 MQA/GQA（被推广的基线）构成直接的继承关系；与 P103（MiniCache）是同一洞察的两条路线（训练时共享 vs 推理时合并）；与 P089（Palu 隐藏维度低秩）在「开发 KV 冗余的新维度」这一方法论上一致；与 P088、P039 的经验观察（层间相似性）互为佐证——CLA 的价值在于把这些观察**前移到架构设计**而不是事后利用；与 P063（SkipV1Former 跨层复用第一层 Value 头）在思路上高度接近，二者都以「跨层复用 K/V」为核心机制，可作为同期对照。

## 7. 可迁移点与开放问题

可迁移：(a) 「冗余存在于多个维度，结构共享优于事后压缩」这一判断适用于任何需要在架构层面节省资源的场景（MoE 专家、多模态编码器、状态空间模型）；(b) 从零训练验证架构假设（而非在旧模型上近似改造）是获得可信度量的正确做法，即使成本更高。开放问题：跨层共享在更大规模上的精度代价；长上下文任务上的影响；最优共享间隔与深度/宽度的关系；与 GQA/MLA 的组合；以及是否可通过少量继续训练把已发布模型改造成 CLA。
