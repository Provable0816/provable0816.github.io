# P089 Palu: KV-Cache Compression with Low-Rank Projection

- 会议/来源：ICLR 2025（主会）
- 方向簇：KV
- 链接：/paper_files/paper/2025/hash/7da6e0e00702c60607a6ae05c802ef85-Abstract-Conference.html
- 本地全文：cache/txt/P089.txt

## 一句话贡献

指出既有事后压缩方法（选 token 或降比特）都**无法利用 KV 张量在隐藏维度上的冗余**，据此提出 Palu：把线性层分解为低秩矩阵，缓存压缩后的中间状态，并在运行时重建完整的 key/value；为提升精度、压缩率与效率，进一步引入中等粒度低秩分解、高效的秩搜索算法、低秩感知的量化兼容增强，以及带算子融合的优化 GPU kernel。50% 压缩下保持强精度并在 RoPE 注意力模块上取得最高 1.89× 加速；与量化结合可达 2.91× 加速且相对纯量化方法 perplexity 最多低 1.19。

## 1. 问题与第一性原理动机

KV 压缩此前集中在两个方向：**选哪些 token**（沿序列维度裁剪）与**用多少比特**（沿数值精度裁剪）。论文指出还有第三个未被开发的维度——**隐藏维度**。这是结构性的遗漏：KV 张量的形状是（序列 × 头 × 维度），而低秩现象在维度方向上的证据早已存在（P035 也以「KV 在隐藏维度呈低秩」为出发点，并指出 RoPE 会抬高效秩）。若只在序列与精度两个方向压缩，就等于放弃了三分之一的空间，并且这两种压缩方式彼此难以互补（选 token 会破坏连续性，量化在低比特下误差急剧上升）。

## 2. 核心洞察

洞察是：既然 KV 由线性层投影生成，就可以**从生成机制入手**——把 $W_K$、$W_V$ 分解成低秩形式，直接缓存中间的低维状态，用时再重建。这比事后对已生成的 KV 做低秩拟合更有原则，因为分解点位于计算图中，可以端到端选择秩。第二层洞察在兼容性：低秩与量化本可叠加，但简单叠加会让误差互相放大；Palu 通过「低秩感知」的设计让两者兼容，于是量化带来的额外精度损失很小，同时省下更多显存——这一点对实际部署尤其重要，因为单靠任一维度难以达到目标预算。

## 3. 方法机制

(1) 把相关线性层做中等粒度的低秩分解，缓存压缩后的中间态；(2) 用高效的秩搜索算法为各层/组件选择秩；(3) 采用低秩感知的量化兼容设计；(4) 用算子融合的 GPU kernel 把重建与注意力计算合并执行，避免重建开销抵消压缩收益。代价是：需要离线分解与秩搜索（相当于一次模型改造）；运行时重建带来计算，收益强依赖 kernel 优化；RoPE 会抬高效秩（P035 的发现），因此低秩分解必须先处理位置编码的影响。

## 4. 实验证据

50% KV 压缩下保持强精度，RoPE 注意力模块最高 1.89× 加速；与量化结合后最高 2.91× 加速、比纯量化方法省更多显存，且 perplexity 最多低 1.19（即精度更好），额外精度损失小到可忽略。代码开源。

## 5. 第一性原理再审视

第一，「50% 压缩」在当下文献中属于温和水平（相比 P045 的 394×、P077 的 400×），Palu 的定位更适合被理解为**高保真压缩**而非极限压缩；把它的压缩比与激进 token 淘汰方法直接比较会得出错误结论。第二，1.89× 与 2.91× 是注意力模块级别的加速，端到端加速会更小（注意力只占解码时间的一部分），读者应区分模块与整体口径。第三，低秩分解的有效性受 RoPE 影响（P035 明确指出 RoPE 放大 key 的方差、抬高效秩），因此实际可达的秩可能比无位置编码时高——论文的「中等粒度」设计估计正是对此的折中，但需要给出秩与精度的曲线来支撑。第四，perplexity 是语言建模指标，与下游长文任务能力并不总一致；「perplexity 更低」不应被直接读作「长上下文能力更强」。第五，离线分解与秩搜索意味着换模型需要重做，通用性弱于免训练方法。

## 6. 与相邻工作的关系

与 P035（SALS）最接近：都以隐藏维度低秩为出发点，SALS 在隐空间做稀疏选择并只重建被选 token，Palu 从线性层分解入手并重建全部 KV——前者把低秩当作检索空间、后者当作存储格式；与量化路线（P067、P070、P072）在「精度维」上正交且明确追求兼容；与 token 淘汰路线（P083、P087）在「序列维」上正交；与 P062（LRQK 用低秩做代理打分但保留全精度计算）相比，Palu 用低秩**替换**了存储，属于有损路线。定位上补齐了 KV 压缩的三个正交维度中的最后一个。

## 7. 可迁移点与开放问题

可迁移：(a) 「从生成机制出发做压缩（分解线性层）而非事后拟合」这一思路可推广到激活压缩与权重压缩；(b) 「两种正交压缩手段叠加时需专门设计兼容性，否则误差互相放大」是一条重要的工程经验，可应用到低秩 + 量化、稀疏 + 量化的组合。开放问题：RoPE 下可达的最优秩；秩搜索的成本与跨模型迁移；模块级与端到端加速的差距；与 token 淘汰方法的三维联合设计；以及在长文精确检索任务上的表现。
