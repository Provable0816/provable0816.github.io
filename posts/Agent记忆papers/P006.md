# P006 FreqKV: Key-Value Compression in Frequency Domain for Context Window Extension

## 一句话贡献

发现 KV 状态的能量高度集中在频域低频分量，据此提出 FreqKV：在频域迭代压缩不断增长的 KV 缓存（无额外参数、架构无关），仅需 8K 长度的极少训练即可把 LLaMA-2-7B 的上下文扩展到 256K 并保持稳定困惑度，在 LongBench、RULER、Needle-in-a-Haystack 上普遍优于现有 KV 压缩方法。

## 1. 问题与第一性原理动机

上下文窗口由预训练位置编码决定，超出即失效；而用满自注意力做窗口扩展的代价是二次复杂度。已有压缩路线各有结构性缺陷：eviction（SnapKV、PyramidKV、FastKV、LaCache）按注意力分数丢弃 token，**被丢弃 token 携带的信息不可恢复**，在超出预训练长度外推时性能骤降；token merging（CaM、KVMerger、D2O）保留更多信息但未经微调时效果不佳；LoCoCo、Activation Beacon 引入额外模块并需要训练，参数与显存开销随之上升。真正的问题是：是否存在一种**不丢弃信息、也不新增参数**的压缩形式？频域视角给出了一条路径——如果上下文信息在低频段高度集中，那么高频分量的截断就是低损失压缩，而非信息删除的赌博。

## 2. 核心洞察

KV 状态在频域呈现强能量集中：低频分量承载主要上下文信息，高频部分大量冗余。因此可以把「保留哪些 token」的问题改写为「保留哪些频率分量」的问题——后者的粒度是全局的、可微调的（保留比例即压缩率），并且天然对时间轴对齐，不依赖任何注意力打分。论文进一步指出实现细节：**key 状态在应用 RoPE 之前压缩并缓存**，这样位置信息不会被频率截断破坏（压缩后仍能在解码时正确注入位置）。这一洞察意味着上下文外推能力与注意力稀疏性可以被解耦：即使注意力不稀疏（需要读全上下文），缓存依然可以压缩。

## 3. 方法机制

FreqKV 迭代地在频域压缩增长中的 KV 缓存：对缓存做变换（DCT）、保留低频分量、逆变换回时间域，随后继续接纳新 token 并重复该过程（组件数量见附录 A）。方法无额外参数、与架构无关，代价是需要一个极小的适配训练：用 LLaMA-2-7B/13B 在 RedPajama 上以 8K 训练长度训练（论文亦称 "minimal training"），并把 LLaMA-2-chat-7b 从 4K 扩到 8K、LLaMA-3-instruct-8b 从 8K 扩到 16K 用于理解类评测。主要超参是保留频率分量数、保留比例与 sink 大小（附录 F 给出消融）。

## 4. 实验证据

困惑度（Table 2，PG-19，滑动窗口 256）：7B/训练 8192 时 Full FT 为 7.55/7.21/6.98（评测长 2048/4096/8192），LongLoRA 7.70/7.35/7.14，LoCoCo 8.15/8.08/7.27，FreqKV 7.45/7.12/7.04，并可外推至 16384/32768 仍为 7.02/7.02；训练长度 32768 时，LongLoRA 8.29/7.83/7.54/7.35/7.22 而 FreqKV 7.47/7.14/7.04/7.00/6.98。13B 上 FreqKV 为 6.82/6.52/6.44/6.42/6.41，优于 LongLoRA 的 7.03/6.73/6.58。值得注意的是 Full FT 与 LoCoCo 在 16K 训练长度上 OOM，而 FreqKV 可行。

理解任务：LongBench 上 FreqKV 对 LLaMA-2-chat 与 LLaMA-3-instruct 多数类别提升，对比对象包括 eviction（GemFilter、SnapKV、PyramidKV、LaCache、FastKV）、merging（CaM、KVMerger、D2O）与通道压缩（ThinK）（Table 3）；RULER 上一致优于基线（Table 4）；另有 Needle-in-a-Haystack 与 LongGenBench 结果。

证据缺口：(a) 核心证据是困惑度，而 PPL 对长程精确检索与多跳推理不敏感——一个只保住低频/全局语义的缓存可以在 PPL 上表现良好，却在需要逐字回忆的任务上失败，论文未把「保真型任务」单列评估；(b) 频域压缩的均匀性假设（各段 KV 用同一保留比例）没有做变体对照（例如对长文档的位置分段自适应）；(c) 「无参数」成立，但并非完全免训练，8K 适配训练的必要性与其数据依赖性未充分消融。

## 5. 第一性原理再审视

该方法的有效性等价于一个可检验的信息假设：KV 序列在频域的能量谱随时间轴衰减，且决策所需的判别信息主要落在低频。这在语义聚合任务（摘要、主题理解）上合理，因为低频分量对应对时间轴平滑的成分；但对**稀疏且高频**的信息（唯一标识符、人名、精确数字、代码变量名）恰恰相反，它们对应时间域上的尖峰，是频域中的宽带分量，截断高频会直接删除它们。因此可以预测：FreqKV 在「大海捞针」类逐字检索与长代码依赖任务上会明显弱于 eviction 方法（后者至少能按注意力把针保留下来）。论文报告的 NIAH 结果需要按此预测审读。第二个隐含假设是频域压缩与 RoPE 的可交换性，论文通过在 RoPE 之前压缩来规避（这是该方法能在扩展窗口时保持稳定的关键工程选择，也说明并非任意频域压缩都可行）。第三，PPL 的单调改善（7.45→7.02）与压缩率的耦合没有做「等压缩率下与 eviction 的对照」，因此无法排除「更少 token 反而降低噪声」的解释。

## 6. 与相邻工作的关系

与 SnapKV/PyramidKV/FastKV/LaCache 属 eviction 谱系（差异：不删除 token，而是全局截断频率）；与 CaM/KVMerger/D2O 属 merging 谱系（差异：不引入相似度合并，改在频域线性变换）；与 LoCoCo/Activation Beacon 属「加模块+训练」谱系（差异：无新增参数，仅需极少训练）；与位置编码外推方法（PI、LongRoPE）互补——前者解决位置可达性，FreqKV 解决缓存可容纳性。

## 7. 可迁移点与开放问题

可迁移之处：把「保留哪些 token」的离散选择问题转成「保留哪些频率分量」的连续截断问题，使压缩率成为可控标量，并可与位置编码解耦（压缩先于 RoPE）；这一变换视角同样可用于视频/多帧 KV（时间轴频域）、多轮 agent 记忆（对话时间轴的低频=长期主题，高频=具体事实）。

开放问题：能否构造自适应频谱分配，让「低频保语义、高频保指针」两类信息按任务动态分配比特；能否给出频域截断导致的检索误差上界；在需要逐字保真的场景下，频域压缩与 eviction/混合模式哪个更优，尚无对照。
