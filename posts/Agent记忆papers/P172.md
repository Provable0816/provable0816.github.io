# P172 Leveraging Attention to Effectively Compress Prompts for Long-Context LLMs（AttnComp）

- 方向簇：CTX

## 一句话贡献

用模型自身的注意力而非信息熵来决定保留哪些 token：以 query 对 context 的因果 cross-attention 作为重要性度量（AttnComp），再用图算法把 token 聚成「语义单元」以消除逐 token 独立决策带来的语义破坏。

## 1. 问题与第一性原理动机

提示压缩的历史基线是「按信息熵/perplexity 保留 token」，其隐含假设是**信息量与有用性同构**。AttnComp 指出这个假设在长上下文 RAG 里失效：一篇文章里 perplexity 最高的往往是罕见词与专名，而它们未必是回答当前问题所需；反过来，平淡的连接词可能承载推理必需的逻辑关系。更根本的缺陷是**决策的单位错了**：token 是分词器的产物，不是语义单位，逐 token 独立打分再删除，会切断「短语—从句—句」内部依赖，压缩率越高破坏越重。因此要同时修正两件事：度量（用什么打分）与粒度（在哪里切）。

## 2. 核心洞察

论文的核心判断是「压缩的度量应当来自模型读这段上下文的**实际路径**」。做法是用因果 cross-attention——让 query 去 attend 上下文——把「模型在回答这个问题时会把注意力放在哪里」直接变成 token 重要性（Figure 1 框架）。这比外部打分器多了一层因果性：注意力反映的是模型下一步会用的信息，而非语言模型对文本的惊讶度。第二个洞察是**语义单元**：把注意力相似/相关的 token 用图算法聚成簇，以簇为单位做保留/删除，使删除动作作用在语义完整的单元上。

## 3. 方法机制

三段式：(1) 从指定层的注意力头中抽取 query→context 的 cross-attention 权重，作为每个 token 的重要性；(2) 构建 token 图（节点为 token，边由语义/注意力关联给出），用图算法做聚类得到语义单元，单元内共享保留决策；(3) 在 token 预算约束下按单元重要性滤除，产出压缩提示。论文还引入 coarse-to-fine 流程（先用粗粒度方法压到中间长度，再做 token 级压缩），以及对比「使用全部注意力头 vs 仅使用检索头（retrieval heads）」的设计选择。代价：需要一次前向以获取注意力（不是免模型方法），且注意力统计的可靠性与所选取层/头强相关。

## 4. 实验证据

任务分为合成 RAG 场景与通用长上下文。RAG 侧用 Natural Questions 的检索增强设置（每问 20 篇文档、其中 1 篇含答案），通用侧用 LongBench 的多任务子集。Table 1 报告 NQ 上不同压缩方法在「答案文档位于第 1/5/10/15/20 位」以及**重排序（reorder）**条件下的表现——这一设计直接针对 lost-in-the-middle：如果压缩只是保留「位置靠前」的内容，重排序实验会暴露它。Table 3 报告 LongBench 上以 2000 token 为目标的压缩结果。消融（Table 2）给出四个变体：去掉语义单元（退化为 token 级）、用 spaCy 短语单元、用全部注意力头（而非检索头）、用 PPL 度量；论文结论是去掉任一组件都会掉分，其中「语义单元」与「用注意力而非 PPL」的贡献被明确量化。Figure 2 给出不同 token 级度量在不同过滤率下的曲线。

**证据缺口**：(a) 论文没有给出**压缩率—精度曲线的完整形状**，只在若干固定压缩率上比较，读者难以判断曲线是否在高压缩率处陡降；(b) 「检索头」的选择依据未系统化（哪些层、如何识别、是否跨模型稳定）；(c) 注意力作为重要性度量存在已知的**注意力 ≠ 因果贡献**问题（可通过 attention rollout / 扰动对照检验），论文未提供这类对照，使「注意力即重要性」仍是未证假设。

## 5. 第一性原理再审视

该方法的成立依赖两个假设，二者都比表面上更强：其一，**当前的 query 已能代表最终需求**——但在多跳、澄清式对话中，真正的问题往往在压缩之后才成形，此时以当前 query 打分必然漏掉稍后才被用到的证据；其二，**注意力权重是因果重要性的无偏估计**——而注意力饱和、attention sink、以及多头上冗余的注意力都会让权重分布失真。第三个更微妙的问题是「语义单元」的定义循环：聚类依赖注意力，注意力又依赖当前 query，若 query 本身偏置，聚类会把偏置固化成结构。从信息论看，压缩是固定预算下的率失真问题；论文选择的是「按模型使用频率分配码率」，这与按熵编码（按内容统计分配码率）是两种不同的最优性准则，只有在「使用频率 ≈ 任务相关性」时才一致，而这恰恰是 RAG 里最不稳定的假设。

## 6. 与相邻工作的关系

与 LLMLingua 系列等基于 PPL/熵的**内容统计派**直接对立：AttnComp 把打分器从外部语言模型换成任务模型自身的注意力。与 Gisting、ICAE、AutoCompressor 等**用连续向量替代 token**的路线不同，它仍是硬删除（离散选择），因此保留了可读性与可解释性。与 H2O/SnapKV 等 KV cache 侧的重要性打分是同源思想在不同层面的应用（提示侧 vs 缓存侧），两者的打分器可以互通。

## 7. 可迁移点与开放问题

可迁移：(a) 把「重要性度量应从任务模型的前向路径中读取」这一原则推广到记忆库淘汰、多模态 token 剪枝；(b) 语义单元作为压缩的最小单位，是任何「删除会破坏结构」的压缩场景的通用技巧（代码、表格、多跳文档）。开放问题：当查询在过程中演化时如何做**惰性压缩**；注意力作为重要性度量的因果验伪；检索头的跨模型可迁移性；以及与 KV 侧压缩的联合优化能否共享同一套重要性估计。
