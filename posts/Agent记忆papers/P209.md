# P209 TokenSeek: Memory Efficient Fine Tuning via Instance-Aware Token Ditching

- 会议/来源：ICLR 2026（主会）
- 方向簇：ARCH
- 链接：https://openreview.net/forum?id=e6a11b618402617342f38f5b49430937

## 贡献

针对微调阶段的显存瓶颈（激活占主导）提出 TokenSeek：用**实例级**的 token 选择性丢弃替代以往对全批次统一套用的数据无关策略——依据上下文与梯度信息定位每个样本中真正承载监督信号的 token，只对它们保留完整计算，从而在保持甚至提升性能的同时大幅削减训练显存（Llama3.2 1B 上从基线降到 2.8 GB，即原显存的 14.8%）。

## 机制要点

动机来自 Figure 1(a) 的显存分解：不同 batch size 下 activation 始终是训练显存的主要组成，因此优化激活是最高杠杆的方向。Figure 2 对比了 TokenSeek 与 TokenTune 框架：前者做**实例感知的 token seeking**（结合上下文信息与梯度信息，见式 5 与 §3.2.1），后者只做随机 token 选择；随后是高效的 token ditching（§3.2.2），在注意力层按式 9–10 把选定 token（$h_t$）与未选定 token（$\bar h_t$）分开计算注意力 $h_t = \mathrm{softmax}(Q_t[K_{\bar t},K_t]^\top/\sqrt d)$，从而在保持对未选 token 可见的同时避免对它们做全部反向传播。Figure 4 给出单个训练实例的可视化：上下文信息选出的 top 50% token 与梯度信息选出的 top 50% token 分别以红/蓝标注，并给出末层平均注意力图与倒数第二层激活的累积梯度图——这是「为什么这样选有效」的直接机制证据。

## 关键结果

Table 1 在 ARC（25-shot）、MMLU（5-shot）、HellaSwag（10-shot）、TruthfulQA（0-shot）、WinoGrande（0-shot）上比较各方法并与基线对照，同时报告平均与最大显存；Figure 3 在 Llama3.2 1B 的 QLoRA 设置下给出显存—性能的三线对比（最大/最小/中位）。一个可解释性发现是：梯度式选择会**刻意避开早期的模板/指令性短语**，把注意力留给承载内容的 response 主体——这说明梯度优先级与真实监督信息对齐，也为「模板 token 是训练中的冗余」提供了实证。论文另在 Qwen2.5 0.5B 等更小模型上验证了通用性。

## 局限与定位

第一，它优化的是**训练显存**而非推理记忆，与本方向主线（推理期 KV/上下文压缩）目标不同，属于相邻簇；论文本身也把 activation 优化作为迁移自既有 memory-efficient training 的路线。第二，实例级选择需要在训练前或训练中计算梯度信息，其代价与稳定性（尤其在小 batch 或梯度噪声大时）未被完整讨论。第三，丢弃 token 意味着部分监督信号被弱化，这在**长链推理**类样本上风险最高，而评测以多选题为主。定位上，它的价值在于提供了「按梯度定位信息密度」这一可迁移工具：同样的判据可用来决定推理期保留哪些 token（与 P198 的可学习保留、P003 的 retention gate 形成「梯度式 / 学习式 / 启发式」三足对照）。
