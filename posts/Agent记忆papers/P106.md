# P106 xRAG: Extreme Context Compression for Retrieval-augmented Generation with One Token

## 一句话贡献

重新定义稠密检索中文档 embedding 的用途：不再只用于「检索」，而是把它当作**检索模态的特征**，通过模态融合（modality fusion）直接注入语言模型的表示空间，从而彻底去掉文档的文本形态，实现「一个 token」的极端压缩。xRAG 中唯一可训练的部分是模态桥接模块，检索器与语言模型都保持冻结，因此可以复用离线构建的文档 embedding 并保留即插即用的检索增强特性；在六个知识密集型任务上平均提升超过 10%，并在部分基准上追平未压缩模型，同时把整体 FLOPs 降低 3.53×。

## 1. 问题与第一性原理动机

RAG 的成本结构里存在一处明显的重复：检索阶段已经用稠密编码器把文档压成了 embedding，随后却把**原文**再喂给语言模型，等于把同一份信息编码了两次（一次进入检索空间、一次进入语言空间）。这种做法之所以长期存在，是因为 embedding 被认为「只够做相似度匹配，不足以支撑生成」。xRAG 的问题设定正是挑战这一假设：如果 embedding 已含足够信息用于匹配，它是否也含足够信息用于生成？若是，则可以让 embedding 直接进入生成路径，从而消除文本与嵌入之间的信息重复。

## 2. 核心洞察

洞察是**跨模态融合视角**：把稠密检索向量视为「检索模态」的输入，语言模型视为「文本模态」的处理器，两者之间需要一个可学习的桥接。这与多模态 LLM 中图像 token 与文本对齐的问题同构，因此可以直接借用其思路（投影 + 对齐训练）。第二层洞察在工程上更关键：既然检索器与 LLM 都冻结、只有桥接可训练，那么**已有的大规模离线文档索引无需重建**，这使方法具备即插即用的现实可行性——很多压缩方案失败并非因为效果差，而是因为要求重建索引或重训模型。这与 P020（Cartridges 需要为每篇语料训练一次）形成鲜明对比。

## 3. 方法机制

(1) 用现成的稠密检索器获得文档 embedding；(2) 通过模态桥接把 embedding 映射到 LLM 的表示空间（相当于一个「检索模态 token」）；(3) 只在桥接模块上做对齐训练，检索器与 LLM 冻结。代价是：压缩比极高意味着信息瓶颈极窄（每个文档 1 个 token 量级），对需要逐字细节的任务风险大；桥接模块的泛化性（换检索器/换 LLM/换领域是否需要重训）决定实际可用性；高压缩比下多文档场景的区分度衰减值得关注。

## 4. 实验证据

在六个知识密集型任务上平均提升超过 10%，优于此前的上下文压缩方法；兼容从稠密 7B 到 8×7B MoE 的多种骨干；在部分基准上追平未压缩模型，同时整体 FLOPs 降低 3.53×。

## 5. 第一性原理再审视

第一，标题中的「One Token」是理解该工作的关键口径：一个 token 的表示维度与文本 token 相同量级，因此压缩比可与其原文档长度之比达到极高数量级；但这也意味着**该 token 必须承担文档的全部可检索信息**，其上限受表示维度与检索器编码能力的共同约束。哪些任务能承受这一瓶颈、哪些不能，是判断适用性的核心问题——论文以知识密集型 QA 为主，这类任务的答案通常可由少量事实支撑；对于需要引用原文、比较措辞或精确数值的任务，1-token 压缩的风险很高。第二，「平均提升 10%」需要看清基线：若基线是其它压缩方法而非未压缩 RAG，则提升部分来自压缩方法的改进；若与未压缩模型「追平」，则说明压缩本身的损失被桥接训练补偿。第三，冻结检索器意味着 embedding 的质量是上限；若检索器在领域外表现差，xRAG 无法弥补。第四，FLOPs 降低 3.53× 是端到端口径（含检索与生成），这一点比只报 KV 压缩比更有意义，值得同类工作效仿。第五，高压缩比下的**多文档区分**问题（多个文档各压成一个 token，模型能否分辨哪个文档说了什么）在摘要中未涉及。

## 6. 与相邻工作的关系

与 P020（Cartridges，把语料离线训成 KV）都追求「用离线算力换在线成本」，但 Cartridges 需要按语料训练且保留 KV 结构，xRAG 用已存在的检索 embedding 且只需训练一个桥接；与 P019（COMI 的软 token 压缩）、P085（Activation Beacon）相比，xRAG 的压缩比更极端且在检索增强框架内；与 P099（HippoRAG）、P024（REMem）等图式记忆相比，xRAG 不改变记忆组织方式，只改变「文档如何进入模型」这一环节；与多模态 LLM 的视觉 token 压缩（P110、P028）在方法上同源——都是把一种模态的稠密表示注入语言模型。

## 7. 可迁移点与开放问题

可迁移：(a) 「已有一份压缩表示时，不要重新编码原始对象」是一条可产生巨大收益的工程判断，适用于所有「检索 + 生成」的两段式流水线；(b) 借用多模态融合的思路处理检索—生成之间的模态鸿沟，是一个有通用性的类比。开放问题：1-token 瓶颈下的任务适用边界；桥接模块跨检索器/跨 LLM/跨领域的迁移；多文档区分度；需要逐字证据的任务上的表现；以及压缩表示是否可组合（多个文档的 embedding 能否与查询准确交互）。
