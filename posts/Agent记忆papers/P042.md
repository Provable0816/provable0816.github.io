# P042 KeyDiff: Key Similarity-Based KV Cache Eviction for Long-Context LLM Inference in Resource-Constrained Environments

- 方向簇：KV

## 一句话贡献

发现「几何上更独特的 key 往往获得更高注意力」，据此提出纯基于 key 相似度、**完全不依赖注意力分数**的免训练淘汰方法 KEYDIFF，并配合块式（block-wise）推理使显存全程受控；在 LongBench 上以 8K cache 预算（约 23% 压缩）相对不淘汰基线仅有 ≤0.04% 的精度损失，端到端延迟最多降低 30%。

## 1. 问题与第一性原理动机

边缘设备上的 KV 淘汰有两个被现有工作忽视的结构性约束。第一，主流方法用注意力分数衡量 token 重要性，但注意力分数在真实推理栈里往往不可得——FlashAttention 等高效 kernel 不吐出注意力矩阵，因此「依赖注意力打分」的淘汰方法在实践中会**与最需要它的高效实现互斥**。第二，更根本的是内存约束的时序问题：多数方法先处理完整条 prompt 再淘汰，意味着在 prefill 中间态cache 会短暂膨胀到完整规模——对显存受限设备而言，这恰恰是在最危险的时刻突破内存上限。因此问题的正确提法不是「如何更准地打分」，而是「如何在整条推理链路的每一刻都维持内存上界，且不依赖注意力矩阵」。

## 2. 核心洞察

论文的核心观察是：key 在向量空间中的**几何独特性**与它的注意力分数正相关——若某个 key 与其它 key 的平均成对余弦相似度低，它更容易得到高注意力。直觉上这是合理的：如果所有 key 都指向同一方向，query 无法区分它们；一个偏离主方向的 key 才携带可区分的信息。论文用 Lemma 3.1 与 Theorem 3.2 把 key 的多样性与注意力分数联系起来，为「只用 key 相似度做淘汰」提供理论依据。这条洞察的价值在于它**把打分所需的输入从注意力矩阵降级为 key 本身**，从而同时解决「kernel 兼容性」与「可提前计算」两个问题。

## 3. 方法机制

(1) 推理时把输入 prompt 切成块依次处理，每处理完一块就按淘汰策略裁剪 cache，使显存占用在整个 prefill 与解码过程中都有界（这是与「先全量 prefill 再淘汰」范式的关键差别）；(2) 淘汰分数仅由 key 的平均成对相似度（key diversity）导出，保留几何上更独特的 key 及其对应 value，论文也讨论了用 key 平均值等更廉价的近似变体（Table 14/15）；(3) 因为不读取注意力矩阵，可与优化过的注意力实现共存。方法整体免训练，无校准数据需求。代价是：分数仅反映 key 几何结构，完全不含查询信息，在「几何普通但语义关键」的 token（例如高度重复文本中的某一处关键数字）上存在原理性盲区。

## 4. 实验证据

LongBench：Llama 3.1-8B 与 Llama 3.2-3B 在 8K cache 预算（约 23% 压缩）下相对不淘汰基线精度差 ≤0.04%；6K 预算（约 33% 压缩）下差 ≤1.5%，论文称在此设定下既优于其它淘汰方法，也优于其它方法在该资源约束下的表现。数学推理：DeepSeek-R1-Distill-Llama-8B 在 Math500 上接近基线。效率：相比其它 token 淘汰方法端到端延迟最多降低 30%。另在 Needle-In-A-Haystack 上优于竞争淘汰策略，并讨论 block size $B=128$ 的设定。Qwen 家族亦在评测范围内。

## 5. 第一性原理再审视

三点需要限定。第一，23% 的压缩比在当下 KV 压缩文献里属于**保守**水平（同类工作动辄宣称 4×–13×），因此「≤0.04% 精度损失」这一亮眼数字是在相对宽松的压缩条件下取得的；真正的卖点是「严格内存约束下仍可运行」与「不依赖注意力」，而非压缩率本身——读者若把它与其他方法的高压缩比结果直接比较会得出错误结论。第二，理论部分（Lemma 3.1 与 Theorem 3.2）刻画的是特定构造下的关系（围绕 need-in-haystack 式场景），把「key 多样性与注意力正相关」上升为普适结论需要更强的条件；论文也未给出该相关性在长尾任务上的分布。第三，方法对查询完全不可知，因此在「同一批 key 对不同 query 应有不同重要性」的任务上必然次优；块式处理还引入了块边界效应（某 token 在块内看似冗余，跨块才显示重要性），而块大小是需调的超参。第四，「延迟降低 30%」是与其它淘汰方法比而非与不淘汰基线比，且强依赖资源受限的设备特性，跨硬件可移植性未知。

## 6. 与相邻工作的关系

与 H2O、SnapKV、Ada-KV（P037）等注意力驱动方法相比，KEYDIFF 的对立面是「不打分而是看 key 几何」，因而可与 FlashAttention 之类的融合 kernel 共存——这是它最实质的差异化；与 CriticalKV 把 value 范数纳入打分相比，本文连 value 与注意力都不需要；与 P040（AsymKV）同样关注 key 的局部结构，但 AsymKV 用同质性做合并、KEYDIFF 用多样性做淘汰，二者对 key 结构的利用方向相反。定位上属于面向边缘部署的资源受限方案，而非追求极限压缩比的研究型方法。

## 7. 可迁移点与开放问题

可迁移：(a) 「指标与被优化系统解耦」这一设计原则——把打分输入从注意力矩阵换成 key，换来的是与高效 kernel 的兼容性，这类「为了可部署性主动弱化信息」的取舍在系统工程中普遍适用；(b) 块式处理使内存上界在整个生命周期内成立，这一视角可推广到任何需要严格资源约束的流式推理与 agent 记忆写入。开放问题：key 多样性与注意力相关性的适用边界；能否用极轻量的查询侧信号补上「查询不可知」的盲区而仍保持 kernel 兼容；块边界效应的缓解方式；以及把压缩比推到 4× 以上时该方法是否出现断崖式退化。
