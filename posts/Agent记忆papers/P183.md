# P183 SPARK: Query-Aware Unstructured Sparsity with Recoverable KV Cache Channel Pruning

- 会议/来源：AAAI 2026（主会）
- 方向簇：KV
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40466
- 本地全文：cache/txt/P183.txt

## 一句话贡献

把 KV 压缩的坐标轴从「时间（token）」转到「**通道（feature dimension）**」：观察到通道显著性随查询与位置剧烈变化（某些通道对某个查询近乎零信息，另一些则骤增），于是提出免训练、即插即用的**非结构化通道剪枝**，并在计算注意力分数时**动态恢复**被剪掉的条目（recoverable pruning），从而不牺牲精度的同时获得稀疏收益。

## 1. 问题与第一性原理动机

KV 压缩的三条坐标轴分别是时间（减少 token）、空间（层/头的预算分配）与通道（减少特征维度）。前两条已被大量研究，第三条被系统性忽视，原因是：结构化通道剪枝会把「某通道对所有人都无用」当作前提，而实际上通道重要性是**查询条件化**的。论文 Figure 1 用四格示意对比：全 KV、token 淘汰、结构化通道剪枝与本方法；Figure 2 在 LLaMA3.1-8B 第 18 层第 0 头给出 QK 点积分数的实测分布，显示通道重要性的非结构化、token 依赖模式。这个观察直接否定了「一次性、全局」的通道剪枝，同时给出了新自由度：既然重要性随查询变，就不该永久删，而应在使用时恢复。

## 2. 核心洞察

压缩的目的不是「少存」，而是「少算且不算错」。通道剪枝的收益来自**QK 点积的稀疏化**——被剪通道不参与乘法。因此正确的做法是：在 prefill 期按通道显著性给 key 打上非结构化剪枝掩码（省内存与带宽），但在真正计算注意力分数时，把被剪条目按需**恢复**（省算力但不丢信息）。这把「有损存储」与「无损打分」分开，是全文最有价值的一个解耦。

## 3. 方法机制

(1) 在 prefill 阶段计算通道级显著性分数，对 key 缓存施加非结构化剪枝（掩码记作 $\lambda$，对 key 与 value 分别可设）；(2) 解码阶段用恢复操作 $F$ 在注意力打分时重建被剪通道的贡献（Figure 3 给出整体示意）；(3) 该模块定位为即插即用，可与思考链/推理模型共存（论文用 SPARK($\lambda$) 与 THINK($\lambda$) 两种记法区分配置）。代价：恢复机制带来额外计算与实现复杂度，只有当「剪枝节省的带宽」大于「恢复带来的开销」时才有净收益；显著性估计依赖查询，需要按批/按步处理；非结构化掩码对硬件不友好（需要相应 kernel 优化）。

## 4. 实验证据

主模型为 LLaMA-3-8B-Instruct，基准为 LongBench（Table 1 给出不同通道剪枝率 $\lambda$ 下的结果，并与 Full 及各基线对照）与 RULER（Table 2 在 20% KV 预算、16K 输入下评测；附录 F.2/F.3 补充不同预算与输入长度）。论文的定位是「训练-free、plug-and-play」，因此关键证据是**在相同预算下相对训练-free 基线的质量保持**，以及通道剪枝与 token 级压缩叠加后的增益。

**证据缺口**：(a) Table 1/2 覆盖了固定 $\lambda$，但缺少「通道轴与时间轴的最优分配」分析——在总预算固定时，把预算花在通道还是 token 上更划算，是读者最需要的问题；(b) 恢复机制的实际开销未在摘要层面量化，导致「净收益」需要读者到附录核对；(c) 非结构化稀疏在 GPU 上通常难以转化为真实加速，论文需要给出端到端吞吐而非仅精度；(d) 检索敏感任务（逐字精确）上通道剪枝的误差可能集中在少数高频通道上，需逐任务核验。

## 5. 第一性原理再审视

SPARK 的价值在于它揭示了一个被忽略的自由度，但也因此暴露了一个更本质的判据：**压缩的收益必须用「实际省下的操作」而非「省下的存储」来衡量**。通道轴压缩在理论上有优势（QK 点积直接变小），但受限于硬件对非结构化稀疏的支持；这与 P174/CSR 面临的「位宽降低后 kernel 未必更快」是同一类问题。第二个值得追问的点是「恢复」的信息来源：被剪通道的值若要精确恢复，就必须以某种形式保存——否则恢复只能近似。因此 recoverable 在这里更准确的表述是「在打分时可近似补偿」，其误差界（以及随剪枝率 $\lambda$ 的增长速度）是该方法的核心理论空缺；若误差随 $\lambda$ 非线性增长，则会在高压缩率下突然失效，而论文以离散 $\lambda$ 点取样，曲线形状未必被暴露。

## 6. 与相邻工作的关系

与所有 token 级淘汰/合并方法（H2O、SnapKV、P178）正交，可叠加；与量化/低秩方法（P171、P174、P179）同样正交但取向不同：量化降低每个元素的位宽、通道剪枝减少元素个数（在特征维）。与 P182 构成「同一问题的两种轴」——P182 让压缩 key 可当索引用（token 筛选），P183 让压缩 channel 可在打分时恢复（特征筛选）。与结构化通道剪枝的差别是它坚持非结构化与查询条件化。

## 7. 可迁移点与开放问题

可迁移：(a)「**存储时有损、计算时恢复**」这一解耦，可推广到任何「读取频率低于存储成本」的记忆系统（向量库、多模态 token、历史对话摘要）；(b) 把通道显著性做成查询条件化的量，而不是模型的静态属性——这一点对理解 KV 结构本身有普遍意义。开放问题：通道轴与 token 轴的最优预算分配；恢复误差随剪枝率的解析界；非结构化稀疏的硬件落地；以及把可恢复剪枝与合并（P178）结合，得到「可逆 + 可恢复」的双重保底压缩。
