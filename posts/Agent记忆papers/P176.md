# P176 Beyond Fact Retrieval: Episodic Memory for RAG with Generative Semantic Workspaces（GSW）

- 会议/来源：AAAI 2026（主会）
- 方向簇：AGENT
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40557
- 本地全文：cache/txt/P176.txt

## 贡献

提出生成式语义工作区（Generative Semantic Workspace, GSW）：用 **Operator** 把观测映射成局部语义结构，用 **Reconciler** 把局部结构调和进一个持久工作区，强制满足时间、空间与逻辑一致性，从而让 RAG 从「事实检索」升级为「情节追踪」（追踪角色、动作与时空背景的演化）。在 EpBench（10 万–100 万 token 语料）上比 RAG 基线最高提升 20%，同时把查询期上下文 token 量相对最省 token 的基线再降 51%。

## 机制要点

框架借海马体—新皮层类比：Reconciler 对应海马（检索、工作区、更新），Operator 对应新皮层（LLM 驱动的语义角色抽取）。流程为：长文切成语义连贯块 → 每块经 Operator 生成局部语义图 → Reconciler 将局部实例合并进全局工作区并消解冲突 → 查询时从工作区检索、重排、作答（Figure 2）。与向量 RAG 的根本差别是记忆单元从「文本块 + 嵌入」变成一个**可演化的结构**，角色/动作/时空被显式建模，因此可以回答跨事件的角色变化类问题。

## 局限与定位

第一，语料是**模板生成的合成书**，事件由事件模板逐章生成，其结构规整度远高于真实文本，20% 的提升需要在真实长文上复核。第二，Reconciler 的一致性调和依赖 LLM 自身的判断，当新旧信息冲突时如何裁决（保留哪个版本）是方法能否长期运行的关键，而摘要未给出裁决规则与失败率。第三，成本优势来自「只把工作区中相关子结构喂给 LLM」，这要求工作区本身足够紧凑；章节数从 200 增长到 2000 时工作区如何扩张、是否需要压缩或遗忘机制，是该方法从「记忆构建」走向「记忆压缩」的分水岭。定位上，它代表了记忆研究从「检索器优化」转向「结构化世界模型」的一支，与 P175（ARTEM）同属 2026 年情节记忆工作的两条路线（生成式语义 vs 自组织网络）。
