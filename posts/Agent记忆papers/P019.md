# P019 COMI: Coarse-to-fine Context Compression via Marginal Information Gain

## 一句话贡献

用「单元与 query 的相关度减去它与其它单元的最大冗余」定义的 Marginal Information Gain（MIG），同时驱动粗粒度的分组压缩预算再分配与细粒度的组内 token 加权融合；在 32x 压缩下把 Qwen2-7B-Instruct 在 NaturalQuestions 上的 EM 从次优基线 GMSA 的 24.63 提到 49.15。

## 1. 问题与第一性原理动机

上下文压缩的本质是：在把 $N$ 个 token 压到 $N/r$ 个表示时，如何决定丢弃什么。主流做法（LLMLingua、SnapKV、Activation Beacon 一类）以「与 query 相关的 token 更该保留」为准则，等价于对每个单元独立打分再取 Top-k。这个准则隐含了一个强假设——被保留单元之间条件独立。一旦违反，压缩器会把同一事实的多个近似复制一起保留，用有限的预算存储冗余信息；原文在 Introduction 中明确把这一点指为「implicitly assume conditional independence ... leading to significant redundancy」。第二个结构性缺陷是固定压缩率：同一段上下文里不同片段的信息价值差异很大，全局均一压缩等于把预算平摊给无关片段。因此正确的目标不是「最大相关度」，而是带递减回报的边际增益（原文引用 submodularity 文献 Bilmes 2022 作为这一思路的背景）。

## 2. 核心洞察

MIG 用一个极简形式刻画边际增益：$G(x_i,q,X)=\cos(x_i,q)-\max_{j\neq i}\cos(x_i,x_j)$。第一项是相关性收益，第二项是用「最近邻相似度」当作冗余代价的代理。这个设计的关键在于它把不可直接度量的「联合冗余」换成了逐 token 可算的 $O(N)$ 最近邻惩罚，使得同一套打分能同时用于段级（决定预算分配）与 token 级（决定融合权重）。论文在 Appendix A 中声称 MIG 的期望性能优于仅用相关性，并在 Table 2 的消融里给出了间接支持：去掉粗粒度或细粒度的冗余项都会掉点（NaturalQuestions 32x 上 EM 分别从 56.31 降到 54.59 与 51.53）。

## 3. 方法机制

COMI 是 encoder-decoder 框架。流程：(1) query 平均池化得到单一向量 $q$；(2) 把 encoder 隐状态 $H$ 切成 $m$ 个等长段，每段取与 $q$ 余弦最大的代表向量 $\hat h_i$，计算段级 MIG 并按 $P_i=\mathrm{softmax}(-G(\hat h_i,q,H))$ 分配预算（增益越高压缩率越低）；(3) 段内对每个 token 算 MIG，用 $\mathrm{softmax}(G(h_k,q,S_i))$ 加权把所有 token 融合为 1 个压缩向量。训练上 encoder 与 LSA 模块全量微调，decoder 只更新每层的 $W_Q,W_K,W_V,W_O$，用答案的交叉熵损失端到端优化压缩表示的可解码性。复杂度方面，分组再分配为 $O(N_g\log N_g+N_g^2)$、融合为 $O(r^2)$，因为 $N_g$ 与 $r$ 都远小于 $N$ 而被论文称为轻量。

## 4. 实验证据

骨干为 LLaMA-2-7B-Chat 与 Qwen2-7B-Instruct，训练集从 NaturalQuestions、HotpotQA、2WikiMQA、NarrativeQA、MultiNews 各采样 20,000 条（长度 ≤32K），8×H20 训练。Table 1 主结果：Qwen2 在 16x 下 NaturalQuestions EM/F1 = 56.31/55.52，2WikiMQA 52.13/60.43，HotpotQA 45.11/60.52；32x 下分别为 49.15/49.59、48.89/57.07、40.46/55.24。同表 16x 下 Activation Beacon 在 NaturalQuestions 只有 11.67/27.53。Table 3 端到端延迟：NarrativeQA 上 COMI 3.27 s，原长 prompt 7.04 s，SnapKV 2.10 s，Activation Beacon 3.93 s。Table 4 用原生 256K 的 Qwen3-4B-Instruct，16x 压缩下 NaturalQuestions F1 34.79 反而高于直接喂全长 prompt 的 16.90。消融（Table 2，32x，Qwen2）中损失最大的是去掉细粒度融合（50.81/50.82）与去掉细粒度冗余（51.53/52.89）。

## 5. 第一性原理再审视

三点值得警惕。第一，评测口径不公平：训练样本直接取自五个评测数据集本身，而 SnapKV、LongLLMLingua、LLMLingua-2 等基线多为免训练或使用不同训练协议，因此「+25 EM」里有多少来自 MIG 机制、多少来自同分布微调无法分离。原文并未报告跨域（训练集外的长文档）结果。第二，$L_i=L_{org}\cdot P_i$ 且 $\sum_i P_i=1$，意味着各组目标长度之和恰为原长，而 Eq. 7–8 又把每段融合成 **1 个** token，两处对「压缩预算如何落地」的描述并不自洽，实际计算图的压缩率来源（分组数 $m$？还是别处？）在正文中未交代清楚。第三，MIG 把冗余定义为「与单个最近邻的相似度」，这是逐点代理而非集合级冗余；在多跳问答里支撑事实本就共享实体，此时冗余惩罚可能反向损害必要信息。此外，软融合摧毁了字面形式（数字、实体名），而论文的评测以 EM 为主——用一个摧毁字面形式的表示去冲击最依赖字面匹配的指标却仍然领先，说明提升很可能主要来自 encoder 的语义重编码能力，而非选择准则本身。

## 6. 与相邻工作的关系

与 ICAE、GMSA 同属软 token 压缩（把长上下文改写为紧凑连续表示），区别是把「选择 + 融合」两个尺度统一到一个 MIG 打分下；与 Activation Beacon、SnapKV 同属面向 KV/上下文预算的压缩，但那两者在 KV 层做丢弃/合并、无需额外训练，本方法需要训练 encoder 且要求 decode 侧部分微调；与 LongLLMLingua、LLMLingua-2 这类硬 token 压缩相比，本方法牺牲可解释性与 API 兼容性换取更高的压缩容忍度。

## 7. 可迁移点与开放问题

最可迁移的是 MIG 这个打分式：$O(N)$ 可算、无量纲、既能排序又能当软权重，可直接搬到 RAG 重排、agent 长期记忆的检索预算分配、KV eviction 的重要性打分。开放问题：(a) 在**没有**同分布微调的条件下 MIG 是否仍有增益；(b) 冗余项是否应改成集合级（如子模覆盖或行列式点过程）；(c) 多跳任务中「冗余」与「证据链」的冲突如何建模；(d) 原文的预算分配公式与实现之间的不一致需要澄清，否则压缩率这一核心受控变量其实未被严格定义。
