# P178 KeepKV: Achieving Periodic Lossless KV Cache Compression for Efficient LLM Inference

- 会议/来源：AAAI 2026（主会）
- 方向簇：KV
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40611
- 本地全文：cache/txt/P178.txt

## 一句话贡献

把 KV 压缩从「淘汰」改成「合并 + 注意力校正」：用 Electoral Votes 机制记录合并历史并自适应修正注意力分数，再用 Zero Inference-Perturbation Merging 补偿合并造成的注意力损失，从而做到单步合并无损、多步合并有误差界，并在 10% 预算下保持生成质量与 >2× 吞吐。

## 1. 问题与第一性原理动机

淘汰（eviction）是不可逆的信息删除：一旦某个 KV 被丢，后文即使需要也无法恢复，这解释了长程检索任务上的系统性崩溃。合并（merging）试图保住信息量——被淘汰的 KV 被折进保留的 KV 中。但合并引入了一个更隐蔽的问题：它改变了参与 softmax 的**分母**。全 KV 下 $a_i = \exp(q^\top k_i)/\sum_j \exp(q^\top k_j)$，合并后原来的两个 logit 变成一个，求和项数减少，注意力总和不再为 1，于是模型看到的注意力分布与它在训练时学到的分布不一致——论文把这种不一致造成的质量下降称为 **Attention Sag**（Figure 1 用四个示意块对比 eviction / 合并 / Full KV / KeepKV 四种情形）。

## 2. 核心洞察

核心判断是：合并的正确性问题是一个**注意力权重守恒问题**，而不是相似度问题。因此需要两件东西——(1) 一份「合并历史」的账本，知道当前保留的 KV 吸收了哪些原始 token，才能在计算注意力时把被吸收的权重按比例还原（Electoral Votes：保留 KV 的注意力分数按它代表的合并投票数自适应调整）；(2) 一次补偿项，显式抵消合并前后注意力总和的变化（Zero Inference-Perturbation Merging）。Figure 2 用三条经验证据支撑这一设计：保留 top-$k$ 并不可靠地保住大多数注意力质量；被淘汰的 token 在后续生成中仍有相当比例会进入 top-20% 注意力；每个 token 的注意力在各生成步之间方差很大（即「重要性」是时变的）。

## 3. 方法机制

(1) 选择要淘汰的 KV 对后，不删除而是与最相似的保留 KV 合并（Figure 3 的示例流程：被淘汰的 $(k_e,v_e)$ 找到余弦相似度最高的保留项 $(k_c,v_c)$ 并归并）；(2) Electoral Votes 在保留项上记录「合并了多少原始 token 的票」，据此缩放其注意力分数，恢复权重守恒；(3) Zero Inference-Perturbation Merging 提供一个补偿项，使合并前后对输出的扰动在单步上为零，并给出多步累积误差的界；(4) 由于该方法只定义「合并动作」，不规定「谁被淘汰」，因此可与 H2O、D2O 等现成策略及各种层间预算方案自由组合。代价：合并需要相似度搜索（论文给出 cache size = 400 时的额外开销实测，Table 2）；合并是不可逆的语义平均，对需要**逐字精确**的内容（数字、ID、代码）有失真风险；参考文献已修正为周期性（periodic）压缩流程，因此仍有同步成本。

## 4. 实验证据

吞吐：Table 1 报告 4K 上下文、20% 压缩率下 KeepKV（batch 8）的吞吐，与 Full cache（batch 2，116.54 tokens/s）、H2O（8，317.33）、D2O（8，214.8）对照，摘要给出的整体结论是 >2× 吞吐提升。质量：Table 3 报告 Llama-2-7B 等模型在 LongBench（单文档 QA、多文档 QA、摘要、合成、代码）上 20% 压缩率的完整结果，Figure 4 给出 HELM 与 LM-Eval 上的曲线；摘要强调「仅 10% KV 缓存预算仍保持优越生成质量」。开销：Table 2 给出合并的额外计算开销，代码与扩展版（arXiv:2504.09936）公开。

**证据缺口**：(a) 摘要的「single-step lossless」有理论支撑，但「lossless」指的是注意力扰动为零，不等价于**输出等价**——读者需注意这两个层次；(b) 多步误差界是理论结果，实验里缺少「误差界是否紧」的检验（例如对比实际多步累积失真与理论上界）；(c) 需要精确检索的任务（NIAH 类、代码补全）是合并式方法的高危区，Table 3 的代码子任务（Lcc、RepoBench-P）应被优先核验，而摘要未强调这一维度；(d) 合并相似度阈值与合并顺序会影响长期行为，缺少敏感性分析。

## 5. 第一性原理再审视

KeepKV 的贡献可以概括为一句：**它把「删除信息」换成了「降低信息的分辨率」**。这在信息论上是更温和的有损编码（不丢弃支撑，只降维），因此在小预算下天然优于 hard eviction。但代价是它把误差从「可能为零」变成「一定存在且不可逆」：合并后的 KV 是若干原始向量的组合，任何后续查询都无法把它拆开，因此对**需要区分被合并在一起的两个 token**的查询必然出错。这提示了一条清晰的判据：合并式方法适用于「语义可平均」的内容（叙事、描述性文本），不适用于「原子不可分」的内容（数字、标识符、代码符号）。论文用 Figure 2 证明「top-$k$ 保不住大部分注意力」和「注意力是时变的」，这两条证据实际上同时支持合并与支持「不该做一次性压缩」，因此读者可以从中读出比论文自身主张更强的结论：**在生成长度未知时，任何一次性压缩都有结构性风险，真正需要的是可撤销或有界的压缩**。Electoral Votes 的价值也在此——它是让合并**可审计**的元数据，这一思路可迁移到任何「多个原始条目折叠成一个表示」的系统。

## 6. 与相邻工作的关系

与 CaM（cache merging）等合并方法相比，差异在于是否维护合并账本并校正注意力：CaM 等直接平均导致 Attention Sag，KeepKV 用 Electoral Votes 修正。与 H2O、SnapKV、StreamingLLM 等淘汰方法正交且可组合（论文的消融正是把 KeepKV 套在多种淘汰策略上）。与 P177（Judge Q）构成「打分更准 vs 承认丢失」的两条路线对照；与 P174（QJL）同属「保留所有 token 只是降低保真度」的思路，但一个降位宽、一个降分辨率。与 KV 量化同样正交，可叠加。

## 7. 可迁移点与开放问题

可迁移：(a) **为不可逆操作保留元数据**（此处是合并账本）以便后续补偿，这一原则适用于 agent 记忆的摘要/归纳、向量库的聚类合并、检索索引的压缩；(b) 「压缩导致的分布漂移需要显式补偿」是可迁移的工程范式，任何改变了 softmax 分母或归一化因子的近似都需要类似校正。开放问题：合并式压缩在精确召回任务上的界；与量化/稀疏的叠加；自适应决定「合并还是淘汰」（当相似度低时合并本身就危险）；以及把单步无损推广为「对下游任务的输出无损」。
