# P087 Not All Heads Matter: A Head-Level KV Cache Compression Method with Integrated Retrieval and Reasoning

- 会议/来源：ICLR 2025（主会）
- 方向簇：KV
- 链接：/paper_files/paper/2025/hash/f649556471416b35e60ae0de7c1e3619-Abstract-Conference.html
- 本地全文：cache/txt/P087.txt

## 一句话贡献

提出 HeadKV 与 HeadKV-R2：把 KV 压缩从「层级」推进到**头级**，并针对上下文问答这一需要**同时具备检索与推理**的任务，设计了一种「上下文推理能力估计」来评估每个头的重要性；在 LongBench、LooGLE 等基准与 Llama-3-8B-Instruct、Mistral-7B-Instruct 上显著优于强基线，尤其在小缓存（KV size = 64 / 128）下优势明显——仅保留 1.5% 的 KV cache 即可达到全量性能的 97%。

## 1. 问题与第一性原理动机

层级压缩隐含假设「同层各头的重要性相近」，而多头注意力的存在本身就说明各头承担不同功能（P084 的检索头/流式头划分、P066 的时序一致性分类都印证了这一点）。更关键的是，论文指出的评估维度问题：上下文问答既需要**检索**（找到证据）又需要**推理**（组合证据），而只按检索能力挑头会漏掉承担推理职能的头——一个头可能几乎不参与长距离召回，却负责在证据之间建立联系。因此头重要性的度量标准必须与任务的真实能力需求对齐，而不是沿用「注意力是否覆盖长距离」这类单维代理。

## 2. 核心洞察

洞察是：头的重要性是**任务能力依赖的**，且这种依赖可以被显式估计。HeadKV-R2 通过构造上下文推理能力的估计来打分，使选择过程兼顾「能找到」与「能用上」。这一视角的重要性超出了一个具体方法：它提示压缩准则应当从「信息在哪」转向「能力在哪」——后者才是下游指标的直接决定因素，也是为什么单纯基于注意力幅度的打分在低资源（小 cache）设置下会迅速失效。

## 3. 方法机制

(1) 在头级别评估重要性（而非对整层统一裁剪）；(2) HeadKV-R2 用上下文推理能力估计来刻画头对「检索 + 推理」两类需求的贡献；(3) 按重要性分配各头的 KV 预算。代价是：能力估计需要一个校准/评估流程（是否依赖特定数据集需核实）；头级预算使不同头的 cache 结构异构，对 kernel 与内存对齐提出要求；校准结果跨模型/跨任务的可迁移性决定其复用价值。

## 4. 实验证据

基准覆盖 LongBench 与 LooGLE；模型覆盖 Llama-3-8B-Instruct 与 Mistral-7B-Instruct；并做了长上下文能力测试。总量结论：显著优于强基线，在 KV size = 64/128 的低资源设定下尤其明显；在上下文问答基准上仅用 1.5% 的 KV cache 就达到全量性能的 97%。代码与数据开源。

## 5. 第一性原理再审视

第一，「1.5% 预算达到 97% 性能」的两个数字需要分别验证：97% 是相对全量的比例，若全量分本身不高（例如 40 分），97% 对应的绝对分仅约 39；同时 1.5% 是在何种上下文长度与评估集上取得也需要明确。第二，「上下文推理能力估计」的构造方式是全文最关键的技术细节，也是可复现性的核心：若它依赖特定基准的题目分布，那么在真实业务中需要重建校准集，通用性打折。第三，低资源下的优势很可能部分来自**头级异质性**本身（等同于给予更大的结构自由度），而非估计算法的精确性；需要消融把「头级 vs 层级的自由度差异」与「估计方法」分离。第四，与 P084 的对照很有价值：两者都做头级划分，但 DuoAttention 只分两类且面向通用长上下文，HeadKV-R2 面向检索+推理复合需求；论文应给出在对方强项任务上的对比，以确定各自适用边界。

## 6. 与相邻工作的关系

与 P084（DuoAttention 的检索头/流式头二分）最直接，差别是是否显式建模推理能力；与 P066（CateKV，按时序一致性分类并分策略）在分类依据上不同；与 P037（Ada-KV 头间预算分配）、P083（CAKE 层间 + 时序分配）在「分配维度」上构成头、层两条互补路径；与 P090（RazorAttention，同样基于检索头但不丢弃信息的补偿机制）共享头划分思想但处理被弃 token 的方式不同。定位上属于头级压缩中加入能力维度的改进。

## 7. 可迁移点与开放问题

可迁移：(a) 「按任务所需能力（而非信息量）评估组件重要性」是压缩准则设计的重要升级，可推广到层、专家、模态分支的重要性评估；(b) 在低资源区间验证方法优势（而非只报平均）应当成为 KV 压缩评测的常规做法。开放问题：能力估计的校准成本与跨域迁移；头级异构 cache 的 kernel 支持；与检索头二分类方法的适用边界对比；以及与量化/稀疏组合时的稳定性。
