# P177 Judge Q: Trainable Queries for Optimized Information Retention in KV Cache Eviction

- 会议/来源：AAAI 2026（主会）
- 方向簇：KV
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40497
- 本地全文：cache/txt/P177.txt

## 一句话贡献

针对 KV eviction「用 prefill 末端窗口当 query 来打分」导致的局部偏置，训练一组可学习的 soft token 追加在输入末尾，只微调 embedding 层，让这些 soft token 的注意力图去**对齐真实解码 token 的注意力图**，从而得到具有全局视野的重要性打分器。

## 1. 问题与第一性原理动机

主流 eviction（H2O、SnapKV、PyramidKV 等）用 prefill 阶段最后若干 token 作为 query 计算 KV 重要性，这个代理量有两个结构性缺陷。其一，**位置偏置**：末尾窗口天然关注近处内容，于是「近期被关注」被当成「长期重要」，位于中段的关键证据（lost-in-the-middle）被系统性低估。其二，**因果错配**：真正要服务的是**未来将要生成的 token**，而 prefill 的末尾 token 只是众多可能未来中的一个任意代表。前者是统计偏差，后者是目标函数错位——两者叠加使注意力打分器始终在「观测到的注意力」而非「需要的注意力」上做近似。论文 Figure 2 用 prompt 调整前后的性能落差直接展示了这一脆弱性：同一批方法在同一预算下，仅仅改动提示的表述方式，分数就显著波动。

## 2. 核心洞察

如果打分器的偏差来自「用某个具体 query 冒充未来」，那么正确的修法是**学一个专门的 query 代理**：它不必对应真实 token，只要其注意力分布与「真实解码时的注意力分布」在统计上一致即可。把这一目标写成训练任务，就得到「用 soft token 的注意力图去拟合解码 token 的注意力图」的蒸馏式目标；由于只更新 embedding 层，训练成本被压到极低——这是该方法的工程核心：**把打分器的设计问题转化成一个极小的参数学习问题**。

## 3. 方法机制

(1) 在词表中引入 $n$ 个可学习 soft token（论文实验取 $n=32$），追加在输入序列末尾（Figure 3 展示训练/prefill/decoding 三阶段）；(2) 训练时，让 soft token 对原始输入的注意力图与真实解码 token 的注意力图对齐，等价于学一个「有全局视野的打分 query」；(3) 训练只更新 embedding 层（其余参数冻结），训练集取 ShareGPT 的 5 万条样本（4.5 万通用 + 0.5 万代码）；(4) 推理时复用现有 eviction 算法，仅把打分 query 换成 soft token。代价：需要一次轻量训练并绑定到具体模型（无法零成本迁移到新模型）；soft token 长度 $n$ 是超参（32 为效率与泛化的折中）；打分器与具体 eviction 策略仍需配套调参。

## 4. 实验证据

模型为 Llama-3.1-8B-Instruct 与 Mistral-7B-Instruct-v0.3，基准为 LongBench、RULER、Needle-in-a-Haystack。Table 1 给出 Llama-3.1-8B-Instruct 在 128/256/512 预算下与 StreamingLLM、H2O 等方法的对照（Full KV 在 512 预算下为 39.80）；Table 2 给出 LongBench 上跨模型、跨预算的完整对比，Table 3 给出 RULER（n=100 样本），Figure 4 给出 NIAH 在 4K–32K 长度上的曲线。摘要与正文的量化结论是：LongBench 平均提升约 1 分，RULER 提升超过 3 分。Table 4 进一步报告「关键 KV 命中率」：在相同预算下，soft token 打分能比 SnapKV 保住更多真正被后续生成用到的 KV，这为「打分器更准」提供了直接机制证据，而不只是端到端分数。

**证据缺口**：(a) 训练数据是 ShareGPT（对话为主），而评测包含代码、多文档 QA 等分布；未见对训练分布敏感性的消融；(b) $n=32$ 的选择依据是「训练效率与泛化的平衡」，但缺少 $n$ 的扫描曲线，读者无法判断性能对 $n$ 的敏感性；(c) 提升幅度（LongBench +1、RULER +3）在绝对意义上是**中等**，且对比方法是否经过同等调参需要核对；(d) 判别性证据最强的是 Table 4 的命中率指标，建议读者以此而非端到端均值来评估该方法的真实贡献。

## 5. 第一性原理再审视

Judge Q 把「重要性」的估计从观测式中介（prefill 末尾 token）替换成学习式中介（soft token），方向正确，但仍继承了 eviction 范式最深的一条假设：**重要性可以在生成之前一次性判定的**。而 Figure 2 与 KeepKV（P178）的 Figure 2 都指出注意力分布在生成过程中会漂移，被淘汰的 token 可能在后文重新变得关键；一次性打分越准，越会让人误以为问题已解决。第二个假设是「注意力图对齐 ⇒ 重要性对齐」：蒸馏的是分布的相似性，而下游关心的是「保住哪些 KV 才能不改答案」，两者仅在注意力与因果贡献一致的范围内等价——这一点需要扰动式对照（例如人为遮蔽被高分 token 看精度掉多少）来验证，论文未提供。第三，从信息论角度，soft token 本质上是在输入里插入 $n$ 个「探针」，用少量参数换取对全序列的注意力视图；探针数量与信息量成正比，因此 $n$ 的扫描缺失是这份工作最实质的证据空缺。此外，训练成本虽低但**绑定模型**，在生产环境的多模型服务里，每个模型都要一份探针，这是它的隐性运维成本。

## 6. 与相邻工作的关系

与 SnapKV / H2O / PyramidKV 等**观测式打分**方法直接竞争：Judge Q 换掉的是打分 query，而不是淘汰策略本身，因此可与层间预算分配（如 PyramidKV 的金字塔分配）叠加。与 P178（KeepKV）对比鲜明：KeepKV 承认淘汰不可逆的损失，改用「合并 + 注意力校正」；Judge Q 选择把「打分更准」这条路走到尽头。与 P180（Lethe）互补：Lethe 强调层间与时间维度的动态预算，Judge Q 强调打分器的全局性，两者可组合。与 query-aware 的 KV 检索方法相比，它仍保持单次决策的 eviction 结构。

## 7. 可迁移点与开放问题

可迁移：(a)「学一个探针去模拟将来才会出现的信息需求」这一范式，可直接用于 agent 记忆的预取与淘汰、多轮对话历史的裁剪决策；(b) 只调 embedding 层的极低成本适配，适合在已有部署上做增量优化。开放问题：探针数 $n$ 与收益的缩放关系；打分器与淘汰策略的联合优化（当作可微的选择问题）；生成过程中注意力漂移的在线修正（与 Lethe 的时序剪枝合流）；以及跨模型/跨任务的探针复用。
