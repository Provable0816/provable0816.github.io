# P086 MELODI: Exploring Memory Compression for Long Contexts

## 一句话贡献

提出 MELODI：一种用短上下文窗口处理长文档的记忆架构。核心原则是把短期与长期记忆表示为**跨 transformer 层与跨上下文窗口的层级化压缩方案**——短期记忆由多个层对上下文窗口做循环压缩、保证窗口之间平滑过渡；长期记忆则在**单个中间层**内进一步压缩并跨窗口聚合信息。相对强基线 Memorizing Transformer（对 64K 个 KV 对做稠密注意力），MELODI 在多个长上下文数据集上性能更好，同时显存占用降低 8×。

## 1. 问题与第一性原理动机

用短窗口处理长文档的核心矛盾是：窗口内的信息处理成本可控，但**跨窗口的信息如何携带**决定了模型能否回答需要全局视野的问题。既有方案大致两类：一类把长期记忆做成大容量的键值存储并对其做稠密注意力（成本高，且随记忆扩大而增长），另一类把历史压成定长状态（成本低，但容量受限、易覆盖）。MELODI 的问题设定是：能否通过**结构的层级化**让两种记忆各司其职，从而在不牺牲质量的前提下把长期记忆的存储压下来。

## 2. 核心洞察

洞察是「分层」这一维度被忽略了：常规做法只在一个层级上压缩（要么压成状态、要么保留 KV），而模型本身是逐层加工的——浅层表示更具体、深层更抽象。因此可以让**多层协同完成短期记忆的循环压缩**（保证窗口过渡平滑，因为每层都参与了状态转移），而把**长期聚合集中在单个中间层**（中间层的表示通常被认为兼具具体性与抽象性，适合做信息汇总）。这一「用层深度换记忆容量」的分配方式，使得同样显存预算下能容纳更长历史，从而以 8× 更小的记忆取得更好的性能。

## 3. 方法机制

架构上：M 个短期层 + 1 个长期层 + N-M-1 个短期层；短期层循环地把每个窗口 $x_k^0$ 压成短期记忆 token $\{z_k^l\}$；长期层在自身内部把压缩后的 key-value 存入长期记忆 $m_{1:k}$ 并跨窗口聚合。代价是：长期层成为信息瓶颈（若该层容量不足，全局信息仍会丢失）；层级结构需要相应的训练；「单点聚合」的设计也意味着该层的稳定性对整体质量至关重要。

## 4. 实验证据

对照基线是 Memorizing Transformer（64K 对 KV 的稠密注意力）。MELODI 在多个长上下文数据集上取得更优性能，同时记忆占用降低 8×。摘要未给出逐任务细节与具体模型的规模。

## 5. 第一性原理再审视

第一，「更好的性能 + 8× 更小内存」是相对 Memorizing Transformer 这一基线，而该基线的稠密长记忆本身就属于昂贵设计；与更现代的压缩方法（P085 Activation Beacon、P045 KVzip）相比是否仍占优，决定了它当前的相对位置。第二，把长期聚合放在单个中间层的假设需要更直接的证据：跨窗口信息的质量是否对该层深度敏感（例如换到更浅或更深的层会怎样），这是可以实验证伪的设计问题，论文若未给出该消融，则「中间层适合聚合」仍是直觉。第三，短期记忆的循环压缩会造成跨窗口误差累积；长文档末尾对开头信息的依赖属于最坏情况，需要专项测试。第四，架构级方法需要从零训练或大规模改造，落地成本高于可挂载的 KV 压缩方法（对比 P083、P084），这在工业采用上是关键差异。

## 6. 与相邻工作的关系

与 Memorizing Transformer（被对照的基线）同属「长记忆 + 短窗口」，差别在于压缩的层级化设计；与 RMT/循环记忆架构（P021）都使用跨窗口的状态传递，但 MELODI 把压缩分散到多层而非集中在 memory token 上；与 P075（M+ 的隐空间记忆 + 检索）相比，MELODI 不引入外部检索；与 P085 一样属于「训练式压缩」，但压的是跨窗口记忆而非全部激活。定位上属于长上下文记忆架构的设计探索。

## 7. 可迁移点与开放问题

可迁移：(a) 「用网络深度作为压缩维度」这一思路可推广到多模态长序列（按层分配不同时间尺度的记忆）与流式处理；(b) 把长期聚合集中到少数层、把短期状态分散到多层，是降低记忆成本的通用分工模式。开放问题：长期层的最佳位置与容量；跨窗口误差累积；与现代 KV 压缩方法的横向对比；从零训练的成本；以及在需要高精度逐字召回的任务上的表现。
