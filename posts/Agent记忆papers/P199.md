# P199 MatryoshkaKV: Adaptive KV Compression via Trainable Orthogonal Projection

- 会议/来源：ICLR 2025（主会）
- 方向簇：KV
- 链接：https://openreview.net/forum?id=d7b351608d824a4680344a02b180a947
- 本地全文：cache/txt/P199.txt

## 一句话贡献

补上 KV 张量四个轴中被忽视的那一轴——**特征维（feature dimension）**：用可训练的正交投影矩阵把 key/value 降到低维子空间，并用 Matryoshka 式嵌套训练让投影矩阵的列按重要性分层，从而支持「同一套投影、任意压缩率」；再按层与头自适应搜索最优压缩率，在 LLaMA2-7B/Mistral-7B 上以平均 60%（极端场景 75%）的压缩率保住 90% 以上性能。

## 1. 问题与第一性原理动机

KV 张量形如（层数, 头数, 序列长度, 特征维）。现有工作几乎全聚焦前三个轴（层间预算、头剪枝、token 淘汰/合并），因为它们直接对应「减少元素个数」。但注意力的计算量同时取决于特征维：QK 点积与 V 的加权都是在 $d$ 维上做的。如果 KV 的特征表示存在低秩结构（注意力只需少数方向上的投影即可近似），那么**降维可以在不删任何 token 的前提下降低计算与存储**——这是一种与 token 淘汰正交、且不引入「信息被不可逆丢弃」风险的压缩。论文先检验最自然的低维投影——PCA——发现它在中等压缩率下有效但**在低压缩率下急剧退化**（Table 1 的实证）。退化原因不是低秩假设错，而是 PCA 优化的是重构误差，而下游关心的是注意力输出。

## 2. 核心洞察

两个判断构成本文的核心：其一，**投影矩阵应当被训练而不是被求解**——PCA 是无监督的最优重构基，而注意力所需的子空间由任务损失决定，二者一般不同；因此用蒸馏目标直接调投影矩阵能弥合差距。其二，**压缩率不应是训练时的固定超参**。Matryoshka 训练强制投影矩阵的列形成层级（Figure 2：把主要信息集中在前若干列），于是推理时可截断到任意维度而无需重训。这一设计把「为每个压缩率训一个模型」变成「训一次、按需截断」，同时使**逐层逐头的异构压缩率分配**成为可能——而 Figure 1 显示不同层/头的可行压缩水平差异很大（用 ARC-challenge 样本蒸馏得到的可视化）。

## 3. 方法机制

(1) 为每层每头的 K/V 引入正交投影矩阵（正交性保证降维不引入额外缩放畸变）；(2) 用**蒸馏损失**训练投影矩阵，对齐降维后与原始模型的注意力/输出行为，而非最小化重构误差；(3) **Matryoshka 训练**：按嵌套的列顺序组织投影矩阵，使前缀子矩阵即为一个可用的小投影，从而一次训练覆盖一整个压缩率区间（论文称最终结果对 schedule 选择不敏感）；(4) 给定总预算后，**搜索各层/头的最优压缩率**（异构分配）。代价：需要一次蒸馏训练（虽数据效率高，论文强调 training data efficiency）；正交约束限制了解空间；逐层逐头搜索带来一次性调优成本；与量化/token 淘汰的组合效果未系统评测。

## 4. 实验证据

源模型为 LLaMA2-7B-base 与 Mistral-7B-v0.3-base；评测为常识与推理类多选题集合：HellaSwag、ARC-challenge、ARC-easy、PIQA、WinoGrande、CommonsenseQA，报告相对 baseline 的百分比（100% 为原模型）。Table 1 是 PCA 与本方法的对照（论文记为 MKV），关键结论是 PCA 在中等压缩下尚可、低压缩率下明显退化，而可训练投影显著弥合差距；主结果声称在平均 60% 压缩率下保持 >90% 性能，特定极端场景可到 75%。Figure 1 给出逐层/逐头可行压缩水平的可视化差异，支撑异构分配的必要性；正文另外报告训练方案对 schedule 不敏感。

**证据缺口**：(a) 评测集中在**短上下文多选题**，而 KV 压缩的真实收益场景是长上下文（LongBench、RULER、NIAH）；缺少长上下文证据使「60% 压缩保 90% 性能」的外推风险较大。(b) 蒸馏目标的选择（对齐注意力输出还是最终 logits）会决定学到的子空间性质，论文未做不同蒸馏目标间的对照。(c) 与 token 级方法（eviction/merge）的**联合最优预算分配**未做——在总预算固定时，把预算花在特征维还是 token 维上是核心问题。(d) 逐层逐头的压缩率搜索算法细节与搜索成本未被量化，(e) 「数据效率高」这一主张需要与「用多少蒸馏样本」一并呈现。

## 5. 第一性原理再审视

降维压缩与删 token 是两类本质不同的有损操作：前者在**每个 token 上都引入小误差**，后者在**少数 token 上引入大误差**。这个区别决定了两者的失效模式不同——降维的误差是弥散的、对需要**精确定位单个 token** 的任务（单针检索、标识符匹配）相对友好，但对需要**高精度数值读出**的任务（大数运算、精确比较）更危险；而 token 淘汰恰好相反。因此一个可检验的预测是：MatryoshkaKV 在多针检索类任务上应当优于同压缩率的淘汰方法，而在精确数值任务上应当劣于「保全部 token、只降位宽」的方法；论文未做这一分族验证，而它恰恰是判断该路线适用边界的关键。第二个值得追问的假设是「低秩结构在所有层与头都成立」：Figure 1 显示可行压缩水平差异巨大，说明部分层/头几乎不能降维，异构搜索因此在实践中是必需的而非锦上添花——这也意味着收益高度依赖搜索质量。第三，从表示学习角度看，用正交投影降维等价于**固定基 + 截断**，其表达能力弱于可学习的一般线性映射；正交约束换来的是数值稳定性与可嵌套性，这一取舍在极低压缩率下是否仍划算，需要与「非正交 + 适配」的对照实验来回答。

## 6. 与相邻工作的关系

与 KV 量化的区别在压缩的对象：量化降低每元素的位宽（P174 QJL、P179 KVmix），本文降低每元素的维度——两者可叠加。与低秩近似类工作（如用 SVD 消除量化残差、或用低秩投影近似注意力）相比，本文的关键差异是**投影矩阵可训练且分层分头自适应**，并由 Matryoshka 结构提供「一次训练、多档可用」。与 token 淘汰/合并（H2O、SnapKV、P178 KeepKV）正交且互补。与 P183（SPARK）同在特征维操作，但 SPARK 做的是通道级非结构化剪枝 + 打分时可恢复，本文做的是维度投影 + 降维后再计算，前者保留原坐标、后者换基，两者的误差传播路径不同。

## 7. 可迁移点与开放问题

可迁移：(a) **Matryoshka 式嵌套训练**是一个通用技巧——一次训练覆盖多档预算，可搬到量化位宽、检索 top-$k$、记忆库容量等维度；(b) 「压缩基应由任务损失而非重构误差决定」这一判断适用于任何把长表示压成短表示的设计（prompt 压缩、agent 记忆摘要、跨模态对齐）。开放问题：特征维与 token 维的最优预算分配；长上下文与精确检索任务上的边界刻画；正交约束 vs 一般线性映射的取舍；与量化、淘汰、合并的组合最优解；以及把投影矩阵的搜索从离线一次性调优升级为按输入自适应。
