# P061 Compress, Gather, and Recompute: REFORMing Long-Context Processing in Transformers

- 会议/来源：NeurIPS 2025
- 方向簇：CTX
- 链接：/paper_files/paper/2025/hash/90a2d040c8613e409611db8c237629c4-Abstract-Conference.html

## 贡献

针对超长上下文（常超出模型预训练窗口）提出两阶段推理框架 REFORM，试图同时避开两条既有路线的短板：循环压缩类方法难以保全信息，随机访问类方法则需要大量显存。REFORM 的做法是「先压、再捞、后重算」——第一阶段增量处理输入块并维护压缩 KV cache、构建跨层上下文嵌入并用早退提升效率；第二阶段通过相似度匹配定位关键 token 并**有选择地重新计算**它们的 KV cache。

## 机制要点

核心思想是不把压缩当作终局：压缩只负责把上下文保持在可控预算内，而真正的精度保障来自「重算被选中的关键 token」。这实际上承认了一个前提——压缩必然有损，因此需要在知道什么是关键的时候再补算。跨层上下文嵌入用于在压缩态下仍能判断哪些内容值得回溯；早退策略则用来抑制增量处理的开销。代价是引入了「选择—重算」这一额外的决策与计算步骤，需要与压缩率联合调参。

## 关键结果

相对基线，在 1M 上下文长度上 RULER 提升超过 52%、BABILong 提升 34%；在 ∞-Bench、RepoEval、MM-NIAH 上也优于基线，说明跨任务与跨模态的适应性；同时推理时间减少 30%、峰值显存降低 5%。

## 局限与定位

最重要的一点是**显存只降 5%**：这说明 REFORM 的定位是「在几乎不省显存的前提下大幅提精度」，与追求极限压缩比的方法（如 P045 的 394×、P067 的 87.5%）不在同一赛道上，直接与其他压缩方法比压缩率会得出错误结论。其次，52%/34% 的提升是相对「基线」而非全注意力，基线本身可能很弱；应关注它相对全量上下文的上限差距。第三，「重算」意味着推理时间与显存节省之间存在张力——30% 的时间下降需要在多大的压缩预算下取得、是否包括重算开销，需要核实。第四，早退策略会引入近似误差，其失效条件（例如需要深层语义才能判断重要性时）未见分析。定位上，REFORM 与 P051（检索式注意力）、P057（层级稀疏注意力）同属「选择性访问 + 精确计算」范式，区别是它把选择放在离散 token 级并显式重算。
