# P059 InfiniPot-V: Memory-Constrained KV Cache Compression for Streaming Video Understanding

- 会议/来源：NeurIPS 2025
- 方向簇：VLM
- 链接：/paper_files/paper/2025/hash/caef5f5e658aa1f7565f063a2cd99726-Abstract-Conference.html

## 贡献

提出 InfiniPot-V：首个**免训练、查询无关**、为流式视频理解施加「硬性且与流长无关」的显存上限的框架。既有方案要么假设整段视频与用户查询离线可得，要么必须先构建完整 cache 再压缩——后者意味着显存仍随流长增长，无法满足手机、AR 眼镜、边缘机器人这类固定内存设备。

## 机制要点

在视频编码（持续写入 cache）过程中监控 cache 用量，一旦达到用户设定的阈值就触发一次轻量压缩：用 Temporal-axis Redundancy（TaR）剔除时间轴上冗余的 token，用 Value-Norm（VaN）排序保留语义显著的 token。两把尺子分工明确——TaR 处理「重复的帧/事件」，VaN 处理「信号强度」，都不需要查询信息，因此可在未知未来问题的情况下持续运行。

## 关键结果

在四个开源 MLLM 与四个长视频/流式视频基准上，峰值 GPU 显存最多降低 94%，维持实时生成，且准确率与全量 cache 持平或更高——包括多轮对话场景。论文给出量级背景：15 分钟、10 fps 的视频经 LLaVA-Next-Video-7B 处理需要约 100（GB 级）显存。

## 局限与定位

两点值得追问。第一，「硬上限」是本文最重要的卖点，但摘要未说明压缩触发频率与总计算开销：频繁触发的轻量压缩若累加起来，可能抵消显存收益，而流式场景恰以延迟为第一约束。第二，VaN 只按 value 范数排序，隐含「范数大即重要」这一常被质疑的假设——在需要精确保留细小但关键信息（远处的小目标、一闪而过的动作）的监控场景，低范数 token 可能承载决定性线索；TaR 也可能误删「看似重复但语义有差异」的片段（例如连续两帧中唯一变化的对象）。论文称多轮对话下仍持平，但未给出此类高危场景的专项评测。定位上，InfiniPot-V 与 P028（MARC，查询相关检索 + RL 蒸馏）、P029（VideoChat-Flash，层级压缩）互为参照：它在三者中最强调**在线、查询无关、硬约束**，代价是放弃了查询信息带来的精度上限。
