# P090 RazorAttention: Efficient KV Cache Compression Through Retrieval Heads

- 会议/来源：ICLR 2025（主会）
- 方向簇：KV
- 链接：/paper_files/paper/2025/hash/2a98af4fea6a24b73af7b588ca95f755-Abstract-Conference.html
- 本地全文：cache/txt/P090.txt

## 一句话贡献

提出 RazorAttention：免训练的 KV 压缩算法。论文观察到 (i) 多数注意力头主要关注**局部上下文**，(ii) 只有少数「检索头」才会真正注意全部输入 token；据此对两类头采用不同缓存策略——检索头保留完整 cache、非检索头丢弃远端 token；并额外引入**补偿 token（compensation token）**机制以部分恢复被丢弃 token 的信息。相对既有淘汰方法，它在不显著影响性能的前提下把 KV cache 缩小 70% 以上，且兼容 FlashAttention，无需重训练或额外开销。

## 1. 问题与第一性原理动机

论文对「选择性丢弃 token」这一主流路线提出了一个原则性批评：丢弃是**不可逆**的，而被丢掉的 token 可能在未来查询中变得关键。既然不可逆的代价如此之高，那就应当先问「是否所有头都需要看到全部 token」。论文的判断是否定的——只有在少数负责长距离召回的头上，远距 token 才是必要的；其余头本质上在做局部处理，为它们保存远端 token 是不必要的风险与开销。这样问题就从「丢哪些 token」变成了「哪些头需要保留远端 token」，把一个高风险的一次性决策转化为一个可离线分析的结构性分工。

## 2. 核心洞察

两条洞察。第一，**头异质性是压缩的机会**：如果所有头都需要全量 cache，任何压缩都会伤害能力；但既然只有一部分头需要，就可以把压缩集中在不需要的部分，从而在保持能力的前提下省下大部分显存。第二，「丢弃之后还能补救」——补偿 token 用少量额外表示承载被丢弃远端 token 的聚合信息，缓解局部头因看不到远端而丢失的上下文。这一设计承认了「丢弃必然有损」，但试图把损失控制在可接受范围，与 P040 的「把误差集中到单一可度量环节」有异曲同工之处。

## 3. 方法机制

(1) 识别检索头（哪些头参与长距离召回）；(2) 检索头保留完整 KV cache，非检索头只保留近端 token 并丢弃远端；(3) 使用补偿 token 恢复部分被丢弃信息；(4) 实现上兼容 FlashAttention，因此不需要读取注意力矩阵、不引入额外开销。代价是：检索头的识别方式与稳定性决定上限；非检索头丢弃远端是永久性的（补偿只是部分恢复）；「多数头只关注局部」这一统计结论在不同任务/模型上的一致性需要证据。

## 4. 实验证据

跨多种 LLM 评测，KV cache 缩小 **70% 以上**而性能无明显影响；强调与 FlashAttention 兼容、可即插即用、无需重训练。摘要未给出具体基准名称与逐任务数值。

## 5. 第一性原理再审视

第一，与 P084（DuoAttention）与 P087（HeadKV-R2）的核心观察高度重合，三者的差异主要在「检索头如何识别」「被弃信息如何补偿」「是否分两类以上」。因此阅读时应把重点放在**识别方法与补偿机制的质量差异**上，而非「头异质性」这一已被多方验证的观察本身；论文（2024 年 7 月投稿）在时间上早于多数同类工作，但作为 2025 年收录的条目，其相对贡献需要在此语境下理解。第二，「70% 以上」是压缩比，而兼容 FlashAttention 与免训练是其真正的落地优势——这与 P042（KEYDIFF 同样避免注意力矩阵）属同一工程动机。第三，识别检索头的具体算法（是否基于校准数据、是否需逐模型重做）决定通用性，摘要未给出。第四，不同模型的头分布差异很大（MHA/GQA），在 GQA 下「头」的语义变化会影响分类的有效性。第五，补偿 token 是一种有损聚合，其收益与代价（额外的 token 预算）需要量化对比，否则无法判断它相对「多保留几个远端 token」是否更划算。

## 6. 与相邻工作的关系

与 P084（DuoAttention）、P087（HeadKV/HeadKV-R2）、P066（CateKV）同属头级压缩家族：DuoAttention 把流式头压成常数长度、HeadKV-R2 用检索+推理能力估计、CateKV 按时序一致性分类，RazorAttention 的特色是**补偿 token** 这一补救机制；与 P042（KEYDIFF，不依赖注意力矩阵、严格内存上界）在工程约束上一致；与 P045（KVzip，查询无关压缩）相比，RazorAttention 是查询相关但免训练。定位上属于头级压缩中加入信息补救的代表。

## 7. 可迁移点与开放问题

可迁移：(a) 「先判断哪些组件必须看全量信息，再只对不需要的组件压缩」是降低不可逆损失的通用原则，可推广到 MoE 路由与多分支网络；(b) 用少量补偿表示恢复被丢弃信息，是把有损操作变得可控的实用手法。开放问题：检索头识别的可迁移性与校准成本；GQA/MLA 下的适配；补偿 token 相对「多留 token」的性价比；与量化/低秩方法的组合；以及在需要跨远距聚合（而非仅召回）的任务上的保持率。
