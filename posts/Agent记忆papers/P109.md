# P109 Chain of Agents: Large Language Models Collaborating on Long-Context Tasks

- 会议/来源：NeurIPS 2024
- 方向簇：CTX
- 链接：/paper_files/paper/2024/hash/ee71a4b14ec26710b39ee6be113d7750-Abstract-Conference.html

## 贡献

提出 Chain-of-Agents（CoA）：用自然语言驱动的**多 agent 协作**来处理长上下文任务。框架由多个 worker agent 顺序通信、各自处理文本的不同分段，最后由 manager agent 汇总为统一输出。CoA 交错地「读」与「推理」处理整段输入，并通过给每个 agent 分配**较短的上下文**来缓解长上下文的注意力聚焦问题；在问答、摘要与代码补全上相对 RAG、Full-Context 与其它多 agent 方案最高提升 10%。

## 机制要点

论文的动机分析很清晰：两条主流路线各有一个盲区——输入缩减（RAG）**不保证**覆盖到含所需信息的片段；窗口扩展**不保证**能聚焦到相关信息。CoA 用分工回避这两个问题：每个 worker 只看一段短文本（聚焦容易），通过顺序传递的通信把信息聚合起来（覆盖完整）。等价地说，它把「让一个模型处理长上下文」转化为「让多个模型各自处理短上下文 + 通信」，从而把长上下文能力问题变成信息传递问题。

## 关键结果

在问答、摘要、代码补全三类任务上相对 RAG、Full-Context 与多 agent LLM 强基线取得最高 10% 的提升；框架适用于多种 LLM。

## 局限与定位

第一，成本结构是本方法的核心问题：顺序通信意味着**串行依赖**，总延迟随分段数线性增长，且每个 worker 的调用都要计费；摘要未给出成本/延迟对比，而这是与 RAG（单次检索）竞争的关键。第二，顺序传递会造成**信息瓶颈与误差累积**：早期 worker 若遗漏关键细节，后续无从补救，这与 P025 指出的「边读边记」的单向覆写问题同源；相比之下，允许回调或双向通信的架构（P025）可能更稳。第三，分段的边界是固定切分还是语义切分未被说明，而边界处的证据最容易被两个 worker 同时忽略（P039 与 P111 都指出「边界丢失」是压缩方法的典型失效模式）。第四，与 LongAgent 等多 agent 长文方案相比，CoA 的差别主要在于通信顺序与汇总方式，需要更细致的消融来说明「顺序 worker + manager」相对「并行 worker + 汇总」的优势来源。定位上属于「用协作替代压缩」这一路线，与 P020/P045 等压缩路线形成对照。
