# P134 Read As Human: Compressing Context via Parallelizable Close Reading and Skimming

- 会议/来源：ACL 2026（主会）
- 方向簇：CTX

## 一句话贡献

提出 RAM（Read As HuMan）：一个模拟人类阅读行为——**对重要内容精读、对次要内容略读**——的自适应混合上下文压缩框架。RAM 把上下文切分为段，与输入查询并行编码；高相关段被**完整保留（精读）**，低相关段被**查询引导地压缩为紧凑摘要向量（略读）**；随后把显式文本段与隐式摘要向量拼接送入解码器，从而同时获得性能与并行效率。

## 1. 问题与第一性原理动机

论文针对长上下文部署的两个障碍：计算低效与信息冗余。既有压缩方法的问题在于「非此即彼」——硬 token 压缩删除原文（不可恢复，P111 归纳的失效模式都与此相关），软 token 压缩把全部内容改写成连续表示（牺牲可读性与可引用性，P019 的 COMI 属于此类）。RAM 的判断是：**不同重要性的内容应当采用不同处理方式**，而不是对所有内容施加同一操作。这一判断的合理性来自人类阅读策略——精读与略读的混合，其信息论含义是让有限预算的分配与内容价值对齐。

## 2. 核心洞察

两条洞察。第一，**保真度应当是分级的**：高相关内容保持原文形式，既保住了精确召回能力（数字、实体、措辞），也让输出可以引用证据；低相关内容才允许有损压缩。这实际上回答了 P122 提出的「记忆—利用鸿沟」的一种应对：对最可能被使用的部分不做压缩，从而降低「需要展开」的负担。第二，**并行化**：把分段与查询的编码并行执行（而非顺序读取），使压缩阶段的延迟不随段数线性增长——这与 P109（CoA 的顺序 worker 串行通信）形成鲜明对比，说明「分段 + 汇总」这一结构可以用并行或串行两种实现，延迟特性差异巨大。

## 3. 方法机制

(1) 上下文切分为段；(2) 各段与输入查询并行编码，得到相关性；(3) 高相关段完整保留（精读）；(4) 低相关段做查询引导的压缩，生成摘要向量（略读）；(5) 显式文本与隐式摘要向量拼接后送入解码器。代价是：相关性判定决定保真度分配，误判会使关键内容被略读（而它一旦被压成向量就难以精确引用）；「精读」段的数量/比例需要与预算匹配；需要训练（含并行编码架构与摘要向量的对齐）。

## 4. 实验证据

论文报告 RAM 在长上下文任务上同时取得更优性能与更好的自然语言可读性/可引用性（论文强调「both superior performance and natural language ...」），并在并行效率上受益。具体压缩比、延迟与基准数值需回看正文。

## 5. 第一性原理再审视

第一，分级保真的核心风险是**判定错误的不可逆性**：若某个低相关段实际上包含关键证据（多跳任务中常见——单看与查询不相关，但与其它段组合后就关键），略读会把信息压成向量，之后的精确使用能力受限。这与 P019（COMI 的 query 相关性主导选择）遇到同样的结构性问题，而 RAM 通过「保留部分为原文」缓解了它，但未消除。第二，「精读/略读」的比例是一个新的超参，其最优值随任务的信息密度变化；论文需要给出该比例与任务类型的对应关系，否则难以部署。第三，并行编码意味着各段独立处理，段间的依赖（跨段指代、跨段因果）在编码阶段无法被利用——虽然解码器会看到拼接后的全部内容，但相关性判定本身已受限于段内信息。第四，可读性/可引用性这一优势值得强调：它是软 token 压缩方法的固有短板，RAM 保留了部分原文从而部分解决，但只对「被判定为精读」的段有效。第五，与 P122（用 RL 训练模型在生成中展开压缩表示）相比，RAM 用「保留原文」替代「学会展开」，是更保守也更可靠的路线选择。

## 6. 与相邻工作的关系

与 P019（COMI 的 query 相关软 token 压缩）在「按相关性分配压缩强度」上同构，但 COMI 全部转为软表示、RAM 保留高相关段的原文；与 P111（gist 压缩的失效模式）的三种失效（边界、惊奇、沿途）相关——RAM 的分级保真天然缓解「惊奇即丢失」（意外的关键内容若被判为相关则保留原文）与「边界丢失」（段被整体处理）；与 P118（按句间相似度动态切块）在「分段策略」上互补，RAM 的分段方式可与其结合；与 P109（顺序 worker）相比是并行实现；与 P113（面向检索的压缩）相比，RAM 面向生成并保留可引用性。定位上属于混合保真度的压缩框架。

## 7. 可迁移点与开放问题

可迁移：(a) 「对不同价值的内容采用不同保真度的表示」是压缩设计的通用范式，可推广到多模态（高清原图 + 低清缩略图）、代码（保留签名、压缩实现）、表格（保留表头与关键行）；(b) 使压缩阶段并行化以消除随段数增长的延迟，是长上下文系统的关键工程约束。开放问题：相关性误判的不可逆代价与补救；精读比例的自适应设定；段间依赖在编码阶段的缺失；压缩比与延迟的完整曲线；以及与 P122 式「可学习展开」路线的对比。
