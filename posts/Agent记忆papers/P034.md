# P034 Channel-Aware Mixed-Precision Quantization for Efficient Long-Context Inference

- 会议/来源：ICLR 2026
- 方向簇：KV
- 链接：/paper_files/paper/2026/hash/55f5aa8d997a8071d0651e0009ec49a2-Abstract-Conference.html

## 贡献

提出 ChanMix：面向 KV cache 的通道感知混合精度量化框架。出发点是量化敏感性在**通道维度上并不均匀**——除已被广泛利用的大幅值 outlier 通道外，还存在一批幅值小但同样脆弱的稳健通道（robust channels）；据此按通道敏感度做非均匀比特分配，支持 2-bit 的 channel-wise 量化并配套自研 Triton kernel。

## 机制要点

现有做法通常对 key cache 做 channel-wise、对 value cache 做 token-wise 量化，并统一使用相同比特宽度，在低比特下退化严重。ChanMix 保留这一「key 通道 / value token」的量化轴，但把比特预算按通道敏感度重新分配，让高敏通道拿到更多位宽、稳健通道降到极低比特。该设计要在 2-bit 下真正转化为速度与显存收益，依赖定制 kernel 的实现。

## 关键结果

在 NIAH、RULER、InfiniteBench 上，对 Llama、Mistral、Qwen 三族模型，ChanMix 相对所有基线在 RULER 上取得至少 5 个绝对百分点的提升（摘要），并称一致优于均匀量化。效率侧：支持推理时 batch size 提升 2.3×、上下文长度延长 1.5×。背景数据引用 Llama-3.1 每百万 token 需 125GB 显存。

## 局限与定位

外部效度被评测条件削弱：作者自述因实际限制排除或部分评估了若干基线（ZipCache 在超过 38K token 时 OOM，故只测 32K 以下；InfiniteBench 因预估执行时间超过一个月而被排除），这使部分结论只在较短上下文上成立。其次，「至少 5 个点」未区分比特配置与模型族，需回看正文表确认幅度一致性。第三，通道敏感度如何标定（是否需校准集、成本多少、换模型是否需重标定）属于部署关键细节，摘要未交代。定位上属于量化路线精修：相对 token 淘汰不丢信息，相对低秩/共享类方法不需架构改动，通用性更好，但压缩比上限受低比特量化误差约束。
