# P046 MPCache: MPC-Friendly KV Cache Eviction for Efficient Private LLM Inference

- 会议/来源：NeurIPS 2025（主会）
- 方向簇：KV
- 链接：/paper_files/paper/2025/hash/8c2df4c35cdbee764ebb9e9d0acd5197-Abstract-Conference.html
- 本地全文：cache/txt/P046.txt

## 一句话贡献

把 KV cache 淘汰搬到**安全多方计算（MPC）**语境下重新设计：指出明文场景的淘汰与稀疏注意力算法无法直接用于隐私推理，提出 MPCache——用「只看一次」的静态淘汰丢弃不重要 KV、再用查询相关的动态选择激活少量 KV 参与注意力计算，并配套 MPC 友好的相似度近似、分层聚类与跨层索引共享三项优化，使解码延迟降低 1.8–2.01×、通信量降低 3.39–8.37×。

## 1. 问题与第一性原理动机

MPC 下的 LLM 推理（用户与云各持一部分秘密共享）能提供形式化的隐私保护，但代价是每一步计算都要在密文上做交互，长输入序列的开销尤其不可接受。明文里的淘汰方法之所以**不能直接搬过来**，是因为它们依赖的算子类型不同：它们在明文里大量使用 softmax 归一化、注意力矩阵的精确比较、以及非线性打分；而这些在 MPC 中要么需要昂贵的协议（如密文上的比较、exp 近似），要么通信轮数爆炸。因此问题不是「把明文算法加速」，而是「重新设计一个能在密文算子集合下高效执行的淘汰算法」——这是一个被忽视但结构性的约束转换问题。

## 2. 核心洞察

论文的观察是：长序列中的历史 token 对后续解码的影响差别很大，因此可以分两阶段处理——**先粗筛、再精算**。粗筛用「只看一次」的静态淘汰，它不需要查询信息，因此可以在 prefill 阶段一次完成且不随解码反复执行；精算用 query-aware 的动态选择，只在每步注意力中激活一小部分 KV。这种「静态 + 动态」的分工之所以在 MPC 下特别合适，是因为它把昂贵且查询相关的操作限制在很小的子集上（降低通信量），而把大规模筛选交给廉价的一次性步骤。第二层洞察是：既然通信是主要成本，就应该用**索引**而非**数据**在各方之间传递——因此 hiearchical clustering 做粗粒度组织、cross-layer index sharing 让多层复用同一套索引，把「传输选中向量」变成「传输选中位置」。

## 3. 方法机制

MPCache 由四部分构成：(1) look-once 静态淘汰，丢弃不重要的 KV；(2) query-aware 动态选择，只激活少量 KV 参与注意力；(3) MPC 友好的相似度近似——用密文下可高效计算的算子替代精确相似度；(4) 分层 KV 聚类与跨层索引共享，减少索引构建与传输开销。方法在多种生成任务上优于先前的 KV 淘汰基线，报告的解码延迟降低 1.8–2.01×、通信量降低 3.39–8.37×（随序列长度变化）。代价是：相似度近似引入了额外的选择误差，静态淘汰的阈值与聚类参数构成新的调参面，而「MPC 友好」意味着算法设计空间被密文算子约束，可能与明文最优解存在差距。

## 4. 实验证据

论文称在多种生成任务上一致优于先前 KV 淘汰基线，并给出两组效率数字：解码延迟降低 1.8–2.01×、通信量降低 3.39–8.37×（不同序列长度下）。摘要未给出精度损失的具体幅度，也未列出评测任务集合与模型规模，需要回看正文判断「优于基线」是在何种预算与模型上达成。

## 5. 第一性原理再审视

第一，MPC 场景的**评价指标应当是通信量与轮数，而非仅仅是延迟**：论文报告了通信量降幅是好的，但也需要说明通信轮数（round complexity）是否同步下降——MPC 的实际瓶颈常常是轮数导致的网络往返延迟，而非字节数。第二，「MPC 友好」的相似度近似是可验证性最弱的一环：近似打分可能让淘汰决策偏离明文最优，而论文未给出近似误差与任务精度之间的定量关系。第三，静态与动态两阶段的分工中，静态淘汰是**不可逆**的，一旦误删就无法在动态阶段挽回；论文应给出静态淘汰预算的敏感性分析（若静态阶段保留更多，延迟与精度如何变化）。第四，跨层索引共享假设不同层的选择结果高度相关——这个假设在明文文献中已有讨论（例如 P039 报告 ChunkKV 的层间索引相似度更高），但在 MPC 下共享索引会同时泄漏层间的相关性信息，其对隐私保证的实际影响（是否削弱形式化安全）值得明确说明，而摘要未涉及。

## 6. 与相邻工作的关系

与 SnapKV、H2O、P037（Ada-KV）等文淘汰方法属于同一问题但受不同约束：那些方法在明文下自由使用 softmax 与精确比较，MPCache 必须在密文算子集合内重建等价逻辑；与 P042（KEYDIFF）有相似的动机——都试图避开某些不便获得的中间量（KEYDIFF 避免注意力矩阵以兼容 FlashAttention，MPCache 避免密文下的高开销算子）；与 P053（Spotlight Attention）同属「用近似检索替代完整注意力」，但一个求低延迟检索、一个求低通信。定位上属于隐私推理这一交叉方向。

## 7. 可迁移点与开放问题

可迁移：(a) 「先确认目标执行环境允许哪些算子，再设计算法」这一约束优先的设计范式，适用于 TEE、联邦学习、边缘 NPU 等所有受限执行环境；(b) 「传输索引而非数据」是把通信瓶颈从数据量转为元数据的通用技巧，可推广到分布式 KV 共享与多设备协同推理。开放问题：通信轮数是否同步下降；近似相似度的误差—精度曲线；静态淘汰不可逆带来的鲁棒性风险；跨层索引共享对形式化隐私保证的影响；以及与 P045 的查询无关压缩能否组合以进一步减少通信。
