# P094 SCBench: A KV Cache-Centric Analysis of Long-Context Methods

- 会议/来源：ICLR 2025
- 方向簇：BENCH
- 链接：/paper_files/paper/2025/hash/a540b17fb2295c736d5afd6c507acf66-Abstract-Conference.html

## 贡献

提出以 **KV cache 生命周期**为中心的评测基准 SCBench：把长上下文方法的评估拆成四个阶段——KV cache 的生成、压缩、检索与加载——因为既有基准多在**单次请求**设定下评测，忽视了真实使用中的完整生命周期。特别是 KV cache 复用已被 vLLM、SGLang 以及多家 LLM 服务商广泛采用，而现有评测未覆盖这一关键环节。SCBench 使用共享上下文的测试样例，含 12 个任务、两种共享上下文模式，覆盖四类能力：字符串检索、语义检索、全局信息与多任务。

## 机制要点

基准设计的关键是「共享上下文」：同一段长上下文被多个请求复用，因此方法不仅要处理一次性的压缩，还要在**多次请求之间**保持一致性与可复用性。这一点直接区分了此前无法区分的方案——例如查询相关的压缩在单请求下表现良好，但在多请求共享上下文时可能因为压缩时的查询偏好而损害后续请求。评测覆盖 8 类长上下文方案：门控线性 RNN（Codestral-Mamba）、Mamba-Attention 混合（Jamba-1.5-Mini），以及稀疏注意力、KV cache dropping、量化、检索、加载与 prompt 压缩等高效方法；在 6 个 Transformer 长上下文 LLM 上运行（Llama-3.1-8B/70B、Qwen2.5-72B/32B、Llama-3-8B-262K、GLM-4-9B）。

## 关键结果

论文的核心发现之一：**sub-$O(n)$ 内存的方法在多轮场景下表现受损**，而具 $O(n)$ 内存的稀疏编码配合 sub-$O(n^2)$ 的 prefill 计算则更稳健。这一结论为「压缩比越高越好」的常见假设提供了重要的反面证据。

## 局限与定位

作为基准工作，其价值依赖评测设计的中立性：任务与共享模式由作者定义，仍可能存在与特定方法族亲和的偏差；8 类方案的实现细节（各方法使用官方代码还是重实现）直接影响可比性，需要核实。此外「sub-O(n) 内存方法在多轮下受损」是一个重要的经验规律，但论文应给出机制解释（是压缩时的查询偏好导致，还是信息不可逆丢失？），否则难以指导方法设计。定位上，SCBench 与 P027（BEAM，叙事连贯的 10M 对话基准）互补：BEAM 关注长对话的记忆能力维度，SCBench 关注 KV cache 生命周期与服务模式；两者共同标志着该领域从「刷单请求指标」转向「按真实负载评测」。
