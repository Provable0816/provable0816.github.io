# P173 Prompt Compression with Context-Aware Sentence Encoding for Fast and Improved LLM Inference（CPC）

- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/34639

## 一句话贡献

把提示压缩从 token 级搬到**句子级**：训练一个 query-aware 的句子编码器对每个句子给出相关性分数，按分数保留句子，从而在更高压缩率下避免 token 级删除造成的语义碎裂，并显著降低压缩本身的计算开销。

## 1. 问题与第一性原理动机

token 级压缩有两个结构性代价。第一，**语义代价**：删除中间 token 会破坏句子内部句法与指代，压缩率越高越明显，因为压缩率的上限受限于「剩余 token 还能不能组成可读、可推理的文本」。第二，**计算代价**：许多 token 级方法需要一个语言模型对整段上下文逐 token 打分（前向一遍甚至多遍），压缩省下的推理成本可能被压缩过程本身吃掉——论文用延迟对比直接把这一点摆出来。这两个代价共同指向一个设计原则：**压缩粒度应当与语义单位对齐**，且打分器的成本必须低于被压缩掉的那部分推理成本。

## 2. 核心洞察

句子是天然的语义原子：以句为单位保留/丢弃，可以保证被保留下来的内容始终是完整可读的，也让压缩率以「句数」为粒度离散化。真正的技术难点不在粒度，而在**打分必须是「上下文 + 问题」条件化的**：同一句话在不同问题下的重要性完全不同，而静态句子嵌入（Sentence-BERT 一类）只编码句子本身。作者的判断是，用对比学习专门训练一个「给定问题、给每个句子打分」的编码器，可以让压缩器变得又小又快。

## 3. 方法机制

(1) **数据构造**：用 LLM 生成 (Question, Answer) 对并做校验，再为每个问题挑出**正样本句**（与问题相关）与**负样本句**（不相关但同处上下文），形成 CQR 数据集（Figure 2）；(2) **对比训练**：训练 context-aware sentence encoder $f_\theta$ 在该数据上学「问题—句子」相关性；(3) **推理压缩**：对上下文逐句打分，按分数保留前若干句，直到满足 token 预算 $\tau$。框架图见 Figure 1，示例打分见 Figure 4。代价：需要构造并维护一套训练数据；压缩粒度粗，在「关键信息只占半句话」的场景下可能过度保留；句子切分质量（跨句指代、列表、表格）会影响上限。

## 4. 实验证据

评测在 LongBench（单文档 QA、多文档 QA、摘要、少样本、合成、代码等子任务）与 ZeroSCROLLS 上展开，并在医学论文摘要等领域特定任务上补测。Table 1 的总览给出 LongBench 上的性能—延迟对照：CPC 50.0，LongLLMLingua 48.8，LLMLingua-2 42.2，LLMLingua 37.4；论文称相对最强 token 级方法最高 **10.93×** 推理加速（延迟对比另见 Figure 3）。Table 2 给出不同压缩率下的逐子任务结果，摘要强调「在较短长度约束下改进更明显」，Table 3、Table 4 分别报告领域任务与更大预训练模型下的表现，代码与数据已开源于 Workday/cpc。

**证据缺口**：(a) 延迟对比的口径需要细看——`1/τ`、Tokens 两列说明压缩后长度并不完全相同，**性能—延迟的公平对比需要固定 token 预算或固定延迟**，论文给了两列但读者需自行核对是否同口径；(b) 句子级压缩在「信息分布在跨句指代中」的任务（多跳、长文档摘要）上风险最大，论文的多跳结果（MuSiQue、HotpotQA、2WikiMultihopQA）是该主张的关键证据，需要逐项核验而非只看 AVG；(c) 训练数据由 LLM 生成并自行校验，存在**生成器分布偏置**，这会系统性决定哪些句子被学会认为「相关」。

## 5. 第一性原理再审视

句子级压缩把率失真问题从「token 的无序集合」变成「句子的有序集合」，带来一个隐藏假设：**信息的最小不可分单元是句子**。这个假设在摘要任务上大致成立，但在三类场景下失效：一是关键信息由句子之间的**推理链**构成（删掉中间前提则结论句变成噪声）；二是答案需要**跨句聚合**（比较、计数、时间线）；三是结构化内容（表格、代码、日志），其「句子」边界本就无意义。其次，对比学习学到的是「问题—句子」的静态相关性，而不是「该句子对最终答案的边际贡献」——这两者在多篇文档互相冗余时必须区分：一篇高相关但与另一篇重复的文档，其边际价值近零，而句级打分器没有去重机制（除非数据集里恰好含这类负样本）。从效率角度，该方法真正的优势是**压缩器小**而非「压缩率高」，因此它更适合作为「多级压缩管线中的第一级」（先句级粗筛，再 token 级精修）——论文本身也采用了粗到细流程，这一组合思路值得记住。

## 6. 与相邻工作的关系

与 LLMLingua / LongLLMLingua / LLMLingua-2 同属提示压缩，但粒度与打分器都不同：它们多是 token 级 + 语言模型打分，CPC 是句子级 + 专用小编码器。与 P172（AttnComp）互补：AttnComp 借任务模型的注意力打分但仍是 token 级，CPC 用独立小模型但工作在语义单位上。与 RAG 的 reranker（按段落打分）在思想上同源，区别是 CPC 处理的是**已被拼进提示的长上下文**，粒度更细、预算约束更硬。

## 7. 可迁移点与开放问题

可迁移：(a)「用对比学习专门训练一个廉价的相关性打分器，服务于预算受限的内容裁剪」是通用范式，可用于 agent 记忆检索、多轮历史裁剪、工具输出截断；(b) 分级压缩（粗粒度先筛、细粒度再压）在延迟—质量权衡上通常优于单级。开放问题：句级与 token 级的最优组合策略；跨句推理链的保持；去重与边际价值估计；以及压缩器对训练数据生成器偏置的鲁棒性。
