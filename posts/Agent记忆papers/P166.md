# P166 Interactive Episodic Memory with User Feedback

- 会议/来源：CVPR 2026
- 方向簇：AGENT
- 链接：/content/CVPR2026/html/Subedi_Interactive_Episodic_Memory_with_User_Feedback_CVPR_2026_paper.html

## 贡献

指出情景记忆的自然语言查询（EM-NLQ）中一个被主流方法忽略的现实问题：**用户的提问可能含糊或不完整**（例如「我把杯子放哪了？」可能指多个杯子），而现有方法都在**一次性（one-shot）设定**下作答，因此给出错误响应后无从挽回。论文提出 EM-QnF（Episodic Memory with Questions and Feedback）任务：用户可以就模型的初始预测给出**反馈**或补充信息（例如「在这之前，我找的是那个大的蓝色杯子而不是白的」），帮助模型**交互式地**修正预测；为此收集了基于反馈的交互数据集，并提出**轻量的训练方案**以避免昂贵开销。

## 机制要点

该工作的价值在于**任务定义层面的修正**：把「查询理解」从模型的内部不确定性转化为可以与用户协作消解的过程。这回应了多个工作共同指出的问题——P116（AgenticLU 让模型自问自答进行澄清，但澄清由模型单方生成）、P136（错误归因接地，模型用了错误来源的证据却无从察觉）、P128（语境不匹配的检索）都说明「问题本身不对」时系统无法自救；引入用户反馈是把这一外部信息变成可用的修正信号。第二个要点是「轻量训练方案」：交互式系统若依赖为每个反馈类型训练专用模块，工程成本会迅速上升，因此轻量适配是可行性的关键。

## 关键结果

论文报告在反馈式交互设定下的改进，并给出新数据集；具体指标与基线需回看正文。评估这类工作应关注**交互轮数的边际收益**（第几轮反馈后收益饱和）以及**用户给出无关或误导性反馈时**的鲁棒性。

## 局限与定位

第一，数据集中的反馈是**构造的**（模拟用户按剧本给出澄清），而真实用户的反馈更嘈杂、更不完整，甚至自相矛盾；从模拟反馈到真实交互之间的差距是这类工作最常被低估的鸿沟。第二，多轮交互意味着多次模型调用，延迟与成本随轮数增长，而「在哪里放杯子」这类问题往往期望即时回答；论文需要给出延迟数据。第三，反馈可能包含**用户自身的记忆错误**，模型若盲从反馈会引入新错误；需要机制判断何时不应采纳（这与 P129「事实与信念分离」的诉求相关）。第四，与 P116（AgenticLU 的自澄清）相比，一个用自提问、一个用用户反馈，两者在成本与准确性上有明确取舍：自提问无需用户参与但可能固化错误假设，用户反馈更准确但需要交互成本。第五，作为任务定义型工作，其影响取决于工业界是否采纳交互式设定。定位上属于情景记忆查询的交互式修正。
