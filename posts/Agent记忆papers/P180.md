# P180 Lethe: Layer- and Time-Adaptive KV Cache Pruning for Reasoning-Intensive LLM Serving

- 会议/来源：AAAI 2026（主会）
- 方向簇：KV
- 链接：https://ojs.aaai.org/index.php/AAAI/article/view/40036
- 本地全文：cache/txt/P180.txt

## 一句话贡献

把 KV 剪枝的「自适应」落实到两个正交维度：**空间**上按每层注意力冗余度分配 token 预算（layerwise sparsity-aware allocation），**时间**上在解码过程中做多轮剪枝，并用 Recency-Aware Selective Retention（RASR）把「近因」与「随注意力演化而来的相关性」结合，面向长链推理（长解码）而非长输入。

## 1. 问题与第一性原理动机

既有 KV 压缩几乎都把火力对准 **prefill 的长输入**，因为那里显存峰值最高。但推理模型（如 R1 蒸馏系列）的负载特征是**长解码**：思维链可产生数千到数万 token 的输出，KV 在生成过程中不断累积，显存与延迟随时间增长。论文用 Figure 1 的层×步注意力稀疏度热图给出关键观察：LLaMA-8B 上早层与晚层稀疏、中层稠密（与「层重要性均匀」的常识相悖）；同一模型上早层随时间变得**越来越稀疏**（选择性增强），而其它层波动（如图中第 13 层）。这意味着两层含义：(1) 统一的层间预算在原理上就是次优的；(2) 预填时算好的重要性在生成过程中会失效。更要紧的是，长链推理里「被淘汰的中间步骤」可能在后文被引用，因此剪枝的时机与依据必须随解码推进而更新。

## 2. 核心洞察

注意力冗余度是**层与时刻的联合函数**，而不是常量。因此最优压缩策略应当是一个随 (layer, step) 变化的两维预算分配问题。RASR 的设计体现了这一点：纯近因（recency）是一条廉价但粗糙的启发式，它在推理任务中恰好危险——思维链的早期步骤（定义、变量绑定）与近期步骤同样关键；RASR 因此把「近因」与「从演化注意力中得到的 token 相关性」结合，使保留集合既覆盖近期上下文又覆盖被反复注视的长期关键项。

## 3. 方法机制

(1) **层间稀疏度估计**：对每层估计注意力冗余（稀疏度），据此分配该层的 token 剪枝预算；(2) **多轮解码期剪枝**：不是一次性在 prefill 决定，而是在生成过程中周期性重排与裁剪 KV；(3) **RASR**：在每一轮保留决策中融合近因信号与注意力相关性信号；(4) 系统层面把上述策略实现为可用的 serving 组件（Figure 2、Figure 3）。代价：需要在解码过程中周期性重算重要性，带来额外计算与同步开销；超参（sparse ratio、recent ratio）需按任务调节，论文消融显示 sparse ratio 超过 400 后收益递减、recent ratio 取 0.3 为平衡点——说明策略存在明显的调参面。

## 4. 实验证据

模型为 DeepSeek-R1-Distill 系列的 Qwen-7B、Qwen-32B、LLaMA-8B、LLaMA-70B（70B 用 3 路模型并行；因硬件限制未测 671B 本体，以官方蒸馏模型作为代理）；基准为 Math500 与 MMLU（Table 1 给出与 PyramidKV、H2O、StreamingLLM、FullKV 的逐科目对照，含 abstract algebra、astronomy、college CS 等细项）。效率侧 Figure 4 给出延迟、生成期显存与吞吐随生成 token 数的变化曲线；Table 1 末段给出不同 batch size（1/4/8/16/32）下的吞吐，FullKV 在 batch 32 处 OOM，而 Lethe 可继续服务；摘要报告吞吐提升最高 2.56×。消融给出超参敏感性：sparse ratio 提升精度但边际递减，recent ratio=0.3 平衡连贯性与压缩率。

**证据缺口**：(a) 评测只覆盖数学推理（Math500）与知识类（MMLU），缺少**长链代码/多跳工具调用**这类「中间步骤被反复引用」的任务，而这类任务才是时序剪枝最容易伤到的地方；(b) 用蒸馏模型代理 671B 原模型，层间稀疏度结构可能不同，外推需谨慎；(c) 论文未报告「剪枝决策与错误答案之间的因果归因」（例如某道数学题失败是因为丢了哪一步），因此「不牺牲推理质量」只能在聚合分数层面成立；(d) 周期性重排的额外开销给出了曲线，但在 batch 很大时的调度成本未单独计量。

## 5. 第一性原理再审视

Lethe 把 KV 压缩的正确性问题识别为**时变预算分配**，这在方向上比「更聪明的静态打分」更接近本质：如果注意力分布本身随时间变化（Figure 2/P178 的经验事实），那么任何单一时刻的决定都只能是最优解的近似，多轮重排才是把误差摊平的合理做法。但多轮重排引入了一个新的失效模式——**剪枝的不可逆性与重排的滞后性叠加**：如果某 token 在 step 100 被删、在 step 2000 才被需要，再多的重排也无法恢复，Lethe 对此没有补救机制（对比 P178 用合并来保底）。第二个值得追问的假设是「近因 + 相关性」足以覆盖重要性：在推理中出现「长程变量绑定」时（早期定义要在很晚才被使用），两个信号的强度都随时间衰减，被剪掉的概率随时间单调上升。从信息论视角看，多轮剪枝等价于一个**逐步收紧的码率预算**，其最优策略依赖于对「未来查询分布」的预测；RASR 用启发式近似了这一预测，因此它的性能上界由启发式与真实未来的接近程度决定，而论文没有给出这一接近程度的度量（对比 P177 用注意力图对齐作为显式目标）。此外，层间冗余度的估计依赖校准数据，跨域稳定性同样未被检验。

## 6. 与相邻工作的关系

与 PyramidKV（层间金字塔预算）相比，Lethe 的预算依据是**实测冗余度**而非固定形状，并且叠加了解码期时序维度——PyramidKV 给的是静态层间分配，Lethe 给的是 (layer, step) 二维动态分配。与 StreamingLLM 的固定滑窗不同，RASR 是相关性加权的重排式保留。与 P177（Judge Q）互补：后者把 prefill 的打分器学准，前者把打分的时机动态化。与 P178（KeepKV）构成对照：Lethe 走「更聪明的删除」，KeepKV 走「删除改成降分辨率」。与 P179（KVmix）的 RPC 动态策略在「近期关键 token 保精度」这一点上异曲同工。

## 7. 可迁移点与开放问题

可迁移：(a) **把压缩预算建成 (层, 时间) 的二维函数**这一框架，可直接迁移到多轮 agent 的上下文管理——每轮对话的预算应当随对话阶段变化，而非固定窗口；(b) 用实测稀疏度而非先验形状分配预算，是可复用的工程原则。开放问题：剪枝不可逆性下的补救（与合并/摘要机制联动）；面向「工具调用/代码」等长程引用密集任务的评测；层间冗余度估计的跨域稳定性；以及把「重排周期」本身作为可学习量（何时重排与重排什么同样重要）。
