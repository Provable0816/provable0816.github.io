# P003 Cache What Lasts: Token Retention for Memory-Bounded KV Cache in LLMs

## 一句话贡献

提出 TRIM-KV：用轻量 retention gate 在 token **产生时**预测其长期内在价值（标量保留分，随时间衰减），内存预算超限时淘汰低分 token；通过从冻结 LLM 蒸馏 + 容量损失训练，仅微调 gate，在多个长任务上超过强 eviction/检索基线，甚至在某些数学任务上超过全缓存。

## 1. 问题与第一性原理动机

在固定显存预算下推理，长上下文的核心矛盾是：KV 缓存随长度线性增长，而注意力计算是内存带宽受限的。三条既有路线的结构性缺陷各不相同：量化/低秩压缩主要在 prefill 有效、随生成长度退化；offloading 保住了精度但引入持续的编排开销，端到端吞吐被 I/O 吃掉；KV eviction 最直接，却依赖「最近被关注的 token 长期也重要」这一不可靠代理——注意力分数是查询条件的（query-dependent），而淘汰是不可逆的。问题的本质因此不是「设计更好的启发式分数」，而是：能否把「长期有用性」变成一个**可学习、与查询无关、在 token 创建时即可估计**的量。

## 2. 核心洞察

token 的内在价值应当在其生成时刻由模型自身状态决定，而不是事后由某个查询的注意力反推。TRIM-KV 让每个 layer/head 配备一个 retention gate，为 token 输出标量保留分 $\beta_{t-i}$，并令其随时间衰减，从而把「能活多久」与「当前是否被关注」解耦。容量超限时淘汰保留分最低者，缓存恒等于预算大小。这个视角的副产品是：学到的分数会自发复现人类已知的启发式（attention sink、sliding window、A-shape），说明这些启发式是同一目标下的特例，而非彼此竞争的方案。

## 3. 方法机制

框架为：在 token 生成处并行计算 retention 分数（每层每头独立），分数随相对位置衰减；推理时按预算 $M$ 保留 top-$M$ 分数 token，形成 eviction 决策 $\alpha_t^i$。训练不更新 LLM 主干，仅用前向 KL 蒸馏对齐冻结模型的注意力输出，再加一个**容量损失** $L_{\text{cap}}$ 强制压缩，以及 next-token 预测项 $L_{\text{NTP}}$；训练开销与推理开销都很小（论文称 gate 微调、推理开销可忽略）。设计代价是：gate 需要逐模型训练（无法直接迁移到新模型），且「价值」的定义继承自蒸馏目标，若下游任务分布与训练数据差异大，分数的语义可能失配。

## 4. 实验证据

模型：Qwen3-4B、Phi3-mini-128K；基准：GSM8K、MATH-500、AIME24、LongProc、LongMemEval、LongBench-V2、SCBench。关键数字：AIME24 在 4096 token 预算下 pass@1 = 75.8，而全缓存 32768 预算为 65.5（Table 5）；LongBench-V2（chunk-prefill, Phi3-mini-128K）Full KV 28.79、LocRet 28.03、TRIM-KV 34.09（+18.41%）（Table 4）；LongProc 上 TRIM-KV@2048 达 96.5/93.5/66.5/49.3/18.0（Table 1）；SCBench 各子任务中多为 eviction 方法中最佳（Table 2）。消融（Table 5）：去掉 $L_{\text{cap}}$ 后 pass@1 从 75.8 崩到 42.9，去掉 KL 为 72.1、去掉 NTP 为 72.5——容量损失是压缩能成立的必要条件，而蒸馏项贡献相对温和。

**证据缺口**：(a) SCBench 的 Retr.KV（长程精确检索）子任务上 Full KV 为 66.00，TRIM-KV 为 0.00——与 StreamingLLM/H2O/SnapKV 同为零分，说明可学习价值函数并未解决「精确召回被淘汰 token」这一类任务，而摘要的「整体优越」叙事没有强调这一点；(b)「超过全缓存」只在数学推理等少数设置成立，且与「压缩即正则」的解释混在一起，缺少独立验证（例如同一模型多种子、不同训练数据重训）；(c) 训练依赖从冻结模型蒸馏，gate 与主干的协同被冻结参数限制。

## 5. 第一性原理再审视

该方法的隐含假设是：token 的长期效用可由其**创建时刻**的局部状态无偏预测。这在两类情况下天然失效：一是长程依赖（后文出现的关键实体改变了早期 token 的意义），此时任何 query-agnostic 的分数都是先验，必然漏掉条件重要性；二是精确检索任务，需要的是全保真存储而非压缩，价値函数无法凭空恢复被丢弃的信息——SCBench Retr.KV 的 0.00 正是这一失效条件的直接证据。从信息论看，「保留 top-$M$」是固定速率的有损编码，能否成功取决于冗余度：冗余高则压缩近似无损（数学题中大量 token 可复现），冗余低（唯一标识符、人名、数字）则无损不可能，这也是它超过全缓存的真正原因——不是因为保留更聪明，而是因为丢弃噪声减少了干扰，这一「正则」解释若成立，则在同一数据上做随机等量丢弃应给出相近结论，而论文未做此对照实验。

## 6. 与相邻工作的关系

与 H2O / SnapKV / StreamingLLM 等基于注意力统计的 eviction 属于同一技术脉络，区别是分数由学习得到而非由观测注意力得到；与 LocRet 这类「可学习但依赖查询」的检索/淘汰方法相比更彻底地摆脱 query 依赖；与 KV 量化、offloading 路线互补而非竞争。

## 7. 可迁移点与开放问题

可迁移的是「把缓存管理转化为一个带容量约束的学习问题」这一形式化：容量损失使压缩率可控，蒸馏使价值函数与主干对齐，两者组合可用于任何需要在预算内保存历史中间状态的系统（多轮 agent 记忆、检索增强管线）。开放问题：能否把 retention 机制纳入预训练/后训练，使注意力本身围绕保留分设计（论文列为未来工作）；如何在需要精确召回时切换到无损存储的混合模式；价值函数对分布偏移的鲁棒性如何度量。
