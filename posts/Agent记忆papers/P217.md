# P217 dKV-Cache: The Cache for Diffusion Language Models

- 会议/来源：NeurIPS 2025（主会）
- 方向簇：KV
- 链接：https://openreview.net/forum?id=db0ee27cb50dd9087b133f6e7d28a90e
- 本地全文：cache/txt/P217.txt

## 贡献

回答一个范式性问题：扩散语言模型（DLM）的非自回归结构 + 双向注意力**天然排斥** KV cache，那么 cache 还能不能用？论文给出延迟（delayed）且条件化的缓存策略 **dKV-Cache**，用两个变体覆盖不同取舍——dKV-Cache-Decode（近无损加速，甚至在长序列上提升性能）与 dKV-Cache-Greedy（激进缓存、生命周期更短、加速更高但性能有损），实现 2–10× 推理加速，且**免训练**。

## 机制要点

动机来自「不同 token 在扩散过程中的表示动态不同」（Figure 2：LLaDA 在 $L=128$、$T=128$、block size 64 下，关键状态跨时间步的成对相似度热图，以及相邻步之间的欧氏距离分析）。据此设计「延迟」机制（Figure 1）：在第 $t$ 步不立即启用刚解码出的 token $D_{t-1}$ 的缓存，而是把 K/V 延迟到下一步再排序复用——这与自回归 cache 的即时复用形成对照，是对双向注意力的适配。Greedy 变体进一步缩短缓存寿命并限制窗口，换取更高加速。

## 关键结果

在 LLaDA-8B-Instruct（Table 1，zero-shot）与 Dream-Base-7B（Table 2，few-shot ICL）上评测，覆盖通用语言理解、数学推理与代码生成；Table 3 专门报告**长 prefill** 设置（dKV-Cache-Decode 刷新步为 4，dKV-Cache-Prefill 从不刷新），其中「不刷新」的变体在长序列上仍然可用。配置：Decode 刷新步 8、Greedy 刷新步 2（窗口大小见表内括号）。一个有趣的现象是 Decode 变体在长序列上**提升**性能，论文解释为现有 DLM 在推理时可能未充分利用上下文信息，缓存间接起到正则/稳定作用。

## 局限与定位

第一，「加速与近无损」的代价是 Decode 变体需要周期性刷新，刷新步是核心超参（8 vs 4 在不同实验里不同），缺少该超参的完整敏感性曲线。第二，「缓存反而提升长序列性能」这一反直觉结论需要谨慎解读：它可能反映 DLM 在长上下文下的表示不稳定（缓存降低了噪声），也可能是评测配置所致，论文对此的解释属于假设而非已证机制。第三，Greedy 变体以二次时间复杂度的窗口换取速度，说明该方法在「更快 vs 更准」之间存在可调面，工程上需要按任务选点。定位上，它与 P185（Sparse-dLLM 双向动态淘汰）、P202（Fast-dLLM v2 的层级缓存）、P203（FlashDLM 的 FreeCache）共同构成本方向对扩散 LLM 的四条并行探索；其独特性在于提出「**延迟**」这一与自回归 cache 相反的时序复用规则，反映了双向注意力下的结构性差异。
