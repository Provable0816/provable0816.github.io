## 摘要

上一版的核心判断（该方向无统一 leaderboard、应按子赛道理解 SOTA、2025 年从删 token 走向治理状态、2026 年转向可恢复与按结果诊断）经本次核验基本成立，但**证据基础需要两处重要修正**：一是上一版遗漏了直接检验「1M 窗口 + 压缩」这一场景的关键实证工作，导致结论偏乐观；二是若干自报数字存在口径错配或限定条件丢失。

本次共核验 66 条文献与基准条目，全部 arXiv 编号、标题、日期、摘要级数字均已回查原始页面；新增 30 余篇上一版未覆盖的论文，其中 3 篇发表于 2026-11-04 至 11-06、真正构成本次时间上的「增量」。最重要的新证据有三组：

1. **1M 窗口下，压缩阈值对任务表现几乎无影响，但压缩会静默删除不可重建的约束。** Salle 等（2026-10-22）在固定 OpenCode scaffold、5 种压缩策略、4 个前沿模型、3 个长程基准上发现：两个 1M 上下文模型在 160K–380K 各压缩阈值下准确率无显著差异，且**没有任何压缩方法优于默认自摘要**；但 ProgramBench 首次压缩即平均丢掉约 1/3 的反作弊规则并随压缩次数单调累积，真实 SWE-chat 会话中「如何工作 / 不该做什么」类指令被丢弃频率约为「要构建什么」的 6 倍 [30]。作者据此提出「当前基准是 compaction-friendly 的」——目标固定、进度落盘，压缩丢掉的大多能恢复，**唯独只存在于上下文中的约束不能**。
2. **完成率是一个系统性失真的指标。** Liu（2026-08-17）用 24 轮确定性工具环境做受控测量：5× 压缩点上所有模型任务完成率变化均不显著，但 GPT-5.5 的重获取工具调用从 21.0 增至 63.9（p=.002），完成率反而 80%→85%（p=1.0）[28]。Chen（2026-06-21）在 1,323 个 episode、7 个模型族上测得：约束在全上下文中时违规率 0%，压缩后升至 30%（部分模型 59%），约束存活于摘要则仍为 0%、被丢弃则 38% [26]。Zerhoudi 等（CIKM 2026）测得 Claude Code `/compact` 在 Sonnet 4.6 上一轮压缩后仅保留 53% 安全规则、五轮后 10% [29]。
3. **「压缩后超过全量」是真实且可解释的现象，不是数字错误。** ReCAP 在 Lost-in-Conversation 代码任务上相对全历史 +19.8 / +41.2 个百分点 [8]，SelfCompact 在 HMMT Feb 26 上相对 No Compaction +18.1 分 [27]，MEMENTO 在 2.5M token 书籍 QA 上以 ≤20K 上下文达 67.8%，超过全书籍上下文 56.7% [31]。原因是长全量历史本身带来注意力稀释与上下文干扰，且多数基准的进度可从磁盘重建。这恰恰说明「接近全量」不是信息论等价命题，而是**在给定任务分布、预算与失败代价下的帕累托前沿**。

对「有上下文长度限制的记忆上下文压缩方法研究」，本次给出的核心判断是：该方向的算法增量空间正在收窄（简单观察屏蔽已能减半成本 [12]，约束固定已能把违规率打回 0% [26]，默认自摘要已不被任何新方法超越 [30]），**真正的空白在度量与失效边界，不在又一个压缩器**。可切入的问题应落在「会话依赖型约束的在线保真」「重获取成本感知的预算决策」「抗 compaction-friendly 的评测基准」「恢复预算受限时的可寻址召回」四条上，具体研究路径见第 9 节。

## 1. 研究边界、场景形式化与证据口径

### 1.1 场景定义

本报告严格限定为：**在调用大模型 API 之前**，对 Agent 在多轮对话、工具调用与任务执行中累积的对话历史、观察结果、工具返回、推理轨迹与中间记忆，进行选择、删减、摘要、结构化、外置与按需召回，使活跃上下文远小于模型窗口上限（如 1M tokens），同时尽量保持接近全量上下文的任务效果。

|                                                                                            |     |          |
| ------------------------------------------------------------------------------------------ | --- | -------- |
| 可形式化为：设第 t 轮累积轨迹为 H_t，窗口上限 W，压缩算子 C 输出活跃上下文 c_t = C(H_t, q_t, B_t)（q_t 为当前请求，B_t 为预算），目标是在 | c_t | ≪ W 下最小化 |

L = ΔTaskEffect + λ₁·ΔConstraintSurvival + λ₂·ReacquisitionCost + λ₃·(1 − CrossRunReliability)

其中 ΔTaskEffect 必须相对**同一个未压缩全量基线**测量。这一形式化把「效果」拆成四个可分别证伪的量，是本报告相对上一版在口径上的主要推进。

### 1.2 三条必须分开的边界

| 边界              | 属本报告主体              | 不属主体                                     | 理由                    |
| --------------- | ------------------- | ---------------------------------------- | --------------------- |
| 调用侧 vs 模型侧      | 改写送进 API 的 token 序列 | KV cache 逐出/量化、gist/软 token、LoRA 编译、权重量化 | 前者黑盒可用；后者需读注意力或改权重    |
| 上下文压缩 vs 长上下文架构 | 对累积历史做治理            | RoPE 缩放、稀疏注意力、位置外推                       | 后者只扩大 W，不解决历史累积与跨请求重发 |
| 压缩 vs 上下文适配     | 把历史变短               | ACE 式增量 playbook（明确「不压缩」）                | 两者目标不同，混列会污染比较 [3]    |

一个典型误置是上一版把 ACBench 作为「压缩口径」提示 [42]：该文评测的是 **GPTQ/AWQ 量化与 Wanda/SparseGPT 剪枝**对 Agent 能力的影响（4-bit 在 workflow/tool use 掉 1%–3%、real-world application 掉 10%–15%），与上下文压缩无关，本次移入「口径澄清」而非主体。

### 1.3 三个不可混用的「全量」

文献中「full context」至少指三件不同的事，跨论文比较时必须标注：

- **F1 全量轨迹入 prompt**：H_t 原样送入，是压缩方法的正确对照组（ACON、CCM、PAIR、SelfCompact、Observation Masking 使用）\[1\]\[7\]\[10\]\[12\]\[27]。
- **F2 全量模型能力/全书籍上下文**：把整个输入一次性给长窗口模型（MEMENTO 的 56.7%、ReCAP 的 LiC full history）\[8\]\[31]。F1 与 F2 在长程 Agent 中常不同：F1 会因累积噪声劣于压缩。
- **F3 全量轨迹落盘可恢复**：压缩只影响活跃 prompt，原文仍在磁盘（Compaction-Friendly 的 filesystem offloading、ReCAP、CWL）\[8\]\[25\]\[30]。**F3 下「无损」是工程事实而非压缩算法功劳**，这是理解「基准 compaction-friendly」的关键。

### 3.1 2025 上半年：记忆从摘要变成可组织对象，状态从文本变成策略

#### [4] A-MEM: Agentic Memory for LLM Agents

- **时间**：2025-02-17（v1），NeurIPS 2025，v11 修订至 2025-10-08
- **问题设定**：现有记忆系统只有存储与检索，缺组织；固定操作与结构无法跨任务自适应
- **核心方法**：Zettelkasten 式原子笔记（上下文描述、关键词、标签）+ 自动链接生成 + 记忆演化（新笔记触发旧笔记属性更新）
- **主要改进点**：压缩粒度从「最近 N 轮」变为「笔记 + 边」，让跨轮约束与失败经验可串联；不改生成模型权重
- **实验数据与指标**：6 个基础模型，LoCoMo 等长期对话基准；全文给出每次操作约 1,200 tokens、区间 1,200–2,500 tokens，对比 LoCoMo/MemGPT 的 16,900 tokens（85%–93% 降低），商业 API 下每次操作 < $0.0003，时延 5.4s（GPT-4o-mini）/ 1.1s（Llama 3.2 1B）
- **相对全量的效果损失**：**未报告与全量上下文的直接对比**；上述是资源与召回口径，不是压缩比或效果差
- **适用场景**：长期对话记忆、跨会话用户偏好、需复用的经验
- **局限**：链接本身是模型生成物，多轮写回会形成陈旧依赖；图膨胀后检索/合并/一致性检查变贵；未评测量化后的信息丢失

#### [6] LightThinker: Thinking Step-by-Step Compression

- **时间**：2025-02-21（v1），EMNLP 2025 oral，v2 2025-09-23
- **问题设定**：推理链自身不断生成 token，占满上下文与显存
- **核心方法**：训练模型学会「何时 / 如何」把冗长思考压成 gist token，专用注意力掩码丢弃原始链；提出 Dependency (Dep) 指标量化对历史 token 的依赖度
- **主要改进点**：压缩决策由模型在生成中学习，而非外部规则；把软压缩从「文档」推进到「推理过程」
- **实验数据与指标**：4 个数据集、2 个模型；报告 peak memory 与推理时间下降、精度保持竞争力
- **相对全量的效果损失**：**未报告统一效果差**；口径为「competitive accuracy」
- **适用场景**：自营可训练模型、数学/推理密集任务
- **局限**：必须训练并绑定对应模型与 gist 表示；状态不可读、精确证据难还原；**黑盒 API 不可用**

#### [5] MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents

- **时间**：2025-06-18（v1），v2 2025-07-17
- **问题设定**：full-context prompting 无界追加历史，导致内存增长、成本上升、超出训练长度后推理退化

- **问题设定**：服务系统在百万 token 会话中只保留小 KV 预算；已有逐出方法都假设「后续需要的 token 仍在缓存中」就够
- **核心方法**：证明这个假设不成立 —— 需要的是**旋转位置距离**有界。PACE = plan-aware retention（Agent 的 planner 告知缓存未来步骤会读哪些上下文）+ bounded positions（重编号保留 token，使其到 query 的 rotary 距离在任意会话长度下 <8K）
- **主要改进点**：把「保留哪些 token」推进到「保留的 token 是否仍可被检索到」；重编号是精确的、无可测困惑度代价
- **实验数据与指标**：Qwen3-8B，100K-token 编码会话、2,048-token 预算，planner-guided 策略在 residency **0.996** 下准确率随「定义→使用」距离从 2K 增至 90K 而 **93%→64%**；预注册新任务上 PACE 100K 通过 **97%** 隐藏单测，H2O 42%、SnapKV 3%，单独任一组件 63%（组合 p<10⁻⁴）；1M / 2M-token 会话（单张 24GB GPU，定义在 0.9M / 1.8M token 前写入）通过 99% / 100% 检查、召回全部会话事实，而「bounded positions 无 foresight」从 33% 跌到 13%；KV 状态 <0.7GB vs 全量 147–295GB；重编号 +9% wall time；Mistral-7B 上 PACE 保持其 40% 能力上限
- **相对全量的效果损失**：不是「压缩 vs 全量 prompt」而是**模型侧 KV 路线**；但它给出一条对本报告场景极重要的反证：即使把「需要的 token」几乎全部留住（residency 0.996），长距离下仍会失效 —— 说明**单纯扩大窗口或提高保留率并不能保证信息可用**
- **适用场景**：自托管推理系统、超长编码会话；黑盒 API 不可用
- **局限**：需 planner 配合与 KV 层控制权；单作者、单模型族为主；与调用侧压缩是互补而非替代关系

### 5.3 三条使「接近全量」不可判定的结构性原因

1. **基准 compaction-friendly** [30]：目标固定、进度留在磁盘，压缩丢弃的内容大多可从环境恢复；因此任务成功率对压缩不敏感，而**只存在于上下文中的约束**（反作弊规则、行为禁令、用户否定）成为唯一真实损失。任何只报完成率的评测都会系统性低估风险。
2. **完成率与交互成本解耦** [28]：5× 压缩点上完成率无显著变化而 retrieval calls 约 3 倍。若 API 成本按工具调用计费，压缩实际更贵。
3. **全量本身不是金标准** \[8\]\[27\]\[30\]\[31]：长全量历史会因注意力稀释、上下文干扰与位置距离 \[34] 而劣于选择性上下文。因此「压缩后超过全量」不应被当作异常或作弊，也不能反过来证明压缩无损。

### 6.2 从这张表能得出的四个具体结论

1. **效果损失的方向高度依赖任务与保真维度，不存在「统一压缩率—损失」曲线。** 同一 ACON 在 AppWorld 两个变体上是 +0.5pp 与 −4.8pp，在 WebVoyager 是 +12.9pp；同一 Observation Masking 在 Qwen3-Coder 是 +1.4pp、在 Gemini Flash (thinking) 是 −4.0 至 −9.0pp。任何「压缩后保持 95% 性能」的宣称都必须绑定模型、任务、阈值三个坐标。
2. **「压缩后优于全量」有四种不同机制，不能混为一谈**：(a) 全量历史的注意力稀释/干扰（ReCAP、SelfCompact、ACON WebVoyager）；(b) 进度可从磁盘重建（Compaction-Friendly 类基准）；(c) 全量指的是 F2 全书籍上下文而非 F1 全量轨迹（MEMENTO）；(d) 压缩产物本身是更好的结构化状态（ReCAP 依赖图、SelfCompact 及时清理）。只有 (a)(d) 是算法贡献。
3. **最严重的风险不出现在完成率维度，而出现在约束与交互成本维度。** Governance Decay 的 +30pp 违规率、Compaction Cliff 的五轮后 10% 规则存活、Interaction Costs 的 retrieval 3 倍增长，都发生在完成率不变的前提下。这意味着**以完成率为唯一指标的压缩研究，其「无损」结论在方法论上不成立**。
4. **可恢复性决定损失是否可逆。** ReCAP（持久图）、CWL（效果落盘 + 依赖图）、Compaction-Friendly 的 filesystem offloading、RLM（变量引用）、PACE（位置重编号）都把「不可逆删减」改为「可重新选择/重新访问」，因此在长程上损失更小甚至为负；而纯摘要法（ACON ut、CCM 无训练版、ReSum）一旦丢失精确值即不可恢复。这是 2026 年最清晰的分野。

## 7. 演进关系与适用边界

### 7.1 三条主轴

**轴一：决策粒度** —— token（LLMLingua-2 [39]）→ 句子/观察块（Observation Masking [12]、SWE-Pruner [20]）→ 轮次/轨迹（ReSum [2]、ACON [1]、Slipstream [24]）→ 结构化状态（MEM1 [5]、CWL [25]、RE-TRAC [21]）→ 失败事件与压缩边界（PAIR [10]、ACON 的失败对）→ 信息类型/承诺原子（Governance Decay [26]、Compaction Cliff [29]、Commitments [23]）。粒度上升的本质是：**从「文本里哪些字重要」变成「哪些信息对后续执行与合规不可替代」**。

**轴二：优化信号** —— 困惑度/重要性 \[39\]\[40] → query 相关性 \[20\]\[36] → 执行反馈与蒸馏 \[1\]\[3] → 终局奖励传播 \[2\]\[5\]\[22] → 同状态反事实分叉 \[10] → 类型化保真可验证性 \[23\]\[26\]\[29]。信号从「文本统计」走向「因果与规范」，这是 2025→2026 最实质的范式变化。

**轴三：信息可恢复性** —— 不可逆删减（token 抽取、周期摘要）→ 原文外置 + 按需召回（A-MEM [4]、filesystem offloading [30]、CWL [25]）→ 持久依赖图可重新选择（ReCAP [8]）→ 软残差补充未知需求（REMORY [9]）→ 程序化递归访问（RLM [18]、PACE [34]）。**2026 年的共识是：压缩不是删除，是给信息换一种可寻址的存在形式。**

## 9. 面向「有上下文长度限制的记忆上下文压缩方法研究」：现状、挑战、问题与路径

### 9.1 研究现状：五条可证伪的判断

1. **算法增益空间已明显收窄。** 在真实前沿模型 + 真实长程任务上，**没有任何压缩方法超过默认自摘要** [30]；零模型调用的观察屏蔽已能减半成本且多数配置效果不降 [12]；约 47 个 token 的约束固定已能把显式约束违规率从 30% 打回 0% [26]。因此「再设计一个更高压缩率的摘要器」的边际贡献很低。
2. **压缩的收益主要来自「清除噪声」与「可恢复性」，不是「信息编码得更密」。** 压缩后超过全量的案例 \[8\]\[27\]\[31] 可由注意力稀释、进度落盘、结构化状态三者解释；ReCAP 的持久图 \[8]、CWL 的依赖驱逐 \[25]、RLM 的变量引用 \[18] 共同说明可寻址性比压缩比更重要。
3. **失效面已从「任务做不成」转移到「做得成但违规 / 做得成但更贵 / 这次成下次不成」。** 完成率不变的三个反证：违规 0%→30% [26]、retrieval 21.0→63.9 [28]、可靠性先于可解性恶化 [10]。
4. **1M 窗口改变了问题性质而非消除了问题。** 阈值在 160K–380K 间对 1M 模型不敏感 [30]，但约束仍逐次丢失；PACE 进一步证明哪怕 KV 保留率 0.996，位置距离增长仍使准确率 93%→64% [34]。因此研究目标应从「避免溢出」转为「在长窗口下保证约束可用与状态可寻址」。
5. **评测生态是最大短板。** 缺少同时报告完成率、约束存活、重获取成本、跨运行可靠性、恢复率@预算、压缩器自身开销的统一基准；AgentMemBench [11] 只覆盖对话记忆检索，Compaction-Friendly [30] 直接指出主流基准对压缩过于友好。

### 9.2 关键挑战（每条给出「难在哪 + 现有证据 + 未解决点」）

| #  | 挑战                 | 难在哪                                             | 现有证据                                                                                             | 未解决点                                                              |

| C1 | **约束的非对称保真**       | 不同信息类型对「措辞精度」的敏感度差一个数量级；统一压缩率必然把规则和日志同率摘要       | /compact 一轮保留 53%、五轮 10% [29]；约束存活则违规 0%、丢弃则 38% [26]；ProgramBench 首轮丢 1/3 规则 [30]               | **会话依赖型 / 隐式约束**（其约束性随上下文变化）无法离线分类；[29] 自述此类需在线判定但超出范围            |

### 9.3 可切入的研究问题（含可证伪假设、最小实验与判据）

以下 6 个问题按「与现有工作的差异边界」排序，每个都明确写出**什么结果会推翻它**。

#### RP1：会话依赖型约束的在线识别与保真（最高优先级）

- **问题**：现有 Constraint Pinning [26] 与 Knowledge Triage [29] 都要求约束可离线抽取为可引用规则。但真实约束常是「在第 12 轮用户说『这个目录下不要用 rm』」这类**作用域与会话状态绑定**的指令，其约束性依赖后续上下文。
- **可证伪假设 H1**：在约束作用域随会话漂移的任务上，静态 Pinning 的违规率显著高于「作用域在线判定 + 条件固定」；且后者的固定 token 开销 < 活跃上下文的 1%。
- **最小实验**：以 ConstraintRot [26] 的确定性 tool-call grading 为底，扩展出「作用域型 / 条件型 / 可撤销型」三类约束 × 9 任务 × 至少 3 个模型族；对照 full-context control、默认自摘要、静态 Pinning、本文方法；主指标违规率，副指标 pinned tokens、允许动作完成率、过度拒绝率。
- **判据**：若三类约束下静态 Pinning 已达 0% 违规，则 H1 被推翻，应转向 C2/C7；若作用域型出现 ≥15pp 差距，则成立。
- **差异边界**：不是再做一次 Pinning，而是把「可抽取」假设去掉，并显式处理撤销与作用域收缩。

#### RP2：以重获取成本与可靠性为联合目标的预算化压缩决策

- **问题**：[22] 把压缩做成预算 MDP 但需 RL 且目标仍是任务回报；[28] 测出 reacquisition cost 但没有把它变成优化目标；[27] 的 rubric 只看执行状态不看恢复代价。
- **可证伪假设 H2**：在固定 API 预算下，以「完成率 − λ·retrieval calls − μ·(1−Pass³)」为目标的免训练触发策略，在相同成本下比固定阈值/rubric 策略取得更高跨运行可靠性。
- **最小实验**：复用 [28] 的 24 轮确定性环境与 [27] 的 6 基准；实现三种触发（固定阈值 / SelfCompact rubric / 本文代价感知）；扫 λ、μ 与预算 B；报告帕累托前沿、Holm 校正显著性、3 次独立运行的 Pass³。
- **判据**：若代价感知策略只在单一环境优于基线、在 ALFWorld 类环境无差异，则 H2 只在特定环境成立，需明确声明适用边界（这正是 [28] 的教训）。

#### RP3：压缩事件的低成本因果归因与在线自愈

- **问题**：PAIR [10] 的反事实分叉是离线、需可回滚环境、每个 boundary 一次 PRE/POST 对（AppWorld history 为 133 boundaries / 464 rollouts / 52.04M tokens）。
- **可证伪假设 H3**：用「压缩前后状态卡的结构化差分 + 后续 2–3 步的轻量探针」可在不使用完整反事实 rollout 的情况下，以 ≥80% 的召回率定位有害压缩边界，成本降至 PAIR 的 1/10 以下。
- **最小实验**：在 PAIR 已发布的 AppWorld / OfficeBench 边界标注上做离线对照，再在可 checkpoint 环境做在线 A/B；指标为有害边界召回率、误报率、额外 token、跨运行可靠性。
- **判据**：若召回率 <70% 或误报导致过度回滚，则放弃，转为纯评测工具。

#### RP4：恢复预算受限时的可寻址召回

- **问题**：ReCAP [8]、CWL [25]、filesystem offloading [30] 都假设原文可取回，但**恢复本身要花 token**，且 [8] 未量化图的开销。
- **可证伪假设 H4**：存在最优的「活跃摘要 : 恢复预算」分配比例，且在恢复预算 < 峰值上下文 10% 时，依赖图式选择（ReCAP 式）显著优于 top-k 语义检索；把图开销计入后优势仍成立。
- **最小实验**：SWE-Together [65]、LiC [59]、LoCoMo [57] 三类任务；扫恢复预算 0/2%/5%/10%/20%；方法为 top-k 检索、ReCAP 式依赖选择、CWL 式驱逐；报告 Recovery Rate@budget、任务分、总 token（含图/索引）。
- **判据**：若计入图开销后优势消失，则结论应写成「可恢复性收益被索引成本抵消」，这本身是有价值的负结果。

#### RP5：抗 compaction-friendly 的评测基准与统一报告规范

- **问题**：[30] 论证主流基准目标固定、进度落盘，压缩丢的多半能恢复；[11] 的 harness 只用单模型静态日志。
- **可证伪假设 H5**：构造「约束仅存在于上下文 + 进度不可从环境重建 + 需跨轮否定/反事实分支」的任务后，现有全部免训练压缩方法（自摘要、观察屏蔽、offloading、ReCAP 式选择）与全量基线的差距会从「不显著」变为 ≥10pp 或规则存活率 ≤60%。
- **最小实验**：基于 AppWorld / τ²-Bench 改造，注入三类不可重建信息；至少 4 个前沿模型 × 5 种策略；统一报告 8 项指标（完成率、约束存活、retrieval calls、Pass³、Peak/Total tokens、Latency、API Cost、Recovery Rate@budget）。
- **判据**：若 H5 不成立（差距仍不显著），则说明压缩风险被高估，研究应转向成本优化 —— 这是一个诚实且有用的结论。
- **价值**：基准 + 报告规范本身就是可发表贡献，且直接服务后续所有工作。

#### RP6：跨模型/跨版本的压缩器漂移检测与免重训迁移

- **问题**：ACON 的指南由 GPT 系优化 [1]、REMORY 绑定冻结 LLM [9]、PAIR 模板适配后跨模型迁移只是单点验证 [10]、SUMONE 声称跨 harness 迁移 [32] 但只报单一绝对下降。
- **可证伪假设 H6**：压缩器的「信息保留质量」随目标模型版本单调漂移，而用无下游标签的 masked-reconstruction 分数可在不跑任务的情况下预测 ≥70% 的效果方差。
- **最小实验**：同一批压缩产物跨 5+ 模型/版本评测，拟合重建分数与任务分的秩相关；对照组为 ACON 蒸馏、PAIR 迁移、SUMONE checkpoint。
- **判据**：若相关性弱（Spearman <0.4），则说明压缩质量不可迁移，应改为「每模型校准」，并给出校准所需最小样本量。

### 9.5 最小可发表工作（MVP）定位

若只做一个工作，建议组合 **P0 + P1 + RP1 + RP5**，标题方向为「*约束不可重建条件下的上下文压缩：失效画像、在线保真与抗友好基准*」。理由：

- **空白明确**：\[26\]\[29] 解决了显式可抽取约束，\[30] 指出了基准友好性，但两者之间「会话依赖约束 + 不可重建进度」这个交叉格无人填；EMNLP 2026 综述 \[55] 的 F2（In-compression Information Loss）与 F3（Post-compression Access Failure）正好提供术语基座。
- **差异边界清晰**：不做新压缩器、不做 RL、不做软 token；贡献是「保真层 + 评测」，与 ACON/ReSum/ReCAP/MEMENTO 不重叠。
- **可证伪、可负结果**：静态 Pinning 可能已经够用，若实验推翻 H1/H5，结论「简单约束固定足以覆盖绝大多数生产场景」同样有价值，且能纠正当前过度研究的倾向。
- **黑盒 API 直接可用**：全部组件免训练、可插拔，符合用户场景定义。

### 9.6 反证与风险（Devil's Advocate）

必须正面回应的四条最强反对意见：

1. **「1M 窗口使压缩不再必要」** —— [30] 显示阈值对 1M 模型不敏感，某些场景确实可以不压缩。**回应**：本研究的价值不在避免溢出，而在 (a) 成本（重发全量历史的 prefill 费用仍随轮数线性增长，[7] 显示 Total input 451,006→76,126）、(b) 约束保真、(c) 位置距离导致的可用性衰减 [34]。研究问题须写成「长窗口下的上下文治理」，而非「窗口不够用」。
2. **「简单方案已经足够」** —— 观察屏蔽 [12] 减半成本、Constraint Pinning [26] 把违规打到 0、默认自摘要不被超越 [30]。**回应**：因此 P1 的失效画像必须先行，且论文定位应是「界定简单方案的失效边界」而不是「提出更强算法」。这是一条诚实且更有说服力的叙事。
3. **「压缩后超过全量说明全量基线选错了」** —— \[8\]\[27\]\[31] 的负损失可能只是 F1/F2/F3 口径混用。**回应**：本报告 §1.3 已把三种「全量」分开；后续实验必须同时报告 F1 全量轨迹与 F3 落盘可恢复两个对照，否则不得使用「接近全量」表述。
4. **「自报数字不可横向比较」** —— ACON 用 gpt-4.1、PAIR 用 GPT-5.6 Luna、CCM 用 Claude/GLM/Kimi、AgentMemBench 用 4-bit Qwen2.5-7B，且压缩器自身开销、judge 开销、图存储开销多数未计入。**回应**：本报告第 4/6 节的数字全部标注出处与口径，不给跨论文排名；后续研究必须在自己 harness 内重跑全部基线，禁止引用他表数字当基线。

## 10. 结论

近两年该方向最实质的进步，不是某个压缩算法取得统治性压缩比，而是**问题被重新定义了三次**：2025 年从「删哪些 token」变为「为下游失败与执行反馈而压缩」\[1\]\[2\]\[3]；2026 年上半年变为「压缩是否可验证、约束是否被保真」\[24\]\[26\]\[27\]\[29]；2026 年下半年变为「在 1M 窗口下，压缩的代价究竟发生在哪个维度、且是否可恢复」\[8\]\[28\]\[30\]\[34]。

对用户的目标「压缩到远小于 1M 且接近全量」，本次调研给出的具体结论是：**在固定任务分布与显式约束可固定的条件下可以做到，且在若干基准上压缩反而优于全量；但这不是信息论等价，而是有前提的帕累托结果。** 可操作的最小组合是：不可变原文归档 + 约束固定层（约 47 tokens，\[26]）+ 结构化状态卡 + 观察屏蔽/依赖图按需召回 \[8\]\[12\]\[25] + 关键约束直传 + 冷恢复预算；必要时才调用摘要器，且必须用 Slipstream 式异步验证 \[24] 或 SpecCompact 式并行加速 \[33] 控制延迟。**明确不应做**的是：为 1M 模型调优压缩阈值 \[30]、把治理约束交给自摘要 \[26\]\[29]、以完成率作为唯一验收指标 \[28]。

面向「有上下文长度限制的记忆上下文压缩方法研究」，最值得投入的不是新压缩器，而是 **约束保真的在线化、完成率之外的代价度量、抗 compaction-friendly 的评测基准、恢复预算受限下的可寻址召回** 四条；研究路径应按 P0 度量 → P1 失效画像 → P2 保真 → P3 决策 → P4 可恢复 → P5 基准泛化推进，每阶段设可放弃判据。若 P1 发现简单方案已覆盖绝大多数格子，应及时转向成本与可靠性优化并如实报告负结果 —— 这比再发表一个「峰值 token 降低 X%」的压缩器更有价值。

### D.1 目标论文

**Read As Human: Compressing Context via Parallelizable Close Reading and Skimming（RAM）**，Tang 等 12 人，arXiv:2602.01840（v1 2026-02-02 / v2 2026-02-27），**ACL 2026 Long Papers pp.28393–28406**（[arXiv](https://arxiv.org/abs/2602.01840) ／ [ACL Anthology](https://aclanthology.org/2026.acl-long.1309/)）。方法：query 与分段上下文并行编码，高相关段原样保留（精读）、低相关段压成 summary vectors（略读），拼接显式文本与隐式向量送 decoder，用对比学习细化分流边界。Table 1（LLaMA-3.1-8B，4×）AVG F1 **46.98**，对照 Activation Beacon 43.48、Provence 42.55、EXIT 42.53、Original Prompt 37.55、LongLLMLingua 38.11、ICAE 30.43；Table 2 端到端延迟 RAM 0.20–0.43s vs EXIT 约 302s / Original 1.23s。摘要自报最高 12× 加速，但 Table 2 未注明比较对象，引用须标口径。
