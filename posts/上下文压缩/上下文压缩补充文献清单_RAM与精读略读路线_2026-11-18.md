**问题设定**：长上下文推理的两个瓶颈 —— 自注意力二次复杂度、自然语言信息冗余。已有 task-aware 压缩要么一次性载入整段输入，要么自回归式逐段压缩，两者都把压缩本身变成效率瓶颈。

**核心方法**：把上下文切成 segment，与 query **并行编码**；query-guided attention 给每段打相关性分 → 高相关段**原样保留**（close reading，显式文本、可解释），低相关段压成 **summary vectors**（skimming，隐式表示）；两者拼接送 decoder；用正负 query–segment 对的**对比学习目标**细化「精读 / 略读」决策边界。保留段数由压缩比经公式推导。

**实验数据与评价指标**（均来自 v2 HTML 全文）：
- Backbone：LLaMA-3.1-8B-Instruct、Qwen3-4B-Instruct；压缩约束 4× / 8×（训练时每样本从 {2,4,8,16,32} 随机采样压缩率）
- 数据集：NaturalQA、2WikiMQA、HotpotQA、NarrativeQA、MultiNews；指标 EM / F1（MultiNews 仅 F1）；训练从五个数据集**各采样 20,000 条**、截断至 20K token、segment size 50、τ=0.1、8×H800
- **Table 1，AVG F1（LLaMA-4× / 8×；Qwen-4× / 8×）**：RAM **46.98 / 42.17 / 47.94 / 42.14**；Activation Beacon 43.48 / 39.73 / 未测 / 未测；Provence 42.55 / 39.11 / 40.12 / 37.05；EXIT 42.53 / 36.94 / 40.70 / 35.50；Original Prompt 37.55 / — / 40.13 / —；LongLLMLingua **38.11 / 33.19 / 32.98 / 27.79**；LLMLingua-2-large 35.39 / 29.15 / 31.38 / 24.57；ICAE 30.43 / 30.44 / 21.68 / 21.85；Closed-book 18.40 / — / 17.94 / —
- **Table 2，端到端延迟（秒，NarrativeQA，平均 16K / 最大 32K，Qwen3-4B；压缩 2×→32×）**：RAM **0.43 / 0.29 / 0.24 / 0.22 / 0.20**；Original Prompt 1.23；LongLLMLingua 25.17 / 11.37 / 7.61 / 5.84 / 5.14；Provence 3.04→2.75；EXIT 约 302（各档几乎不变）
- 摘要口径「up to **12×** end-to-end speedup」：**Table 2 本身未给倍数、也未注明比较对象**。按表内数字，RAM 0.20s vs Original 1.23s 约 6×、vs LongLLMLingua 5.14s 约 26×、vs EXIT 302s 约 1500×。引用「12×」时应标注为作者自报且口径未明。

**与用户场景的关系**：RAM 处理的是**单段长输入（16K–32K）的 query-aware 压缩**，不是 Agent 在多轮/工具调用中累积的历史治理；且需要训练 encoder-decoder 与生成 summary vectors，**黑盒 API 不可直接使用**。按主报告 §1.2 的边界，它属于「模型侧软压缩 / 单段输入压缩」，应作为**支线对照与关键基线来源**，而不是塞进 Agent 侧 SOTA 榜单。这一点必须说清，否则补检会破坏原有口径的一致性。

## 3. 补充检索的做法与证据边界

1. **Backward**：读 `arxiv.org/html/2602.01840v2` 的 §2 Related Work 与全部 51 条 bibitem，提取 30+ 条压缩相关条目及其在原文中的分类。

3. **作者组**：追 Tang / Hai-Tao Zheng / Bo Zheng / Runsong Zhao 组 2024–2026 的压缩论文，确认 `Tang et al. 2025a` = Perception Compressor、`Tang et al. 2025b` = GMSA。

## 5. 与主报告的关系：该补什么、不该补什么

**不该补**：把 RAM 直接加进第 4 节「统一比较矩阵」或宣布它是 Agent 侧新 SOTA。它压的是单段 16K–32K 输入、产出模型内部向量、需要端到端训练，与主报告 §1.2 的排除条件一致。强行并入会污染「黑盒 API 可用」这一核心口径。

**必须补**（主报告因此前的检索策略而真实缺失的内容）：
1. **前史表的引用条目**：Selective Context、LLMLingua、RECOMP、AutoCompressor、Gist Tokens、LLoCO、Activation Beacon —— 主报告 §3.0 只有名字没有链接和数字，而这些是 ACON / PAIR / ReCAP / SUMONE 四篇共同引用的基线。
2. **query-aware / soft 压缩支线章节**：RAM、HyCo2、GMSA、Perception Compressor、COMI、QGC、CPC、CompAct、EXIT、Provence、BRIEF-Pro、Sentinel 构成一条 2023→2026 完整链路，主报告完全空白。这条链路恰好是「按相关性分派保真度」的技术源头。
3. **两条真正的时间增量**：CoMem（2026-11-12，比 PACE 晚 6 天）与 PIR（EMNLP 2026，无 arXiv ID，只能靠 ACL Anthology 找到）。
4. **Agent 侧 KV compaction 反证**：Practical Online KV Cache Compaction for LLM Agents（2608.00902）与 EpiCache（2509.17396），前者直接给出「立即压缩常损害表现、延迟压缩可挽回」的实证，应进入主报告 §9.2 C3。
5. **共同引用基线**：TACO-RL（ACON + PAIR 双引）、LongBench（基准表缺项）、Shi 2023（解释「压缩后优于全量」的源头）。
6. **综述章节**：主报告 §8 列出 Prompt Compression Survey [49] 与 Transformer Context Extension [50]，但未把它们的覆盖范围与上述基线逐条挂钩；补检后可把 §8.3 的「仍未被覆盖」判断收窄 ——「按相关性分派保真度」在综述 [49][50] 中已有位置，但在 **Agent 侧综述 [55] 中仍未与约束保真打通**，这才是真空白。

## 6. 对研究结论与路径的影响（三处需要修正或加强）

1. **§7.1 轴一「决策粒度」应补一条并行演化**：Agent 侧从 token → 轨迹 → 状态 → 失败事件 → 信息类型；模型侧从 token 重要性 → query 相关性 → **精读/略读分流（按相关性分派保真度）** → 性能下限驱动。两条线在 2026 年汇合于同一思想：**不是所有信息都该用同一个保真度压缩**。这使主报告 §9.3 RP1（会话依赖型约束的在线保真）有了跨子赛道的桥 —— 把 RAM 的「相关性分流」升级为「约束关键性分流」，并显式处理 RAM 未覆盖的「撤销 / 作用域收缩」。
2. **§1.6 效率指标应强调「压缩器自身延迟」**：RAM Table 2 给出极端对照 —— EXIT 约 302s、LongLLMLingua 5.14–25.17s、RAM 0.20–0.43s，而 Original Prompt 仅 1.23s。也就是说**某些压缩方法比不压缩更慢**。这与 ACON [1] Table 4（成本降但延迟 73.24s→87.68s 上升）、Slipstream [24]（压缩占端到端延迟 26%–44%）、SpecCompact [33] 的动机完全一致，应作为一条独立结论写入。
3. **§6.2 结论 2「压缩后超过全量」的机制清单应补两项**：(e) 训练目标直接优化「相对未调优全上下文 RAG」（DEX-Comp 16× 超过全量）；(f) 无关上下文干扰被显式建模（Shi 2023 的早期发现、SeCo 的位置偏差解释）。同时保留原有警告：RAM 的 12× 与 46.98 F1 是 **16K–32K 单段 QA**，不能外推到 1M token 的 Agent 轨迹。
