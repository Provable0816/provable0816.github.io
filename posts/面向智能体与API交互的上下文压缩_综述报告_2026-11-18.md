## 摘要

智能体在多轮对话、工具调用与任务执行中持续累积对话历史、观察结果与中间记忆，总上下文可能超过模型原生窗口（如 1M tokens）。本报告要回答的问题是：能否在接近窗口上限前把活跃上下文压缩到远小于上限，同时保持接近全量上下文的任务效果。

近两年最清晰的进步不是某个算法取得统治性压缩比，而是**问题被重新定义了三次**。2025 年，决策对象从 token 变为轨迹、状态与失败事件；2026 年上半年，优化目标从「文本保留得好」变为「约束是否被保真、压缩是否可验证」；2026 年下半年，评测焦点从「任务完成率」转向「完成率之外的代价与可恢复性」。两条原本平行的子赛道 —— 调用侧**上下文压实**（compaction，黑盒 API 可插拔）与模型侧**上下文压缩**（compression，需训练的软表示）—— 在 2026 年汇合于同一思想：**不是所有信息都该用同一个保真度处理**。

对目标问题的具体回答是：**在固定任务分布、显式约束可固定、进度可从环境恢复的条件下可以做到，且在多个基准上压缩反而优于全量；但这不是信息论等价，而是有前提的帕累托结果。** 最严重的损失并不出现在完成率维度：约束在压缩后被静默删除（违规率 0%→30% [25]）、重获取工具调用成倍增加（21.0→63.9 [27]）、安全规则五轮压缩后仅存 10% [28]。因此「接近全量」必须在给定预算、任务分布与失败代价下，用「任务效果差 + 约束存活率 + 重获取成本 + 跨运行可靠性 + 恢复率@预算」联合刻画，而不能用单一压缩比或完成率宣称。

研究层面，算法增益空间已明显收窄：零模型调用的观察屏蔽已能减半成本 [12]，约 47 个 token 的约束固定已能把显式约束违规率打回 0% [25]，在真实前沿模型上没有任何压缩方法超过默认自摘要 [29]。**真正的空白在度量与失效边界，不在又一个压缩器。**

## 1 研究背景与目的

### 1.1 场景定义与形式化

本报告的场景严格限定为：**在调用大模型 API 之前**，对智能体累积的多轮对话、工具调用与返回、推理轨迹、文件与中间记忆，进行选择、删减、摘要、结构化、外置与按需召回，使活跃上下文远小于窗口上限 $W$（如 1M tokens），同时尽量保持接近全量上下文的任务效果。下面给出后文贯穿使用的形式化定义。

**（1）轨迹与状态。** 以「第 $t$ 轮 API 调用」为时间锚点。设该轮调用结束后产生的一批交互单元为

$$U_t = (q_t,\, a_t,\, e_t,\, \dots)$$

其中 $q_t$ 为当前用户请求，$a_t$ 为模型回复/动作，$e_t$ 为工具返回与环境观察，省略号含计划与中间记忆；若需元素级粒度可写 $U_t = (u_{t,1}, \dots, u_{t,k_t})$。第 $t$ 轮**调用前**已有的历史为

$$H_t = (U_1, \dots, U_{t-1}), \qquad H_{t+1} = H_t \oplus U_t$$

即 $H_t$ 含前 $t-1$ 轮的全部产物，**不含本轮 $U_t$**，因此 $q_t \notin H_t$；$\oplus$ 为序列拼接。$q_t$ 是第 $t$ 轮的当前输入，调用结束后才随 $U_t$ 归档进 $H_{t+1}$ —— **同一份内容在两个时刻有两种角色**：调用时是条件/输入，归档后是历史元素，$C$ 中出现的是前者。设 $W$ 为模型原生窗口上限，$B_t$ 为本轮 token 预算，$A_t$ 为不可变原文归档，$R_t$ 为可寻址索引（向量库、依赖图或 ID 日志）。

**（2）压缩算子与活跃上下文：三类算子**

压缩算子按「触发时是否有当前请求 $q_t$」与「产物是文本还是软表示」分为三类。三者的**输入、产出与公式各不相同**，不能共用一个 $C$。下表为总览；逐类的形式化与解释见随后三个小节，触发条件、代表工作与风险对照见 §1.2。

| 类别 | 是否有 $q_t$ | 算子与产出 | 送入模型 | 黑盒可用 | 公式 |
| --- | --- | --- | --- | --- | --- |
| **I 任务无关**（命令式 / query-agnostic） | 否 | $s_t$ 通用摘要（I-a / I-b 两变体） | $s_t$ 与后续任意请求拼接 | 是 | 式 2a |
| **II 任务相关**（请求驱动 / query-aware） | **是** | $c_t = C(H_t,q_t,B_t,A_t,R_t)$，条件化历史视图 | $\operatorname{prompt}_t = c_t\oplus q_t$ | 是 | 式 2b / 2b′ / 2b″ |
| **III 模型侧**（软表示，边界对照） | 可选 | $z_t = C_\theta(H_t,\cdot)$，向量 / gist / soft token | $\pi(a\mid z_t,q_t)$ | 否 | 式 2c |

三类共享同一条长度约束：$\operatorname{len}(c_t)\le B_t\ll W$，且**仅当 $B_t<\operatorname{len}(H_t)$ 时触发压缩**；当 $\operatorname{len}(H_t)\le B_t$ 时 $c_t=H_t$（不压缩）—— 这正对应「接近窗口上限前才压缩」的场景定义。$B_t$ 同时出现在 $C$ 的**输入**（预算条件化：同一算法须按预算输出不同长度）与约束**右端**（硬可行域上界），两种含义见 (4) 后注记。

#### I 任务无关压缩（式 2a）

I 类按**是否建立可寻址索引**再分两个变体 —— 二者都**无 $q_t$**（下标 $\varnothing$ 强调无查询条件），差别在归档与恢复能力：

| 变体 | 公式 | 输入 | 代表 | 压缩后可恢复 |
| --- | --- | --- | --- | --- |
| **I-a 纯摘要式** | $s_t=C_{\varnothing}(H_t,B_t)$ | 仅 $H_t,B_t$；**无 $A_t$、无 $R_t$** | `/compact` [28][29]、LLMLingua-2 [64]、RECOMP [66] | 否 |
| **I-b 归档 + 索引式** | $s_t=C_{\varnothing}(H_t,B_t,A_t,R_t)$ | 含不可变归档 $A_t$ 与索引 $R_t$ | filesystem offloading [29]、CWL [24]、A-MEM [4]、EKV [11] | 是（需恢复预算） |

$A_t$ 与 $R_t$ 在逻辑上**配套**：归档若无索引即不可寻址。I-b 的 $R_t$ 在**写入时**按结构组织（依赖图、笔记链接、ID 日志），不依赖当前请求；II 则是**每请求用 $q_t$ 沿 $R_t$ 选择**。因此「有无 $R_t$」不是 I / II 的分界，「有无 $q_t$」才是 —— 这也是式 2a 当初漏写 $R_t$ 的原因：把索引误当成了 query-driven 召回的专属配件。

| 项 | 说明 |
| --- | --- |
| 压缩对象 | 截至此刻的**全部历史** $H_t$，含此前所有用户消息、工具返回与推理 |
| 产出 | 通用摘要 / 活跃视图 $s_t$，**替换** $H_t$（I-b 另保留 $A_t$ 与 $R_t$） |
| 流程 | 触发（`/compact` / 定时 / 轮次间）→ 整体压缩 → 输出 $s_t$ → 替换 $H_t$ → 后续任意请求复用 |
| 复用 | 一次压缩、多次复用，成本摊到多轮 |
| 代价 | **I-a 最严重**：无归档可恢复，约束丢失最多（一轮丢 47% 安全规则 [28]、违规率 0%→30% [25]）；I-b 可缓解，但需付出恢复预算 |

#### II 任务相关压缩（式 2b、2b′、2b″）

$$c_t = C(H_t,\, q_t,\, B_t,\, A_t,\, R_t)$$

$$\operatorname{prompt}_t = c_t \oplus q_t, \qquad q_t \notin \operatorname{dom}(C_{\text{lossy}})$$

**式 2b′ 中三个记号的定义**（此前正文仅以中文「不参与有损压缩」表述，未给形式化定义）：

| 记号 | 本文档定义 |
| --- | --- |
| $\operatorname{dom}(\cdot)$ | 函数的**定义域**。此处指算子允许处理的输入单元集合；对有损算子而言，即「可能被删减 / 改写的候选集」，由式 2b″ 具体给出 |
| lossy（有损） | 产物**无法反推原文**的变换：token / 句剪枝、抽象摘要、软向量压缩、KV 逐出（对应 [29] 的 *lossy by design*）。相对地，$\operatorname{verbatim}$ 原样保留、不可变归档 $A_t$、索引 $R_t$、直传窗口 $H_t^{\text{recent}}$ 属**保真 / 无损**通路 |
| $C_{\text{lossy}}$ | $C$ 中承担有损变换的**子算子**，不是与 $C$ 并列的独立函数；$C$ 的其余部分为保真通路。二者共同构成式 2b 的 $C$ |

| 项 | 说明 |
| --- | --- |
| 输入 | 历史 $H_t$ + **当前请求 $q_t$** + 预算 $B_t$ + 归档 $A_t$ + 索引 $R_t$ |
| 角色划分 | $H_t$ 是**被压语料**，$q_t$ 是**条件**（数据 vs 条件，类比 query 与 corpus）；$B_t/A_t/R_t$ 是资源参数 |
| 压缩对象 | $H_t$ 中与 $q_t$ 相关的部分保留、不相关部分压掉；**$q_t$ 本身不参与有损压缩** |
| 流程 | $q_t$ 到达 → 预算检查 → 用 $q_t$ 给 $H_t$ 分块打分/选择 → 拼 $\operatorname{prompt}_t$ → 调用 → 归档本轮轨迹 |
| 产出与复用 | 每请求重算的条件化视图 $c_t$；$q_t$ 原样直传 |
| 代价 | query 改写偏差；压缩器自身延迟（EXIT 约 302s [54]）；若误压 $q_t$ 会直接改写任务语义 |
| 代表 | LongLLMLingua [63]、RAM [54]、ReCAP [8]（完整见 §1.2） |

**II 的常见分解（含「最近一轮」直传）**：工程中常把 $H_t$ 末尾若干轮划为免压缩窗口 $H_t^{\text{recent}}$（观察屏蔽 [12]、CCM [7]、SelfCompact [26]），此时

$$c_t = \underbrace{C_{\text{lossy}}\!\left(H_t^{\text{cand}},\, q_t,\, B_t\right)}_{\text{历史有损压缩}} \oplus \underbrace{\operatorname{verbatim}(\Gamma_t)}_{\text{约束固定}} \oplus \underbrace{H_t^{\text{recent}}}_{\text{最近窗口直传}} \oplus \underbrace{\operatorname{Recover}(A_t, q_t)}_{\text{按需召回}}$$

$$H_t^{\text{cand}} = H_t\setminus\bigl(\Gamma_t\cup H_t^{\text{recent}}\bigr), \qquad \operatorname{dom}(C_{\text{lossy}})=H_t^{\text{cand}}\subseteq H_t$$

由 (1) 的 $q_t\notin H_t$ 与上式 $\operatorname{dom}(C_{\text{lossy}})\subseteq H_t$ 可**直接推出** $q_t\notin\operatorname{dom}(C_{\text{lossy}})$。因此式 2b′ 的右半句不是额外假设，而是一条**推论与不变量**：当前请求进入 $C$ 的输入、决定 $H_t^{\text{cand}}$ 中哪些块被保留，却不进入有损变换。

**这一条件对任务相关压缩的三点影响**：

1. **任务语义不变**：$q_t$ 定义「本次要做什么」；若被有损改写，其中的约束、否定、精确 ID 与格式要求会被删改，压缩前后不再是同一任务。
2. **指标可比**：$\pi_{\text{full}}$ 与 $\pi_C$ 必须面对同一个 $q_t$，$\Delta_{\text{task}}$ 才可解释（见 (3)）。
3. **条件 ≠ 对象**：这解释了式 2b 中 $q_t$ 出现却与 $H_t$ 不构成重复；反之若按 chat API 约定有 $q_t\in H_t$（口径说明 3），必须显式写 $C_{\text{lossy}}\bigl(H_t\setminus\{q_t\},\,q_t,\,\cdot\bigr)$ 才能恢复同一不变量。

$H_t^{\text{recent}}$ 是**历史 $H_t$ 的被豁免子集**（上一轮及之前产物），不是本轮新增；记作 $U_t$ 会造成时间索引错位。

#### III 模型侧软压缩（式 2c，边界对照）

$$z_t = C_\theta(H_t,\,\cdot), \qquad \pi(a \mid z_t,\, q_t)$$

| 项 | 说明 |
| --- | --- |
| 输入 | 历史 $H_t$（可含 $q_t$），由可训练编码器 $C_\theta$ 处理 |
| 产出 | 向量 / gist token / soft prompt / 紧凑 KV，**不是可读文本** |
| 送入模型 | $\pi(a\mid z_t,q_t)$，要求模型能消费软表示 |
| 黑盒可用 | **否**（需训练或白盒注意力 / KV 访问） |
| 代价 | 状态不可读、跨模型不可迁移、精确证据难还原 |
| 代表 | ICAE [65]、AutoCompressor [67]、Gist Tokens [68]、Activation Beacon [58]、HyCo2 [53]、RAM [54]、REMORY [9] |

按 §1.2 边界，III 不进入本报告的调用侧效果排名，仅作**基线来源与术语源头**。

#### 口径与实现说明（三类通用）

1. **$q_t$ 与 $H_t$ 不相交**：按 (1) 的约定 $q_t\notin H_t$（$q_t$ 是 $U_t$ 首元素，调用后才归档进 $H_{t+1}$），故式 2b 中二者不构成重复。$U_t$ 在第 $t$ 轮调用之后才产生，既非被压对象也非压缩输入。
2. **$q_t$ 的三层角色**：① 作为**条件输入**进 $C$ —— I 否、II 是，这是两类的本质区别；② 作为**被压对象**（即属于 $\operatorname{dom}(C_{\text{lossy}})$）—— 主流设计两类都否，定义见式 2b′ 下方与式 2b″；③ 计入**预算 / prompt** —— II 当前轮原样出现，$\operatorname{len}(c_t)+\operatorname{len}(q_t)\le B_t^{\text{prompt}}$。故「$q_t$ 纳入压缩范围」应理解为「参与决策、不参与有损压缩」。
3. **另一种实现约定**：若按 chat API 惯例先把当前 user message 追加进 messages 再压缩（此时 $q_t\in H_t$），须显式排除条件项，写成 $c_t=C\bigl(H_t\setminus\{q_t\},\,q_t,\,\cdot\bigr)$，否则自指。两种约定等价但**必须二选一**；本报告采用 $H_t$ 不含当前请求。
4. **$q_t$ 的双重身份**：在 (1) 中是 $U_t$ 首元素、在 (2) 中是条件输入，内容相同而角色不同；如需严格区分可记调用时刻为 $\tilde q_t$、归档后为 $q_t$，本报告以「调用时 / 归档后」时间状语区分。
5. **II 的实现数据通路**：① 取末条 user message 作 $q_t$ → ② 其余作待压 corpus → ③ 用 $q_t$ 打分/选择 → ④ 拼 [system + 约束固定] ⊕ [压缩后历史] ⊕ [$q_t$ 原样] → ⑤ 调用 → ⑥ 归档含 $q_t$ 的完整轨迹。$C$ 的两个参数对应两条不同通路。
6. **预算口径提醒**：(4) 的 $B_t$ 严格说是**历史部分**预算；跨论文比较 token 数须注明是否含当前请求（§5.3）。

**（3）全量基线与四个损失分量。** 令 $\pi_{\text{full}}(a \mid H_t, q_t)$ 为把全量轨迹原样送入时的策略（F1 口径，见 §1.3），$\pi_C(a \mid c_t, q_t)$ 为压缩后的策略，$J(\cdot)$ 为任务回报，$\mathcal{D}$ 为任务分布、$\xi$ 为其中的任务样本（$\tau$ 在下文专指时间步）：

$$
\begin{aligned}
\Delta_{\text{task}} &= \mathbb{E}_{\xi \sim \mathcal{D}}\!\left[J(\pi_{\text{full}}) - J(\pi_C)\right] \\
\Delta_{\text{cons}} &= 1 - S_t, \qquad S_t = \frac{\lvert \{\, \gamma \in \Gamma_t : \gamma \sqsubseteq c_t \,\} \rvert}{\lvert \Gamma_t \rvert} \\
\Delta_{\text{reacq}} &= \mathbb{E}\!\left[N_{\text{ret}}(\pi_C) - N_{\text{ret}}(\pi_{\text{full}})\right] \\
\Delta_{\text{reliab}} &= 1 - \operatorname{Rel}(\pi_C)
\end{aligned}
$$

其中 $\Gamma_t$ 为当前生效的治理/安全/行为约束集合，$\gamma \sqsubseteq c_t$ 表示约束 $\gamma$ 的**精确措辞**在活跃上下文中原样出现，$S_t$ 即约束存活率 [25][28]；$N_{\text{ret}}$ 为重获取工具调用数 [27]；$\operatorname{Rel}$ 为跨运行可靠性（如 Pass³）[10]。

**（4）优化问题。**

$$
\begin{aligned}
\min_{C}\quad & \mathcal{L}(C) = \Delta_{\text{task}} + \lambda_1 \Delta_{\text{cons}} + \lambda_2 \Delta_{\text{reacq}} + \lambda_3 \Delta_{\text{reliab}} \\
\text{s.t.}\quad & \operatorname{len}(c_t) \le B_t \ll W \\
& \operatorname{verbatim}(\Gamma_t) \subseteq c_t \\
& \operatorname{cost}(C) + \operatorname{cost}(\operatorname{Recover}) \le B_t^{\text{cost}} \\
& \forall \tau \in [t, t+K]:\ \operatorname{Recover}(\tau, B_\tau^{\text{rec}}) \ge \rho
\end{aligned}
$$

四个约束依次为：活跃上下文长度上界；治理约束的精确措辞必须原样进入活跃上下文（对应 Constraint Pinning [25]）；压缩器与召回开销计入同一成本预算；在后续 $K$ 步内、给定恢复预算 $B^{\text{rec}}$ 时的恢复率下限 $\rho$（§4.1「可恢复性」）。

**$B_t$ 在优化建模中的角色（为什么它不多余）。** 直觉上常把问题说成「让压缩后 token 尽可能小、同时让记忆率尽可能高」，即把长度放进目标：$\min_C \mathcal{L}(C)+\mu\,\operatorname{len}(c_t)$，其中 $\mu>0$ 为单位 token 的影子价格。对 (4) 的预算约束作拉格朗日松弛

$$\mathcal{L}(C) + \mu\bigl(\operatorname{len}(c_t)-B_t\bigr)$$

可得同一式，故两种表述**在对偶意义下等价**：给定 $B_t$ 会解出 $\mu^*=\partial\mathcal{L}^*/\partial B_t$，给定 $\mu$ 会解出某个长度。但**长度只能出现一次** —— 若把长度惩罚写进目标、又同时保留 $\operatorname{len}(c_t)\le B_t$，属于双重计入，会把解推向远小于预算的一侧，白白牺牲记忆率。正确做法是二选一；本报告取约束形式（ε-constraint 法），$\mathcal{L}(C)$ 中不含长度项。

取约束形式而非加权形式的四条理由：① 窗口是**硬边界**，超窗直接报错/截断，不允许用足够好的效果去「换」可行性，软惩罚无法保证可行；② $\mu$ 无物理刻度（效果是百分点、成本是美元、延迟是秒），而 $B_t$ 由服务侧外生给定（$W$、生成预留、并发、prompt caching 定价、延迟 SLO），可验收；③ 只有固定同一 $B_t$，不同方法的 $\Delta_{\text{task}}$ 才可比（§5.3）；④ $B_t$ 作为 $C$ 的输入表示预算条件化 —— RAM [54] 由压缩比推导保留段数、BRIEF-Pro [50] 可指定句数、PoC [43] 由性能下限反推压缩率、ContextBudget [21] 把「压多少」作为 MDP 动作。

| 表述 | 形式 | 输出 | 局限 |
| --- | --- | --- | --- |
| 有预算（ε-constraint，本报告） | $\min_C \mathcal{L}(C)$ s.t. $\operatorname{len}(c_t)\le B_t$ | $C^*(B_t)$；扫 $B_t$ 得帕累托前沿 | 需外生给定 $B_t$ |
| 无预算·加权标量化 | $\min_C \mathcal{L}(C)+\mu\operatorname{len}(c_t)$ | 取决于 $\mu$ 的单点 | $\mu$ 无物理含义、不保证不超窗 |
| 无预算·纯双目标 | $\min_C \bigl(\mathcal{L}(C),\,\operatorname{len}(c_t)\bigr)$ | 一个解集，需二次决策 | 不可直接部署，且含两个平凡解 |

**与压缩率、记忆率的权衡。** 记 $\rho_t=\operatorname{len}(c_t)/\operatorname{len}(H_t)$。记忆率 $M(c_t)$ 关于 $\operatorname{len}(c_t)$ 非递减但边际递减，且**未必单调到全量**：长全量历史的注意力稀释与上下文干扰会让效果在超过某长度后回落（§4.3 机制 1；ReCAP [8]、SelfCompact [26] 压缩后反而优于全量）。因此「越短越好」与「越长越好」都不成立，$B_t$ 的作用正是选定可操作的工作点；约束形式让目标专心在可行域内最大化 $M$，而不是在长度上继续内卷。需注意「记忆率」在本报告中对应 $\Delta_{\text{cons}}$ 与 $\operatorname{Recover}$，**不等于完成率** —— 完成率不变而记忆已大量丢失正是 2026 年的核心发现 [25][27][28]（§5.1）。

**平凡解与非平凡前提。** 只优化长度则 $c_t=\varnothing$（或仅剩约束固定层）；只优化效果则 $c_t=H_t$（等于不压缩）。问题有意义要求 $B_t<\operatorname{len}(H_t)$ 且 $B_t\ll W$；当 $B_t\ge\operatorname{len}(H_t)$ 时约束不激活，最优解退化为全量基线。又因 $\operatorname{len}(H_t)$ 随轮次增长而 $B_t$ 由服务侧逐轮给定，同一 $B_t$ 在后期自动对应更激进的 $\rho_t\le B_t/\operatorname{len}(H_t)$ —— 这是 $B_t$ 带下标 $t$ 而非全局常数的原因。

**（5）「接近全量」的可判定定义。** 给定任务分布 $\mathcal{D}$、预算 $B$ 与阈值 $(\varepsilon, \delta)$，称 $C$ 为 $(\varepsilon,\delta)$-接近全量，当且仅当

$$\Pr_{\xi \sim \mathcal{D}}\!\left[\, J(\pi_{\text{full}}) - J(\pi_C) \le \varepsilon \,\right] \ge 1 - \delta$$

且四个分量分别满足 $\Delta_{\text{task}} \le \varepsilon_1$、$\Delta_{\text{cons}} \le \varepsilon_2$、$\Delta_{\text{reacq}} \le \varepsilon_3$、$\Delta_{\text{reliab}} \le \varepsilon_4$。

这一定式有两层含义。其一，它是**分布级、有前提的帕累托命题**，不是信息论等价：压缩后 $I(H_t; c_t) \le H(H_t)$，单靠活跃上下文无法还原全量；只有在 F3 口径下把原文外置并按需召回，系统可访问信息量 $I\!\left(H_t;\, c_t \cup \operatorname{Recover}(A_t)\right)$ 才可能接近 $I(H_t; H_t)$，代价是恢复预算 $B^{\text{rec}}$。其二，$\Delta_{\text{task}}$ 必须相对**同一个未压缩 F1 全量基线**测量。把「效果」拆成四个可分别证伪的量，是近两年该方向在方法论上最重要的推进，也是本报告组织材料的主线 —— 完成率无显著变化并不蕴含 $\mathcal{L}(C)$ 小（§5.1）。

### 1.2 边界与术语统一

前期材料里「压缩 / 压实 / compaction / compression」混用，「全量」「内存」等词也存在口径漂移。本综述统一如下，后文不再切换。

| 统一用语        | 英文 / 原词                       | 含义                                                    |
| ----------- | ----------------------------- | ----------------------------------------------------- |
| **上下文压缩**   | context compression           | 总称，涵盖下面两类                                             |
| **调用侧压实**   | context compaction            | API 调用前对累积轨迹的处理；黑盒可用，本报告主体                            |
| **模型侧压缩**   | model-side / soft compression | 把上下文编码为向量、gist token、soft prompt 或压 KV；需训练或白盒访问，黑盒不可用 |
| **精读 / 略读** | close reading / skimming      | 按 query 相关性分流：高相关段原样保留，低相关段压成摘要向量                     |
| **约束存活率**   | constraint survival           | 压缩后仍以精确措辞存在的治理/安全/行为约束比例                              |
| **重获取成本**   | reacquisition cost            | 因信息被丢弃而额外产生的检索/工具调用                                   |
| **跨运行可靠性**  | cross-run reliability         | 多次独立运行下结果的一致性（如 Pass³）                                |
| **恢复率@预算**  | Recovery Rate@budget          | 在给定恢复预算下能重新取回所需原文的比例                                  |

三条必须分开的边界：

1. **调用侧 vs 模型侧**：前者改写送进 API 的 token 序列；后者需读注意力、改权重或消费软表示。模型侧方法不进入本报告的效果排名，但作为**基线来源与术语源头**列全。
2. **压缩 vs 长上下文架构**：RoPE 缩放、稀疏注意力、位置外推只扩大 W，不解决历史累积与跨请求重发。PACE [33] 进一步证明：即使 KV 保留率达 0.996，定义与使用之间的旋转位置距离从 2K 增至 90K，准确率仍从 93% 跌到 64%。
3. **压缩 vs 上下文适配**：ACE [3] 是增量式 playbook，全文无全量基线且明确「不压缩」，不应放入压缩率比较。

一个典型误置是把 ACBench [98] 当作压缩口径提示：该文评测的是 GPTQ/AWQ 量化与 Wanda/SparseGPT 剪枝对智能体能力的影响（4-bit 在 workflow/tool use 掉 1%–3%、真实应用掉 10%–15%），属于**模型权重压缩**，与上下文压缩无关。

**两类压缩任务（运行模式）。** 这两类不是互斥的算法分类，而是同一系统中的两种**运行模式**；区别不在压缩算法本身，而在「压缩发生时是否已有当前请求 $q_t$ 可用」。

| 维度 | 第一类：任务无关压缩（query-agnostic / 命令式） | 第二类：任务相关压缩（query-aware / 请求驱动） |
| --- | --- | --- |
| 触发条件 | 显式 `/compact` 命令、框架层定时、轮次间自摘要；**与用户输入无关** | 用户输入 $q_t$ 到达后，scaffold 检查 $\operatorname{len}(H_t)+\operatorname{len}(q_t)>B_t$ 或超阈值触发；变体还有每请求选择（ReCAP [8]）、rubric 自决（SelfCompact [26]）、每轮压缩（CCM [7]） |
| $q_t$ 是否可用 | **否** | **是** |
| 压缩器输入 | $C_{\varnothing}(H_t,B_t)$（I-a）或 $C_{\varnothing}(H_t,B_t,A_t,R_t)$（I-b），均**无 $q_t$** | $C(H_t, q_t, B_t, A_t, R_t)$ |
| 压缩对象 | 截至此刻的**全部历史** $H_t$；I-a 产出替换式摘要，I-b 产出活跃视图并保留 $A_t,R_t$ | $H_t$ 中与 $q_t$ 相关的部分保留、不相关部分压掉；**$q_t$ 本身不压**（见下） |
| 处理流程 | 触发 → 把 $H_t$ 整体送入摘要器 → 输出 $s_t$ → 用 $s_t$ 替换 $H_t$ → 后续任意请求复用 | $q_t$ 到达 → 预算检查 → 用 $q_t$ 给 $H_t$ 分块打分/选择 → 拼装 $\operatorname{prompt}_t=c_t\oplus q_t$ → 调用 → 归档本轮轨迹 |
| 复用方式 | **一次压缩、多次复用**，成本摊到多轮 | 每请求重算，选择结果随 $q_t$ 变化 |
| 代表工作 | `/compact` [28][29]、Codex 默认自摘要 [8]、周期自摘要 [23][32]、LLMLingua-2 [64]、RECOMP [66]、ICAE [65]、500xCompressor [75] | LongLLMLingua [63]、QGC [69]、CPC [70]、EXIT [59]、Provence [60]、BRIEF-Pro [50]、RAM [54]、ReCAP [8]、SWE-Pruner [19] |
| 主要优势 | 零额外决策、可离线/异步执行、一次成本摊到多轮 | 对请求方向变化鲁棒、保留与当前任务相关的精确证据、便于可寻址恢复 |
| 主要风险 | 丢掉「当前用不上、以后会用」的信息；约束丢失最严重（一轮丢 47% 安全规则 [28]、违规率 0%→30% [25]）；压缩后不可恢复 | query 改写偏差；压缩器自身延迟（EXIT 约 302s [54]）；若误压 $q_t$ 会直接改写任务语义 |

**$q_t$ 是否参与压缩：必须分三层**（$C_{\text{lossy}}$、$\operatorname{dom}(\cdot)$ 与 lossy 的定义见 §1.1 式 2b′、2b″）。

| 层次 | 第一类 | 第二类 |
| --- | --- | --- |
| ① $q_t$ 作为**条件/输入**进入压缩器 | 否（触发时尚不存在） | **是 —— 这是两类任务的本质区别** |
| ② $q_t$ 作为**被压对象**被删减/改写 | 不适用 | **主流设计否**：当前请求必须原样进入 $\operatorname{prompt}_t$，否则任务语义被改写 |
| ③ $q_t$ 计入**预算 / 最终 prompt** | 后续轮次才出现 | 当前轮原样出现，$\operatorname{len}(c_t)+\operatorname{len}(q_t)\le B_t^{\text{prompt}}$ |

因此「第二类将 $q_t$ 纳入整体压缩范围」更准确的表述是「**$q_t$ 参与压缩决策，但不参与有损压缩**」：它进入 $C$ 的输入、决定哪些历史块被保留，本身却必须原样直传。少数 token 级实现把整个 prompt（连 question）一起送进剪枝器，属于需显式防护的例外 —— LongLLMLingua [63] 正是为此把 question 与 context 分开、只压 context；若不分离，query 里的约束、否定与精确 ID 会被一并删掉。两类可以共存：生产系统常用第一类做会话整理/离线归档、第二类做每请求的上下文选择；ACON [1] 的「离线优化指南 + 在线按指南压缩」与 ReSum [2] 的周期摘要工具即混合形态。

### 1.3 三种「全量」不可混用

文献中 full context 至少指三件不同的事，跨论文比较必须标注：

- **F1 全量轨迹入 prompt**：H_t 原样送入，是压缩方法的正确对照组（ACON [1]、CCM [7]、PAIR [10]、SelfCompact [26]、观察屏蔽 [12] 使用）。
- **F2 全量模型能力 / 全书籍上下文**：把整个输入一次性给长窗口模型（MEMENTO 的 56.7% [30]、ReCAP 的 LiC full history [8]）。F1 与 F2 在长程智能体中常不相等：F1 会因累积噪声**劣于**压缩。
- **F3 全量轨迹落盘可恢复**：原文仍在磁盘，压缩只影响活跃 prompt（filesystem offloading [29]、ReCAP [8]、CWL [24]）。**F3 下的「无损」是工程事实，不是压缩算法的功劳**，这是理解「基准对压实过于友好」的关键。

### 1.4 资料来源、检索方法与证据口径

资料来自两轮工作。第一轮以 arXiv 摘要页与 HTML 全文表格为核心，按主题检索并逐条核验 66 条文献与基准条目，以无效 ID 作 404 对照；第二轮针对 `Read As Human`（RAM [54]）的漏检做归因，并补做**引文网络检索**：读 RAM 全文 51 条 bibitem（backward）、追引用它的工作（forward）、追作者组、回溯 ACON/PAIR/ReCAP/SUMONE 四篇参考文献、扫描 ACL/EMNLP/NAACL 会议条目，另逐一核验 31 个候选 arXiv ID（全部真实且主题匹配）。

第一轮漏检 RAM 的原因具有方法论意义，归结为两点：一是**术语分叉**——检索词全绑定 `compaction / agent memory / long-horizon agent`，未覆盖 `query-aware compression / soft prompt compression / hybrid hard-soft`；二是**完全没有做引文回溯**，66 条来源全部由主题检索得到。此外还存在会议渠道盲区（RAM 是 ACL 2026 主会论文）、标题无主题词、基准不交叉、二手线索未追完等问题。本报告因此把「两套术语分别检索 + 四大会议标题扫描 + 至少两篇种子论文的 backward/forward 回溯 + 二手线索三态闭环」作为固定流程建议（§7.5）。

**证据等级**：A = 摘要页与全文表格均已回查、数字可定位到表号；B = 仅摘要页核验；C = 二手线索已回查存在但未提取全文表格；D = 基于 A/B 的推断（正文显式标注）。所有数字为论文自报口径，**未做独立复现实验**，且不同模型、预算、基准下的结果不拼成统一排行榜。

### 1.5 报告目的与结构

目的是把分散在两份材料中的逐篇卡片、勘误、比较矩阵、综述清单与研究路径，重组为一条可连贯阅读的主线，回答「这个方向走到了哪里、分歧在哪、下一步该做什么」。第 2 节先给观点骨架，第 3 节给进展与数据，第 4 节梳理关系与差异，第 5 节列问题与争议，第 6 节判断趋势，第 7 节给研究路径与建议。

## 2 核心主题与主要观点

**观点一：这个方向没有统一 leaderboard，「SOTA」必须按子赛道理解。** 调用侧压实、模型侧压缩、记忆组织召回、结构化工作记忆、连续状态管理、失败与约束治理六条子赛道，压缩对象、训练需求、黑盒可用性、评测基准都不同。把它们放进同一张压缩率表会产生虚假排名。

**观点二：决策粒度持续上升。** token（LLMLingua-2 [64]）→ 句子/观察块（观察屏蔽 [12]、SWE-Pruner [19]）→ 轮次与轨迹（ReSum [2]、ACON [1]、Slipstream [23]）→ 结构化状态（MEM1 [5]、CWL [24]）→ 失败事件与压缩边界（PAIR [10]）→ 信息类型与承诺原子（Governance Decay [25]、Compaction Cliff [28]、Commitments [22]）。本质变化是：从「文本里哪些字重要」变成「哪些信息对后续执行与合规不可替代」。

**观点三：优化信号从文本统计走向因果与规范。** 困惑度/信息熵 \[61\]\[62] → query 相关性 \[69\]\[70] → 执行反馈与蒸馏 \[1\]\[3] → 终局奖励传播 \[2]\[5][21] → 同状态反事实分叉 \[10] → 类型化保真可验证性 \[22][25]\[28]。

**观点四：可恢复性成为 2026 年的分水岭。** 不可逆删减（token 抽取、周期摘要）→ 原文外置 + 按需召回（A-MEM [4]、offloading [29]、CWL [24]）→ 持久依赖图可重新选择（ReCAP [8]）→ 软残差补充未知需求（REMORY [9]）→ 程序化递归访问（RLM [18]、PACE [33]）。**压缩正在从「删除」变成「给信息换一种可寻址的存在形式」。**

**观点五（最重要的转折）：完成率是系统性失真的指标。** 2026 年的三组独立实证表明，压缩造成的损失主要发生在合规与交互成本维度，而终局完成率不变：违规率 0%→30% [25]、重获取调用 21.0→63.9（p=.002）而完成率 80%→85%（p=1.0）[27]、安全规则存活率 53%→10% [28]。因此「完成率无显著变化」不构成无损证据。

**观点六：1M 窗口改变了问题性质，而非消除了问题。** 两个 1M 上下文模型在 160K–380K 各压缩阈值下准确率无显著差异 [29]，但 ProgramBench 首次压缩即平均丢掉约 1/3 的反作弊规则并随次数单调累积。研究目标应从「避免溢出」转为「在长窗口下保证约束可用与状态可寻址」。

**观点七：两条子赛道汇合于「按信息类型分派保真度」。** 模型侧的精读/略读分流（RAM [54]、HyCo2 [53]）与调用侧的约束固定（Governance Decay [25]）、类型化保真（Compaction Cliff [28]）、观察屏蔽 [12] 是同一思想的两种实现：不同信息对措辞精度的敏感度差一个数量级，统一压缩率必然把规则和日志同率摘要。差别在于前者按**相关性**分流，后者按**约束关键性**分流。

**观点八：算法增量空间正在收窄，空白在度量与失效边界。** 零模型调用的观察屏蔽已能减半成本 [12]；约 47 个 token 的约束固定已把显式约束违规率打回 0% [25]；在固定 scaffold、5 种策略、4 个前沿模型、3 个长程基准上，**没有任何压缩方法超过默认自摘要** [29]。继续追求更高压缩率的边际贡献有限。

## 3 关键进展与数据

### 3.1 前史：三条起点（窗口之前，仅作基线）

2023–2024 年形成三条彼此独立的技术路线，其术语与基线一直沿用到 2026 年。

**硬压缩**从信息熵删词开始：Selective Context [61] 与 LLMLingua [62] 按自我信息/困惑度删 token；LongLLMLingua [63] 首次引入当前问题做 query-aware 粗到细压缩（NaturalQuestions 最高 +21.4%、约 4× 更少 token）；LLMLingua-2 [64] 用 GPT-4 蒸馏数据训练 token 分类器，做到任务无关、2×–5× 压缩、3×–6× 加速。RECOMP [66] 与 CompAct [71] 把检索文档主动压成摘要（后者多跳 QA 压缩率高达 47×）。共同局限是：删掉的精确 ID、错误栈与约束例外无法在查询方向改变后低成本恢复。

**软压缩**把上下文变成连续表示：AutoCompressor [67] 递归 summary vectors、Gist Tokens [68] 改注意力掩码（最高 26×、FLOPs −40%）、ICAE [65] 记忆槽 + LoRA、xRAG [73] 单 token 极端压缩、COCOM [74] 与 500xCompressor [75] 分别面向 RAG 与极高倍率。它们信息密度高，但需训练、绑定模型版本、不可读，黑盒 API 不可用。

**query-aware 分流**在 2024–2025 成型：QGC [69]、CPC [70]（对比学习训练句子相关性）、EXIT [59]、Provence [60]、Sentinel [51]（注意力探测）、BRIEF-Pro [50]（32× 压缩较长上下文 9× 平均 QA +4.67%）。这条线在 2025 年出现硬软混合的 HyCo2 [53]（七个 QA 基准平均 +13.1%、减 88.8% token 仍匹配未压缩），并在 2026 年结出 RAM [54]。

### 3.2 2025 年：从删 token 到治理状态（调用侧）

上半年，A-MEM [4] 把记忆组织成可链接、可演化的 Zettelkasten 笔记（每次操作约 1,200–2,500 tokens，对比基线 16,900 tokens，商业 API 下 < $0.0003/次），MEM1 [5] 则以端到端强化学习维持近似常数状态。**MEM1 的 3.5× 性能 / 3.7×「内存」常被误引**：该数字仅限 MEM1-7B 对 Qwen2.5-14B-Instruct、在 16-objective multi-hop QA 单一任务上；且论文所谓 memory usage 定义为 peak token usage（轨迹中任一序列的最大 token 数，作为推理期内存需求代理），**不是物理显存**。

下半年进入压缩工程化。ReSum [2] 把周期摘要做成可插拔工具，并用 ReSum-GRPO 的 advantage broadcasting 解决长程信用分配（免训练相对 ReAct 平均绝对提升 4.5 个百分点，训练后相对 ReSum 再提升 8.2 个百分点——两者都是百分点，且基线不同）。ACON [1] 收集「全量成功、压缩后失败」的配对轨迹，在自然语言空间迭代优化压缩指南，不需微调生成模型，峰值 token 降 26%–54%。ACE [3] 指出反复全量覆写会造成 context collapse，改用增量 delta 维护 playbook（智能体任务平均 +10.6%、金融 +8.6%）。同期可训练路线还有 MemAgent [13]（8K 训练外推 3.5M QA，损失 <5%）、Context-Folding [14]（active context 10× 更小）、AgentFold [15]、Memory as Action [16]（平均上下文长度 −51%）。

一条容易被忽略的低成本基线来自 The Complexity Trap [12]：在 SWE-bench Verified 上，把旧工具输出替换为结构化占位符的**观察屏蔽**，在 Qwen3-Coder 480B 上 Solve Rate 53.4→54.8（+1.4pp）而实例成本 $1.29→$0.61（−52.7%），与 LLM 摘要（53.8 / $0.64）相当；但在 Gemini 2.5 Flash (thinking) 上退化为 40.4→36.4（−4.0pp），LLM 摘要更差（31.4，−9.0pp）。**任何新方法都应先与它比较。**

### 3.3 2026 上半年：验证、约束保真与自决

SWE-Pruner [19] 用 0.6B 神经略读器按显式 Goal Hint 做行级剪枝（Agent 任务 23%–54% token 下降且成功率提升、LongCodeQA 单轮最高 14.84×），因训练的是小剪枝器而非生成模型，仍可接黑盒 API。Slipstream [23] 提出**异步压缩**：压缩器与智能体继续在原上下文上执行并行，后续轨迹成为独立于摘要的验证信号，judge 校验并修补候选摘要（相对同步压缩最高 +8.8pp，端到端延迟 −11.3%–39.7%）。CWL [24] 用类型化、带依赖边的 episode 与确定性 LLM-free 驱逐策略，在单会话 89 个任务、累计 80M tokens 上相对「每任务独立会话」无可测准确率下降。

SelfCompact [26] 是本期最值得注意的免训练方法：用轻量 rubric 让模型在推理时自决「何时压缩」（子任务已解决或轨迹收敛才触发，推导中途或卡住则抑制），明确无需任何微调。**它有 No Compaction 全量对照组**：Qwen3.5-9B 在 HMMT Feb 26 上 34.2→52.3（+18.1 分），三个模型的 Overall Acc 分别 +9.8 / +9.3 / +10.3pp，同时成本降 30%–70%。

约束保真成为独立议题。Governance Decay [25] 在 1,323 个 episode、7 个模型族上用确定性 tool-call grading 测得：约束在全上下文中时违规率 0%，压缩后 30%（部分模型 59%）；约束存活于摘要则仍为 0%、被丢弃则 38%；约 47 个 pinned tokens（< 10k-token 历史的 0.5%）的 **Constraint Pinning** 可把违规率恢复到 0%。Compaction Cliff [28] 用 20 个生产 Agent 配置测得 Claude Code `/compact` + Sonnet 4.6 一轮压缩后仅保留 53% 安全规则、五轮后 10%，并提出按类型分派保真度的 Knowledge Triage（TypeCompact 在五个语料上比最强单次 LLM compactor 多保留 2–4× 规则、五轮 96% recall；TypeDecompose locality violations 0% vs 93%；TypeRetrieve recall@50 100% vs 73%）。

### 3.4 2026 下半年：1M 窗口实证、代价揭示、可恢复与因果诊断

**Benchmarks Are Surprisingly Compaction-Friendly [29]** 首次直接检验本报告的窗口场景。固定 OpenCode scaffold、5 种策略（自摘要、tool-output pruning、filesystem offloading、reasoning block discarding、小模型摘要）、160K–380K 阈值、PaperBench/ProgramBench/PostTrainBench 三个长程基准：Claude Opus 4.6（1M）与 GPT-5.4（1,050K）在各阈值下准确率无显著差异；GPT-5.3-Codex（400K）的 PaperBench 从 160K 阈值 0.38 升至 260K 及以上约 0.60；**没有任何压缩方法优于默认自摘要**，小模型摘要使 GPT-5.3-Codex 0.38→0.18（−20 分）。但 ProgramBench 首次压缩即平均丢掉约 1/3 的反作弊规则（GPT-5.3-Codex 平均丢 2.73/3 类）并随压缩次数单调上升；真实 SWE-chat 会话中「如何工作 / 不该做什么」类指令被丢弃频率约为「要构建什么」的 6 倍。作者的诊断是：现有基准**对压实过于友好**——目标固定、进度落盘，压缩丢弃的内容大多可恢复，唯独只存在于上下文中的约束不能。

**What Does Context Compression Cost an Agent? [27]** 用 24 轮确定性工具环境把重获取成本独立测量：6/6 模型-域比较中 retrieval calls 全部上升（5/6 经 Holm 校正后仍显著）；5× 压缩点上所有单元完成率变化均不显著；GPT-5.5 完成率 80%→85%（p=1.0）而 retrieval 21.0→63.9（p=.002）。需要注意该信号**依赖环境**：ALFWorld 中滑动压缩不出现 retrieval 激增。

**CCM [7]** 把压缩从阈值触发改为每轮默认状态更新，并量化了代价：TerminalBench-2 上 Claude Opus 4.6 成功率 58.4→40.4（−18.0pp）、Sonnet 4.6 42.7→31.5（−11.2pp）、GLM-5 34.8→29.2（−5.6pp），仅 Kimi K3 62.9→64.0（+1.1pp）；峰值 prompt 中位数 16,673→3,568，但部分模型估计成本反而上升（Opus $0.831→$1.087）。

**PAIR [10]** 用匹配反事实继续（同一智能体状态分叉出有/无压缩两条继续）定位孤立的有害压缩事件，发现「可靠性先于可解性恶化」，并修订固定压缩模板。AppWorld history-only 上 Acc 84.1±0.9→81.1±2.8（−3.0pp）、Pass³ 78.6→70.5（−8.1pp），换 Peak token 12.53K→3.89K（−69%）；8-objective QA 上 EM 40.9→39.3（−1.6pp）、Peak 14.53K→7.32K；模板受控设置下反而略超全量（84.7 vs 84.1）。

**ReCAP [8]** 把推理时已算出的注意力持久化为上下文图（节点带累积重要性、边记依赖），新请求沿依赖边选块，选择阶段零额外模型调用，且独立于 KV cache、cache 过期后仍可恢复。Table 1 有全量对照：SWE-Together 24.4±1.87→28.5±0.40（+4.1pp）、Ctx. 28,504→15,344；LiC 代码任务 65.6→85.4（+19.8pp）与 26.4→67.6（+41.2pp）、Ctx. 1,121→94。REMORY [9] 给文本摘要补一段有界软记忆 token 作为序列维残差，SummHay Joint score 43.41（raw）→43.39（−0.02），但 Coverage −4.51、Citation F1 +4.43，输入位置仅为全量的 5.2%。MEMENTO [30] 用 hindsight 注释 SFT 启动 + RL 学写 compaction note，在最长 2.5M token 的书籍 QA 上以 ≤20K 上下文把 Qwen3-8B 从 36.9% 提到 67.8%，超过全书籍上下文 56.7%（成本 <1/50）。


11 月出现四篇增量工作：SUMONE [31] 用 masked reconstruction 自监督训练即插即用摘要器，相对全量上下文估计成本降 78%（DeepSearchQA）/75%（SWE-bench Verified），绝对指标仅降 0.04；SpecCompact [32] 用 slot 并行推测验证把压缩加速 2.04–5.63×；PACE [33] 从 KV 侧证明「留住 token 不等于可用」；**CoMem [34]**（2026-11-12）以 query 引导选择性记忆 + 同上下文 hard negative 对比 + 双向 slot attention，在 QA 与 RULER-NIAH 上跨压缩比一致超过既有方法，是本次资料中时间最新的一篇。

### 3.5 模型侧支线：精读 / 略读与软硬混合

RAM [54]（arXiv:2602.01840，ACL 2026 Long Papers pp.28393–28406）把上下文切段、与 query 并行编码，高相关段原样保留（精读）、低相关段压成 summary vectors（略读），拼接显式文本与隐式向量送 decoder，用正负 query–segment 对的对比学习细化分流边界。训练从五个数据集各采样 20,000 条、最大 20K token、压缩率采样 {2,4,8,16,32}；评测 NaturalQA / 2WikiMQA / HotpotQA / NarrativeQA / MultiNews，backbone 为 LLaMA-3.1-8B-Instruct 与 Qwen3-4B-Instruct。

Table 1（LLaMA，4×）AVG F1：RAM **46.98** / Activation Beacon [58] 43.48 / Provence 42.55 / EXIT 42.53 / Original Prompt 37.55 / LongLLMLingua 38.11 / LLMLingua-2-large 35.39 / ICAE 30.43 / Closed-book 18.40。Table 2 端到端延迟（NarrativeQA，平均 16K、最大 32K）：RAM 0.20–0.43s、Original 1.23s、LongLLMLingua 5.14–25.17s、EXIT 约 302s。摘要自报「最高 12× 加速」，`【待补充】` Table 2 未注明比较对象，按表内数字可推出 6×（对 Original）到 26×（对 LongLLMLingua）等不同量级。

其直系脉络为 Perception Compressor [56]（同组免训练 query-aware）→ GMSA [55]（全软压缩）→ HyCo2 [53]（硬软混合）→ RAM（按相关性分流）→ COMI [57] 与 SeCo [41]（自适应压缩率、语义驱动）。此外 PIR [39]（EMNLP 2026，无 arXiv ID）用扩散语言模型在长上下文中插入 extraction slots 做并行分段阅读，与 RAM 概念同源而路线不同。

**必须强调**：RAM 压的是单段 16K–32K 输入，不是多轮智能体轨迹；需端到端训练并消费模型内部向量，黑盒 API 不可用。它的价值是提供「按相关性分派保真度」的完整模型侧实现、一组整齐的基线数字，以及一个反直觉的效率警示——**某些压缩器比不压缩更慢**（EXIT 302s vs Original 1.23s），这与 ACON Table 4（成本 $0.331→$0.285 但延迟 73.24s→87.68s 上升）、Slipstream（同步压缩占端到端延迟 26%–44%）的动机一致。

## 4 不同内容之间的关系与差异

### 4.1 三条主轴的演进

|主轴|2023–2024|2025|2026|
|---|---|---|---|
|决策粒度|token \[61]\[62][64]|轨迹、状态、记忆笔记 \[1]\[4][5]|失败事件、约束类型、承诺原子 \[10]\[22]\[25][28]|
|优化信号|信息熵、困惑度 \[61][62]|query 相关性、执行反馈、终局奖励 \[1]\[2][69]|反事实分叉、类型化保真可验证性 \[10]\[23]\[25][28]|
|可恢复性|不可逆删减|原文外置 + 按需召回 [4]|持久依赖图、软残差、程序化访问、位置重编号 \[8]\[9]\[18][33]|

三条轴并非互相替代：粒度回答「压什么」，信号回答「按什么标准压」，可恢复性回答「压错了能否补救」。2026 年的多数新方法只在其中一到两条轴上推进，例如 PAIR [10] 是信号轴的范式变化而几乎不改变压缩算法，REMORY [9] 是表示层变化而不改评测，二者互补。

### 4.2 调用侧压实与模型侧压缩：分野与汇合

|维度|调用侧压实|模型侧压缩|
|---|---|---|
|压缩对象|累积的多轮轨迹、工具返回、中间记忆|单段长输入、检索文档、KV 激活|
|产物|可读文本 / 结构化状态 / 索引|向量、gist token、soft prompt、紧凑 KV|
|训练需求|多数免训练|几乎都需训练或白盒访问|
|黑盒 API|可用|不可用|
|典型方法|ACON [1]、ReSum [2]、ReCAP [8]、PAIR [10]、SelfCompact [26]|ICAE [65]、Activation Beacon [58]、HyCo2 [53]、RAM [54]、REMORY [9]|
|评测基准|AppWorld [81]、SWE-bench、BrowseComp [83]、Terminal-Bench [86]|NaturalQA / HotpotQA / NarrativeQA / MultiNews、LongBench [78]、RULER-NIAH|
|主要风险|约束丢失、状态漂移、重获取成本|不可读、跨模型不可迁移、精确值不可还原|

**分野**决定了二者不能进同一张排行榜；**汇合**在于 2026 年共同走向「按信息类型分派保真度」：模型侧用相关性分流（精读留原文、略读压向量）\[53][54]，调用侧用约束关键性分流（规则固定、日志可压）\[25][28]。两者之间的桥是：把「相关性」换成「不可替代性」，并补上 RAM 未处理的撤销与作用域收缩 —— 这正是 §7.3 RP1 的立足点。

值得注意的是，Agent 侧与 KV 侧也存在中间地带：Practical Online KV Cache Compaction for LLM Agents [35] 研究智能体在「未来相关性未知」时必须在线压缩的问题，结论是立即压缩常损害表现、延迟到能用智能体未来 query 作 proxy 时可挽回大部分差距、token eviction 常比 attention matching 更鲁棒，KV −80% 仍能保住精度；EpiCache [36] 在 LongMemEval / Realtalk / LoCoMo \[84][85] 上以 4–6× 压缩接近全 cache 精度。这两篇说明「调用侧 / 模型侧」不是二分，而是需要按**信息是否可寻址恢复**重新切分。

### 4.3 「压缩后超过全量」的六种机制（澄清一个反复出现的争议）

ReCAP +19.8/+41.2pp [8]、SelfCompact +18.1 分 [26]、MEMENTO +11.1pp [30]、ACON WebVoyager +12.9pp [1] 等结果容易被误读为数字错误或作弊。可归纳为六种不同机制：

1. **全量历史本身的注意力稀释与上下文干扰**：长全量输入导致信息分散、位置偏置 \[79][80]，压缩清除噪声后反而更准。Shi 等 2023「LLMs Can Be Easily Distracted by Irrelevant Context」[99] 是这一现象的早期源头，SeCo [41] 把它形式化为位置偏差问题。
2. **进度可从磁盘重建**：目标固定、进展落盘，压缩丢掉的多半能恢复 [29]（即 F3 口径）。
3. **「全量」指 F2 全书籍上下文而非 F1 全量轨迹** [30]。
4. **压缩产物是更好的结构化状态**：ReCAP 依赖图 [8]、SelfCompact 及时清理已解决子任务 [26]。
5. **训练目标直接优化超过未调优全上下文 RAG**：DEX-Comp [40] 16× 压缩超过所有压缩基线及未调优全上下文 RAG。
6. **统计假象**：单次运行、小样本、未校正的完成率差异 [27]。

前五种是真实机制，但只有 (1)(4) 属于算法贡献；(2)(3) 是口径问题，(5) 是训练目标设定，(6) 需排除。因此「压缩无损」既不能由完成率证明，也不能由「超过全量」证明。

### 4.4 适用边界与选型

|条件|首选|应避免|
|---|---|---|
|工具输出冗长、环境可重读、成本敏感|观察屏蔽 [12]（零模型调用）|训练型摘要器|
|有显式安全/合规/行为约束|Constraint Pinning [25] + TypeCompact/TypeRetrieve [28] 作前置层，再叠加任意压缩|直接把约束交给自摘要（一轮丢 47% [28]）|
|多轮中查询方向频繁改变、依赖显式|ReCAP [8]、CWL [24]、filesystem offloading [29]|一次性摘要|
|任务族稳定、可离线采集失败轨迹|ACON [1] 或 PAIR [10] 模板适配|每轮重训的 RL 方案|
|无法离线采集、要即插即用|SelfCompact [26]、SUMONE [31]、RLM [18]|需微调生成模型的方案|
|压缩本身成为延迟瓶颈|Slipstream [23]（移出关键路径）或 SpecCompact [32]（并行化）|同步大模型摘要|
|可训练、奖励可验证、追求定长状态|MEM1 [5]、MEMENTO [30]、ContextBudget [21]|黑盒 API 上强行套用|
|评测/选型|完成率 + 约束存活 + retrieval calls + Pass³ + 恢复率@预算 五项同报|只看完成率或压缩比|

### 4.5 综述与评测体系的位置

现有综述已覆盖：压缩方法分类与失败分类（EMNLP 2026《Context Compression for LLM Agents》[91]，三维分类 target/mechanism/control policy + F1 压缩前决策错误 / F2 压缩中信息损失 / F3 压缩后访问失败）、上下文工程全链路（[90]，§4.3.3 Context Compression，覆盖 1400+ 篇）、记忆表示与操作术语（\[93]\[94][95]）、长上下文架构与评测（[96]）、记忆中心的信息生命周期与成本模型（[92]）、提示压缩（[97]）、KV 侧压缩。

**仍未被任何综述系统覆盖**的三块恰是本报告识别的空白：压缩的约束/承诺保真、重获取成本与跨运行可靠性作为一等评测维度、1M 窗口下压缩的必要性边界与「基准对压实过于友好」的方法论批评。[91] 的 F1/F2/F3 框架是最接近的术语基座，可作为切入起点。

评测方面，AgentMemBench [11] 是唯一同模型、同解码、同流程的统一对照：Qwen2.5-7B-Instruct（4-bit）、491 个标注问句、7 项指标。EKV 外部 KV 存储 macro Recall@5 0.792 / MRR 0.677 / F1 0.156，但足迹 5,126 tokens；近邻窗口 0.468 / 298 tokens。LoCoMo 长距召回上近邻窗口、摘要、实体图的 Recall@5 ≤0.005，只有 EKV 达 0.573 —— **摘要与图在长 horizon 上集体坍塌，只有稠密检索可扩展**；代价是约 17× 足迹、25.6× 成本。其局限是 generator 与 judge 同为 4-bit 7B、静态日志回放、未测写入冲突。

## 5 存在问题与争议

### 5.1 完成率指标的失真（方法论层面最实质的争议）

§3.4 的三组实证共同指向一个结论：**以完成率为唯一验收指标的压缩研究，其「无损」结论在方法上不成立**。PAIR [10] 进一步发现可靠性先于可解性恶化 —— 平均值会掩盖低概率但致命的状态丢失。目前尚无公认的替代指标组合，也无低成本、可跨环境复现的重获取成本测量协议；[27] 在 ALFWorld 中未复现 retrieval 激增，说明该信号依赖环境，不能当作压缩的固有属性。

### 5.2 口径混乱与前期材料中的数字错配

- **三种「全量」混用**（§1.3）导致「接近全量」不可判定。
- **compaction 与 compression 分叉**（§1.2）造成整条模型侧支线在首轮检索中缺失。
- **「内存」歧义**：MEM1 [5] 的 memory usage 实为 peak token usage，不是显存。
- 前期材料另有若干需更正之处：ACE 的 context collapse 案例原为 18,282 tokens 下准确率 **66.7** → 122 tokens 下 57.1，而 63.7 是「无自适应基线」的值，且该案例属于 Dynamic Cheatsheet 的动机分析而非 ACE 结果；ACE 全文无全量基线且明确不压缩；ACON 摘要为「improving task success over existing compression baselines」而非「基本保留」；ReSum 的 4.5% / 8.2% 是平均绝对百分点且基线不同（ReAct / ReSum）；ACBench [98] 是权重量化非上下文压缩。引用编号复用也已在本报告统一重建。

### 5.3 证据质量与可复核性

1. **自报数字不可横比**：ACON 用 gpt-4.1、PAIR 用 GPT-5.6 Luna、CCM 用 Claude/GLM/Kimi、AgentMemBench 用 4-bit Qwen2.5-7B；压缩器自身调用、judge 开销、图/索引存储多数未计入。本报告表 3-1/3-2 全部标注出处与口径，不给跨论文排名。
2. **RAM 的 12× 加速口径未明**：Table 2 未给倍数也未注明比较对象。`【待补充】`
3. **引用计数三方不一致**：RAM 的 cited-by 在 Google Scholar（约 2）、Semantic Scholar API（15 条关系）、mlsanity/scholarfeed（10）之间冲突，Scholar 页被验证码阻断；部分 2026 引用关系仅元数据级、未做全文引用语境核验；GMSA 等 v1 早于 RAM v1 的「引用」判为时间倒挂误匹配。本报告不采信任一 N 值。
4. **版本差异**：ACON v3、ReSum v3、ACE v3、A-MEM v11、Du 等综述 v3 的摘要与章节结构均有变化，引用需标版本。
5. **元数据异常**：AgentMemBench 的 ID 2608 与提交日 2026-06-16 不一致、CWL 的 2606.* 与 2026-05-01 不一致、MEMENTO 的 2611.* 与 2026-10-30 不一致；Compaction-Friendly 摘要称 three frontier models 而全文 Limitations 称 four。以 arXiv abs 页 [v1] 日期为准。

### 5.4 技术争议

- **1M 窗口下压缩是否还有必要？** [29] 显示阈值不敏感，某些场景确实可不压缩。反方依据是成本（全量历史 prefill 随轮数线性增长，CCM [7] 的 Total input 451,006→76,126）、约束保真与位置距离衰减 [33]。较稳妥的立场是把问题表述为「长窗口下的上下文治理」而非「窗口不够用」。
- **简单方案是否已经足够？** 观察屏蔽减半成本 [12]、Constraint Pinning 把违规打到 0% [25]、默认自摘要未被超越 [29]。这构成对「再设计一个更强压缩器」的最强反对，也是本报告主张「空白在度量与失效边界」的依据。
- **软压缩的不可读与不可迁移**：REMORY [9] 绑定冻结 LLM、RAM [54] 需端到端训练，跨模型/版本漂移缺乏系统数据。
- **立即压缩还是延迟压缩？** [35] 给出「立即压缩常损害表现」的 KV 侧证据，与 CCM [7] 每轮压缩导致 3/4 模型成功率下降相互印证，但 SelfCompact [26] 的 rubric 自决又显示压缩可提升效果 —— 分歧点在于**触发依据是否包含执行状态**。
- **压缩器延迟与收益**：某些压缩器比不压缩更慢（EXIT 302s vs Original 1.23s [54]；ACON 延迟上升 [1]），而多数论文只报 token 不报延迟。


### 5.5 评测生态争议：基准对压实过于友好

主流长程基准目标固定、进度落盘 [29]，因此压缩丢弃的内容大多可从环境恢复，任务成功率对压缩不敏感；约束、行为禁令、跨轮否定等**只存在于上下文中的信息**成为唯一真实损失，却几乎不被测量。AgentMemBench [11] 只覆盖对话记忆检索、单模型静态日志。目前缺同时报告完成率、约束存活、重获取成本、跨运行可靠性、恢复率@预算、压缩器自身开销、延迟与 API 成本的统一基准，也缺「约束仅存在于上下文、进度不可重建、需跨轮否定与反事实分支」的任务设计。

### 5.6 信息不足处（需补充）

以下项目在现有资料中**未核实、未读取或无公开证据**，正文中以 `【待补充】` 标注，完整清单见附录 C：ACON 压缩阈值 T_hist/T_obs 的具体数值；Compaction-Friendly 阈值×分数完整数值表（图为唯一来源）；Slipstream 延迟绝对秒数；RAM 12× 的比较对象；RAM 精确 cited-by 数；多数论文未量化的压缩器自身开销与图/索引存储；跨模型、跨 scaffold 的第三方复现；隐式/会话依赖型约束的评测；中文及多语种长程智能体压缩评测；恢复预算受限下的最优召回策略；PIR [39] 等无 arXiv ID 会议论文的全文核验；Compaction Cliff 部分下游表与 ACE 剪枝触发阈值配置。

## 6 发展趋势

**趋势一：从「压缩掉」转向「可寻址、可恢复」。** 完整轨迹不可变归档、活跃上下文有界、精确证据可寻址召回，正在取代单纯提高删减率。ReCAP [8] 的持久依赖图、CWL [24] 的依赖驱逐、offloading [29]、RLM [18] 的变量引用、PACE [33] 的位置重编号是五个不同层面的实现。**待解决**：恢复预算本身受限时的最优召回，以及图/索引开销的完整计入（ReCAP 未量化图开销）。

**趋势二：从「统一压缩率」转向「按信息类型分派保真度」。** 约束固定 [25]、类型化保真 [28]、精读/略读 [54]、观察屏蔽 [12] 已各自验证，下一步是把「相关性」升级为「不可替代性」，并处理会话依赖、条件生效与可撤销约束 —— 现有两类方法都要求约束可离线抽取，`【待补充】` 会话依赖型约束尚无公开评测。

**趋势三：从「完成率」转向「代价与可靠性联合目标」。** 重获取成本 [27]、跨运行可靠性 [10]、约束存活 \[25][28] 正成为一等指标；ContextBudget [21] 把压缩形式化为预算 MDP、PoC [43] 把目标从「指定压缩比」改为「指定性能下限」，但二者都需训练或只看任务回报，**免训练且联合优化压缩/检索/恢复三者的方法仍缺**。

**趋势四：压缩器与执行策略协同。** ReSum-GRPO [2] 承认压缩后的状态改变了策略，PAIR [10] 用反事实诊断修订模板，SUMONE [31] 用自监督信号摆脱对下游任务的耦合，ACON [1] 把优化后的压缩器蒸馏进小模型。共同难题是跨模型/跨版本漂移：`【待补充】` 目前只有 PAIR 迁移到 MiniMax-M3 的单点验证与 SUMONE 的跨 harness 声明。

**趋势五：压缩与解码/服务系统协同。** Slipstream [23] 把压缩移出关键路径、SpecCompact [32] 并行化压缩、Fast KV Compaction via Attention Matching [37] 在隐空间秒级完成 50× 压缩、EpiCache [36] 与 SemantiCache（语义分块聚簇合并 KV，见补充清单 C16）在 KV 层做会话级管理。这条线提示未来的「压缩」会越来越多地发生在服务层而非 prompt 层。

**趋势六：评测从单点走向帕累托前沿与因果诊断。** 合理指标应是任务效果差、关键状态恢复率、成本与跨运行可靠性的帕累托前沿，而非单一压缩比；PAIR [10] 的反事实继续与 [27] 的受控运行时测量提供了两类可复用的诊断协议。

**应降温的方向**：再发表一个「峰值 token 降低 X%」的压缩器；为 1M 模型调优压缩阈值（阈值不敏感 [29]）；把治理约束交给自摘要；以完成率作为唯一验收指标；在没有约束固定层的情况下评测压缩安全性。

## 7 研究路径与结论建议

### 7.1 研究现状：五条可证伪判断

1. 算法增益空间已收窄（\[12]\[25][29] 三条证据）。
2. 收益主要来自清除噪声与可恢复性，而非把信息编码得更密。
3. 失效面已从「任务做不成」转移到「做得成但违规 / 做得成但更贵 / 这次成下次不成」。
4. 1M 窗口改变问题性质而非消除问题 \[29][33]。
5. 评测生态是最大短板 \[11][29]。

### 7.2 关键挑战

|挑战|难在哪|现有证据|未解决点|
|---|---|---|---|
|C1 约束非对称保真|不同类型信息对措辞精度敏感度差一个数量级|规则存活 53%→10% [28]；存活则违规 0%、丢弃则 38% [25]|**会话依赖 / 隐式约束**无法离线分类，[28] 自述超出范围|
|C2 完成率盲区|损失发生在后续交互与合规维度|retrieval 3× 而完成率不变 [27]；F1/F2/F3 失败分类 [91]|标准化、低成本、跨环境可复现的测量协议|
|C3 触发与预算协同|何时压、压多少、留多少恢复预算是耦合决策|1M 模型阈值不敏感 [29]；rubric [26]、MDP [21]、异步 [23]、边界归因 [10]|黑盒上免训练、无反事实、又联合优化三者的策略|
|C4 可恢复性与冷启动|KV 过期后重评需重编码；外置原文召回受预算限制|ReCAP [8]、CWL [24]、PACE [33]|恢复预算受限时的最优召回；图开销计入后的净收益|
|C5 状态真值与写冲突|每轮状态更新都是潜在错误源|CCM 3/4 模型下降 [7]、context collapse [3]、AgentMemBench 未测写冲突 [11]|状态校验、版本化、跨会话矛盾事实合并|
|C6 漂移与评测有效性|压缩改变输入分布；主流基准天然低估风险|PAIR 跨模型单点 [10]、ACON 仅 GPT 系充分验证 [1]、基准友好 [29]|跨模型/版本无重训迁移；抗友好基准与统一报告规范|

### 7.3 四个可切入的研究问题

**RP1 会话依赖型约束的在线识别与保真（最高优先级）。** 现有 Constraint Pinning [25] 与 Knowledge Triage [28] 都要求约束可离线抽取为可引用规则。假设 H1：在作用域随会话漂移的任务上，静态 Pinning 的违规率显著高于「作用域在线判定 + 条件固定」，且固定开销 < 活跃上下文 1%。最小实验：在 ConstraintRot [25] 的确定性 grading 上扩展「作用域型 / 条件型 / 可撤销型」三类约束 × 9 任务 × ≥3 模型族，对照全量 control、自摘要、静态 Pinning。若静态 Pinning 已达 0%，H1 被推翻，应转向 C2/C7。差异边界是不做「又一次 Pinning」，而是去掉「可抽取」假设并显式处理撤销。

**RP2 以重获取成本与可靠性为联合目标的预算化决策。** 假设 H2：固定 API 预算下，以「完成率 − λ·retrieval calls − μ·(1−Pass³)」为目标的免训练触发策略，在相同成本下比固定阈值 / rubric 取得更高跨运行可靠性。实验复用 [27] 的 24 轮环境与 [26] 的基准体系，增加「立即压缩 vs 延迟压缩」变量（依据 [35]），扫 λ/μ/B，报告帕累托前沿与 Holm 校正显著性。若只在单一环境成立，须明确声明适用边界。

**RP3 抗 compaction-friendly 的评测基准与统一报告规范。** 假设 H5：构造「约束仅存在于上下文 + 进度不可重建 + 需跨轮否定/反事实分支」的任务后，现有免训练方法与全量基线的差距会从「不显著」变为 ≥10pp 或规则存活率 ≤60%。基准 + 8 项指标报告规范本身即为可发表贡献。若差距仍不显著，则说明压缩风险被高估，研究应转向成本优化 —— 这是诚实且有用的负结果。

**RP4 恢复预算受限时的可寻址召回。** 假设 H4：存在最优「活跃摘要 : 恢复预算」分配，且在恢复预算 < 峰值上下文 10% 时，依赖图式选择显著优于 top-k 语义检索，且把图开销计入后优势仍成立。在 SWE-Together [87]、LiC [80]、LoCoMo [84] 上扫恢复预算 0/2%/5%/10%/20%，报告 Recovery Rate@budget 与含索引开销的总 token 账。

### 7.4 分阶段路径（每阶段设可放弃判据）

|阶段|目标|交付物|退出判据|
|---|---|---|---|
|P0 实验台与度量|固定 scaffold、固定 1M 模型与小窗口模型、阈值集 160K/260K/380K，实现 5 个基线与 8 项指标采集|开源 harness + 基线复现报告|**Go**：能复现 [29]「1M 阈值不敏感」与 [12]「观察屏蔽减半成本」。**No-go**：先查 scaffold/定价差异|
|P1 失效画像|约束注入、恢复预算扫描、压缩强度扫描，测完成率/约束存活/retrieval/Pass³ 四维响应面|方法 × 失效维度 × 任务类型热力图 + 负结果清单|**Go**：找到简单方案 ≥10pp 或 ≥15% 保真差距的格子。**No-go**：全格子 <3pp 则转向成本/延迟优化|
|P2 约束保真层|作用域在线判定 + 条件固定 + 撤销处理|免训练可插拔模块 + 消融|**Go**：作用域/条件型违规率相对静态 Pinning 降 ≥15pp 且开销 <1%|
|P3 预算化决策|代价感知触发 + 轻量边界探针|策略 + 帕累托曲线 + 与 [26]/固定阈值/[10] 的成本对照|**Go**：相同成本下 Pass³ 或约束存活经校正后显著改善|
|P4 可恢复架构|不可变原文归档 + 结构化状态卡 + 类型化视图 + 按依赖召回，索引开销完整计入|系统 + Recovery Rate@budget 曲线 + 总 token 账|**Go**：计入索引开销后仍在 ≤10% 恢复预算下优于 top-k|
|P5 基准与泛化|发布抗友好任务集与报告规范，跨 ≥5 模型/版本做漂移检测|基准 + 规范 + 漂移表 + 最终论文|**Go**：≥3 个外部模型上结论方向一致；否则明确写成单模型结论|

**最小可发表工作（MVP）**：P0 + P1 + RP1 + RP3，定位为「约束不可重建条件下的上下文压缩：失效画像、在线保真与抗友好基准」。理由是空白明确（[25][28] 解决显式可抽取约束，[29] 指出基准友好性，交叉格无人填）、差异边界清晰（不做新压缩器、不做 RL、不做软 token）、可证伪（静态 Pinning 可能已够用）、黑盒 API 直接可用。

### 7.5 分类建议

- **黑盒 API 工程团队**：不可变原文归档 + 约束固定层（约 47 tokens [25]）+ 结构化状态卡 + 观察屏蔽/依赖图按需召回 + 关键约束直传 + 冷恢复预算；必要时才调用摘要器，并用异步验证 [23] 或并行加速 [32] 控延迟。不要为 1M 模型调优阈值，不要把约束交给自摘要，不要用完成率验收。
- **可训练 / 自托管团队**：连续状态 \[5][30]、策略适配 [2]、软残差 [9] 值得试验，但须接受模型绑定与跨版本迁移成本；KV 侧可参考 \[35]\[36][37]。
- **研究者**：优先做度量与失效边界（RP1/RP3），把两套术语检索、四大会议扫描、backward/forward 引文回溯、二手线索三态闭环固化为调研流程 —— 首轮调研漏掉整条模型侧支线的教训表明，**检索方法本身会影响结论**。

## 8 结论

近两年该方向最实质的进步，不是某个压缩算法取得统治性压缩比，而是问题被重新定义了三次：2025 年从「删哪些 token」变为「为下游失败与执行反馈而压缩」；2026 年上半年变为「压缩是否可验证、约束是否被保真」；2026 年下半年变为「在 1M 窗口下，压缩的代价究竟发生在哪个维度、且是否可恢复」。两条原本平行的子赛道在「按信息类型分派保真度」上汇合，而完成率指标的失效把研究重心从算法推向度量。

对「压缩到远小于 1M 且接近全量」这一原始目标，可操作结论是：在固定任务分布与显式约束可固定的条件下可以做到，且在若干基准上压缩反而优于全量；但这不是信息论等价，而是有前提的帕累托结果。合理指标应是任务效果差、关键状态恢复率、成本与跨运行可靠性的联合前沿，而不是单一压缩比。最值得投入的不是新压缩器，而是**约束保真的在线化、完成率之外的代价度量、抗友好评测基准、恢复预算受限下的可寻址召回**四条；若 P1 的失效画像发现简单方案已覆盖绝大多数场景，应及时转向成本与可靠性优化并如实报告负结果 —— 这比再发表一个「峰值 token 降低 X%」的压缩器更有价值。
